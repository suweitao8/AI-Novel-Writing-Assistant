# 页签记忆与恢复边界

## 背景

模型库、动画库、小说/漫剧工作区、知识库和资产编辑器都包含用户会反复返回的页签或页签式分类。若只保存在组件内存中，离开页面后会回到默认位置，用户需要重复定位正在编辑的分类、章节或资产。

## 决策

第一版只在浏览器端记忆稳定的页签选择，使用带版本的 `localStorage` 命名空间 `ai-novel.remembered-tab.v1`。页签记忆属于当前浏览器的界面偏好，不属于作品数据，因此不写入数据库、不增加 API 字段，也不跨用户同步。

页签通过显式 scope 隔离。全局库使用功能级 scope；小说、漫剧、章节、角色、世界和提示词使用稳定业务对象标识。这样既能在同一对象返回时恢复位置，也不会把一个对象的编辑页签串到另一个对象。

## 当前规则

- 恢复优先级固定为：有效 URL 页签 > 当前 scope 的已记忆页签 > 代码定义的默认页签。
- 所有读取值必须经过当前允许值集合校验；动态页签被删除、旧版本值失效或值损坏时回退默认值。
- URL 驱动的页签在恢复时保留其他 query 参数；有效 URL 仍可复现并覆盖浏览器记忆。
- URL 中存在但不在允许值集合内的页签参数必须规范化为代码定义的默认值，并使用 replace 更新地址；不能先删除参数再让旧记忆重新接管，否则无效深链接会落到不可预测的页签。
- `localStorage` 不可用、被禁用或配额异常时静默降级为内存状态，不阻断页面加载和业务操作。
- 只记忆稳定的页签、分类和重复编辑视图；不记忆滚动位置、搜索词、分页、表单草稿或一次性流程内部步骤。
- 新的页签接入统一使用 `useRememberedTab` / `useRememberedQueryTab`，或通过 `Tabs` 的显式 `rememberedKey` 与 `rememberedValues`；不能在业务模块中各自定义另一套存储键。

## 示例

- 模型库和动画库分别使用独立的全局 scope，返回页面时恢复上次分类，且不会相互串值。
- 小说工作区使用小说 id 作为 scope 的一部分，章节、角色和世界手册继续细化到各自对象 id。
- 直接打开带有效 `tab`、`stage` 或 `view` 的链接时，以链接为准并同步该 scope 的记忆。
- 不推荐把当前选中的临时按钮组写入全局 scope；没有稳定业务边界的状态应保持组件内存状态。

## 失败模式

- **表现：** 返回页面后页签回到默认值。**排查：** 先确认调用点是否提供稳定 scope 和完整允许值集合，再检查 URL 是否显式指定了另一个有效值。
- **表现：** 不同小说或资产之间串用页签。**排查：** 检查 scope 是否包含对应对象 id，且对象切换时没有复用旧对象的受控状态。
- **表现：** 内容区为空或页签不激活。**排查：** 检查动态允许值集合是否在数据加载后更新，以及持久化旧值是否通过校验；不要用硬编码字符串匹配掩盖无效状态。
- **表现：** 嵌入环境禁止浏览器存储。**处理：** 保留默认页签和当前会话内的组件状态，不把存储异常升级为页面错误。
