# 生成布局措辞泄漏进识别 Prompt 导致系统性漏检

## Background

场景状态全景图的生成链路有一条三区构图契约：`v=0.5` 为地平线、`v=0.48–0.52` 是必须保持空净的中心安全带、家具必须完整位于安全带上方。这条规则约束的是**图片生成**（防止生成模型把家具画过地平线）。

空间标记识别 Prompt（`drama.scene.state.3d_markers`）在 v6 及之前复用了这段措辞，要求识别模型"物体的主体和腿脚必须完整位于安全带上方；被分界切开或靠近分界的物体不要标注"。

## Failure Mode

真实室内等距柱状全景里，v≈0.5 是拍摄时的视线高度。门底、桌椅、床几乎全部位于 v=0.5 以下的下半区——这是透视的物理必然，不是生成错误。识别模型按 Prompt 指令执行的结果是：

- 高处的窗户（位于视线上方）被正常标出；
- 视线以下的所有门、桌子、椅子被"靠近分界/被切开"条款系统性跳过。

用户视角的表现是"只有窗识别是对的，门和桌椅全部没有"。深度反算、墙面聚类等下游数学都正常，问题纯粹出在召回入口。

## Current Rule

1. 生成分区措辞只允许出现在图片生成类 Prompt 中；识别/标注类 Prompt 禁止引用任何 `v=0.48–0.52` 安全带、"安全带上方"、"不得跨越分界"字样。
2. 识别 Prompt 的覆盖面要求写成正向扫描指令：上下半区都要逐一检查、从左到右分段扫完 360°、同类每个可见实例独立输出、部分遮挡但可辨认轮廓的物体也要标。
3. 跳过条件只保留一种：完全无法辨认是什么的碎片。宁可多标一个框也不能因为保守而漏掉整个类别。

## Diagnosis Path

当某类固定物体整体缺失而其他类别正常时，先读当前注册版本的识别 Prompt 全文，搜索任何限制"标哪些位置"的负面条款，再考虑视觉模型能力或图片质量问题。漏检通常是 Prompt 合同问题而不是模型能力问题。
