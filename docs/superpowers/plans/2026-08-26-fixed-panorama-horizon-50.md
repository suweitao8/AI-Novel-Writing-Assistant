# 固定全景地面分界为 50%：实施计划

> 设计文档：`docs/superpowers/specs/2026-08-26-fixed-panorama-horizon-50-design.md`

## 目标

移除 `panoramaHorizonV` 的产品可配置性，统一以固定 `v=0.5` 处理旧数据、服务端投射、客户端 shader、空间标记和场景全景生图提示词，并保留旧 JSON 的无损读取兼容。

## 实施步骤

### 1. 先锁定失败行为

- 更新共享环境、服务端环境、分镜布局、标记快照和客户端投影契约测试：旧 horizon 值被忽略、序列化不再写出、编辑器控件消失、shader 不再声明 horizon uniform。
- 为场景状态图和旧版场景全景 Prompt 增加精确 `v=0.5`、`v=0.48–0.52` 安全带和“家具主体/腿部不得跨线”的断言。
- 将空间标记 Prompt 版本升级为 `v3`，测试固定 50% 语义和中心安全带拒识规则。
- 运行窄范围测试，确认这些测试在实现尚未修改时按预期失败。

### 2. 收敛共享与服务端合同

- 在共享类型中定义固定全景 horizon 常量，移除环境输入类型的 horizon 字段，更新匹配和标记当前性判断。
- 在场景环境归一化器中固定 50%，保留历史 JSON 的额外字段读取兼容，序列化只输出可配置环境字段。
- 在空间标记反算中固定垂直射线的 `v=0.5`，标记源环境快照只保存投射中心高度和半球直径。
- 更新故事设置路由 schema、标记服务和分镜摆位合同，旧布局读取时忽略 horizon，新的布局不再输出它。

### 3. 收敛客户端投射与编辑器

- 从客户端环境类型、默认值、归一化和保存快照中移除 horizon 字段，同时允许旧布局读取后被规范化。
- 删除场景 3D 编辑器中的“全景地面分界”滑块及其状态更新分支。
- CPU 投影固定以 50% 为中心，GLSL 去掉 `uPanoramaHorizonV` uniform 和可调 V 偏移；材质更新不再设置该参数。

### 4. 强化场景全景生成 Prompt

- 让场景状态图和旧场景全景两个生成入口都复用同一组严格上下分区规则。
- 对中心安全带增加“无家具、无物体碎片、无腿部穿越”的正向约束，对负向 Prompt 增加家具主体跨线、分割家具、地面杂物等失败模式。
- 不在图片中绘制分割线或拼贴带，明确 `v=0.5` 是纹理坐标合同而非可见图形。

### 5. 文档与回归

- 更新空间标记与 3D blocking wiki，说明固定 50%、旧字段兼容和不再失效的原因。
- 更新 README 与 release notes 的用户可见行为，移除 40%–65% 可调描述。
- 运行服务端相关测试、客户端投影/契约测试、服务端和客户端 typecheck；按项目规则复用不受影响的既有验证。
- 检查工作树、集成到 `main`、明确推送 `origin/main`，确认本地与远程 SHA 一致并清理本次工作树。

## 关键命令

```powershell
pnpm --dir server build
pnpm --dir client typecheck
pnpm workflow:integrate codex/fixed-panorama-horizon-50 --verify "pnpm typecheck" --push
pnpm workflow:cleanup codex/fixed-panorama-horizon-50
```

## 风险与回滚边界

- 风险集中在旧 JSON 的类型兼容和客户端/服务端合同同时收敛；先用兼容读取和序列化断言锁定边界，不删除数据库字段。
- 若旧标记快照因缺少 source environment 无法确定来源，仍按既有规则标记为 stale，不通过猜测 horizon 恢复坐标。
- 不执行数据库重置、迁移或删除操作。
