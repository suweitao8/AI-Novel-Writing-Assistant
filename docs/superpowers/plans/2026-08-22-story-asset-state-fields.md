# 故事资产状态字段归一化实施计划

## 目标

统一角色、场景、道具的状态编辑逻辑，把场景/道具的可变视觉字段移入状态，并扩大编辑弹窗。

## 实施顺序

1. 先增加客户端和服务端契约测试，锁定场景状态字段、道具提示词归属、新建状态编辑器和弹窗尺寸。
2. 扩展共享状态类型与归一化默认值，保持旧顶层字段作为兼容回退。
3. 修改状态编辑器、场景/道具/角色弹窗和详情展示；场景/道具创建时也提交状态数组。
4. 修改状态生图、分镜首帧接线和设定 bundle 持久化，让状态字段成为正式消费来源。
5. 更新架构 wiki、发布说明和 README 最新更新，执行针对性测试、typecheck/build 与 API 回归。

## 验收口径

- 场景编辑界面除场景名外，类型、时间、天气、图片提示词都出现在选中状态的右侧详情中。
- 道具编辑界面除道具名外，图片提示词只在状态详情中维护；旧 45° 图片入口不再作为正式编辑入口。
- 三类编辑弹窗宽度统一为 `max-w-6xl`，状态图仍可点击进入独立大图预览。
- 旧场景/道具没有状态 JSON 时，列表和状态生图仍能得到一个完整初始状态。
- 场景状态生图和分镜首帧提示词包含状态的类型/时间/天气，并继续禁止人物、动物、怪物和其他生物。
