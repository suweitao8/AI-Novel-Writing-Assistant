# IndexTTS 2.5 切换实施计划

## 1. 供应商槽位切换

- 在 shared LLM provider 类型中增加 `indextts25`，移除当前默认槽位对 `voxcpm2` 的依赖。
- 更新服务端供应商注册表、音频槽位、能力表和环境变量示例。
- 保留旧配置数据，不做数据库迁移删除；当前解析只读取新的 IndexTTS 槽位。

## 2. IndexTTS 协议适配

- 在统一音频入口中加入 IndexTTS API 请求模型。
- 实现参考音频解析：data URL、本地路径、HTTP(S) 地址和默认参考音频。
- 对参考音频做内容指纹缓存，避免每次合成反复写入；不删除整合包原有文件。
- 映射 `speaker`、`text`、`duration_factor`、情绪文本和默认参数，接收 WAV 二进制并保持现有 data URL/响度出口。
- 更新短剧 TTS provider 名称与映射测试。

## 3. 启动链替换

- 新增 `start-indextts25-api.cjs`，启动整合包的 `app_api.py`，健康判定只要求 `/health` 返回 `status=ok`。
- 根目录和 server 开发脚本改为 IndexTTS 启动器。
- 移除 VoxCPM2 启动脚本和过期的开发编排断言，确保普通开发启动不会重新拉起 18761。

## 4. 文档与测试

- 更新模型类别 wiki、音频供应商 wiki 和开发环境变量说明，记录 API 与网页工作台的边界。
- 更新服务端音频单元测试和启动器测试，覆盖协议字段、参考音频缓存、懒加载健康状态、错误返回和端口配置。
- 使用现有测试命令执行共享包构建、服务端构建、服务端 node 测试和 workflow 测试。

## 5. 真实运行验证

- 启动 IndexTTS 2.5 API 并检查 9005 的 `/health` 与 `/voices`。
- 调用真实 `POST /tts` 生成短中文 WAV，检查 RIFF/WAVE 头、采样率、文件大小和服务日志。
- 检查 9000 网页工作台的核心 Tab 可见，并确认 VoxCPM2 进程/18761 端口未恢复。
- 完成隔离分支提交、主分支集成、显式推送和工作树清理，最后核对本地与远端 `main` 一致。
