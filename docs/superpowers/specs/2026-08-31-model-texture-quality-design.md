# 模型贴图质量修复设计

## 背景

模型库的 3D 预览在近距离查看时出现严重像素化。已用截图对应的山石颜色贴图确认：源文件为 `2048×2048`、约 `8.7MB`，发布后的文件仍为 `2048×2048`，但只有约 `162KB`。运行时加载链路没有二次缩放；问题发生在模型入库脚本的 FFmpeg JPEG 编码阶段。

当前脚本把 `-q:v 82` 当成了 JPEG 质量百分比。对 FFmpeg 的 MJPEG 编码器而言，`q:v` 是量化值，数值越小质量越高；`82` 会把高分辨率源图压成低细节贴图，因此仅提高尺寸上限并不能解决问题。

## 目标

1. 颜色、法线和 RMA 贴图在保持现有尺寸上限的前提下，使用高质量 JPEG 编码。
2. 重建当前已入库的贴图，保持文件名和模型清单 URL 不变，避免数据库或前端数据迁移。
3. 让模型卡片丢弃旧的低质量缩略图缓存。
4. 用自动化检查防止导入脚本再次回到高量化值，并保留可复现的质量证据。

## 方案

- 导入脚本的 JPEG 量化值统一改为 `2`；`baseColor` 继续限制到最长边 `2048`，normal/RMA 继续限制到 `1024`。
- 为导入脚本增加显式重建开关，默认仍跳过已有输出，重建时通过环境变量开启，避免日常增量导入重复处理全部贴图。
- 先备份当前静态贴图目录并校验文件数量与字节数，再将所有能找到源文件的已发布 JPEG 以新参数生成到临时目录，全部成功后覆盖发布目录。
- 模型缩略图缓存键从 `v18` 升到 `v19`，让浏览器重新生成卡片预览；3D 运行时不额外加入未经证实的纹理降采样或 UV 改动。
- 更新模型库 wiki，明确 FFmpeg `q:v` 的量化语义和重建规则；在客户端契约测试中钉住代表性贴图质量与缩略图版本。

## 非目标

- 不修改 GLB 几何、UV、材质槽位映射或数据库数据。
- 不把 1024 的法线/RMA 无条件扩大到 2048；本次修复针对编码质量，不改变现有尺寸策略。
- 不通过运行时锐化、放大或后处理掩盖源贴图压缩问题。

## 验证

- 先运行回归测试，确认当前代表性岩石贴图和缩略图版本检查失败。
- 重建后检查贴图数量、尺寸、代表性文件字节数及 FFmpeg 可读性，并确认源图与发布图的文件名映射完整。
- 运行客户端契约测试、客户端类型检查、构建和 `git diff --check`。
- 在固定的本地 5174 页面打开模型 3D 预览，确认模型能加载、材质细节恢复、没有新增控制台或网络错误；若端口被其他任务占用，保留该任务并记录无法执行的具体浏览器检查。
