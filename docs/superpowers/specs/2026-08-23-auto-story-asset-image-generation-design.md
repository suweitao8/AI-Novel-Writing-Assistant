# 角色、场景、道具缺图自动生成设计

## Background

角色、场景和道具已经使用状态图作为正式图片数据，服务端也已经提供按资产状态生成图片的接口。当前生成入口仍然是资产详情弹窗里的手动按钮，资产创建、参考内容应用或历史数据加载后，如果默认状态没有图片，用户必须逐个打开资产并手动生成。

本需求的目标是让缺少默认状态图的角色、场景、道具在资产数据进入前端后自动补图，覆盖新创建资产、参考内容应用产生的资产以及历史遗留资产，同时沿用现有图片生成服务和存储契约。

## Decision

采用前端补偿扫描方案：在小说设置页和漫剧工作室挂载一个无界面的自动生成协调器。协调器读取三类资产列表，找到每个资产的默认状态（优先 `label=默认`，否则使用第一个状态），对没有可用图片且当前不在生成中的状态调用现有 `generateStoryAssetStateImage` 接口。

这样，创建或参考内容应用只要让已有 React Query 缓存失效，自动协调器就会在列表重新加载后发现缺图并开始生成；进入资产区域时的首次扫描则负责补齐旧数据。无需把生图请求塞进创建事务，也不需要新增数据库任务表、队列或第二套图片存储逻辑。

### 触发与去重

- 扫描角色、场景、道具三类资产的默认状态。
- `done` 且存在 URL 的状态视为已完成；`generating` 由后端或其他页面接管，自动协调器跳过，避免重复请求。
- `idle`、没有 URL 的状态自动提交生成；`error` 状态在当前页面会话中最多自动重试一次，失败后保留错误状态并交给详情弹窗中的手动重试入口。
- 以 `novelId + kind + assetId + stateId` 作为请求键，在页面会话内去重。创建、更新或缓存失效导致的多次扫描不能重复提交同一状态。
- 采用固定的 3 路并发上限，队列耗尽后继续处理剩余资产，避免一次打开项目就把图片服务压满。

### 状态与界面反馈

协调器在请求开始时先把对应缓存状态乐观更新为 `generating`，请求完成后使用服务端返回的资产更新缓存；失败时写回 `error`，保留服务端错误信息。这样资产卡片和大纲侧栏不需要知道请求来自自动流程，也能立即显示同一状态。

资产展示模型补充默认状态图片状态字段。缺图卡片显示带高亮的“生成中”状态和加载图标；生成失败显示“生成失败”，用户打开详情后仍可使用现有“生成图片/重新生成图片”与取消能力。自动生成成功不逐项弹 toast，整批结束时仅在有失败或确实生成了图片时给出一次简短结果反馈，避免大量资产同时生成时打扰用户。

所有新增状态样式复用项目语义 token 和现有 UI 组件，不写死颜色；自动流程本身不增加新的用户操作控件。

### 入口覆盖

- `StorySettingsTabs`：覆盖短篇工作室和小说简易书架的角色、场景、道具设定页。
- `ComicDramaStudioPage`：在漫剧工作室页级挂载协调器，即使当前停留在脚本、解析或分镜页，也能在资产被创建或应用后自动补图；缓存更新会同步资产页和大纲侧栏的展示。
- 参考内容应用、详情弹窗保存、大纲侧栏快速创建继续使用现有缓存失效流程，不在各个创建入口复制生图逻辑。

## Data and API contract

不修改服务端路由、数据库结构或图片提供商选择。自动协调器只调用已经存在的三个同构状态图片生成接口，并通过现有 React Query key 更新列表缓存。默认状态的判定和状态图片字段沿用 `StoryAssetState` / `StoryAssetStateImage` 共享契约，避免重新解释旧版资产的顶层兼容图片字段。

## Testing

- 先为纯函数补充测试：默认状态选择、缺图筛选、`generating/done/error` 状态判定、会话去重和 3 路并发调度。
- 补充展示契约测试，确认自动生成中的默认状态能投影到资产卡片和预览模型。
- 运行相关客户端类型检查与既有资产/状态图片测试；运行服务端构建，确认复用接口没有破坏服务端契约。
- 浏览器中的实际图片生成依赖本地模型网关和真实项目数据，代码验证完成后由用户在当前漫剧工作室执行一次资产页/脚本页验收。

## Non-goals

- 不把静态分镜改回图生视频或首帧流程。
- 不为自动补图新增独立后台任务系统或数据库状态表。
- 不自动重生成已有有效图片，也不改变现有图片生成服务的供应商路由。
- 不删除失败状态；失败必须可见并保留现有手动重试路径。
