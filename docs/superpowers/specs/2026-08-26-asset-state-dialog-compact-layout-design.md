# 资产状态编辑弹窗紧凑布局设计

## 背景

角色、场景、道具共用 `AssetStatesEditor`。当前状态名单独放在状态图片之前，时代风格又位于图片之后，导致用户需要在弹窗中上下寻找短字段，也浪费了状态图片上方的空间。

## 目标

- 三类资产统一采用“状态图片在上、状态资料在下”的顺序。
- 状态名与时代风格在资料区第一行并列展示。
- 角色、场景、道具的短字段在桌面端按两列排列；窄屏自动回到单列。
- 图片提示词、提示词改写、音色提示词等长内容继续占满整行。
- 保留现有字段、生成入口、3D 编辑入口、校验、保存和数据结构，不改变业务行为。

## 方案

只调整 `assetForms.tsx` 中共用状态详情的 JSX 顺序和网格布局：状态图片区整体提前；图片参考选择与图片操作仍紧跟图片；随后把状态名、时代风格和其他类型字段放入紧凑的 `md:grid-cols-2` 资料区。场景类型、时间、天气不再强制三列，按两列规则自然换行；需要占满宽度的文本字段继续使用 `md:col-span-2`。

## 验证

- 契约测试验证状态图片区出现在状态设定区之前。
- 契约测试验证状态名与时代风格处于同一双列资料区，并验证场景字段不再使用三列布局。
- 运行资产状态相关定向测试、客户端类型检查和构建。
- 在角色、场景、道具三个实际编辑入口打开弹窗，确认图片置顶、字段双列、窄屏无溢出，且取消/保存行为不变。
