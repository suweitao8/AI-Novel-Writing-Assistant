# 动画导出姿态修复设计

## 背景

动画库当前发布的 `UAL2_UE_Anims.glb` 能被 PlayCanvas 正常加载，但页面缩略图中的待机、行走和坐姿表现与预期不一致。检查结果表明，问题不能用“GLB 损坏”概括：目标文件的动画旋转通道是 `VEC4`，四元数长度正常，通道也只指向蒙皮关节；现有重定向结果按其绑定姿态差公式能够重组回目标姿态。

真正的异常在源 UE 动画的基准姿态。原始 `A_INP_Idle` 的首帧与源骨架节点绑定姿态最大相差约 73.7°，而整段动作的局部旋转变化只有约 6.8°；`A_INP_WalkFwd_Loop` 也存在约 40–62° 的首帧基准偏差。重定向器把这些数据当成绝对姿态处理后，目标角色会保持绑定姿态附近的小幅抖动，因而呈现为 T 姿或动作内容缺失。项目 wiki 已记录这与 UE Additive 设置或 FBX 导出未烘焙绝对姿态相符。

## 目标

1. 当前三段动画在目标 UAL2 角色上具备正确的绝对姿态和动作语义：待机不是绑定姿态、行走有交替腿部运动、坐姿保持坐下姿态。
2. 保留并验证现有的“绑定姿态差重定向”算法，不在预览器中加入会破坏其他动画的首帧补偿。
3. 把“格式合法但内容基准错误”纳入自动质量门禁，阻止相同问题继续进入动画库。
4. 动画资源更新后，缩略图缓存必须自动失效并重新生成。

## 不采用的方案

### 在 PlayCanvas 播放时减去首帧

不采用。首帧归一化会把真正需要保留的坐姿、蹲姿和行走重心也抹掉，只是掩盖源数据错误；同时会让同一个片段在不同绑定姿态下产生不一致结果。

### 只修改 `rootBone` 或节点映射

不采用。当前独立重组验证已经证明目标关节映射与旋转写入是自洽的；改播放器节点层级不能修复源动画缺失的绝对姿态。

### 只替换当前二进制，不增加校验

不采用。一次性替换无法防止后续 UE/FBX 导出再次产生同类“能加载但不能用”的片段。

## 选定方案

采用“源侧烘焙 + 绑定姿态差重定向 + 资源内容门禁 + 缓存版本化”的闭环：

1. 在 Cine57 的 UE 动画导出阶段读取原始 `AnimSequence`，确认待机、行走片段不是以 Additive 数据直接导出；必要时在导出前按骨架参考姿态烘焙为绝对骨骼变换。导出的 FBX/GLB 必须保留真实动作首帧，而不是只有相对增量。
2. 使用现有 `final_retarget.py` 的绑定姿态差公式，将三段源动作重定向到 UAL2；修正验证器，使它比较“目标绑定姿态差重建后的世界旋转”，而不是错误地直接比较两个不同骨架的世界四元数。
3. 在客户端测试中解析发布的 GLB，检查 GLB 结构、单位四元数、关节目标、片段时长，以及三段动作的内容指标。内容指标基于采样后的骨骼世界姿态：待机应明显偏离绑定姿态、行走应同时具备双腿运动和交替足部轨迹、坐姿的骨盆高度和膝部弯曲应保持坐姿范围。
4. 提升动画缩略图的缓存版本，使新的 GLB 不会继续使用旧的 `localStorage` 缩略图；保留现有离屏 PlayCanvas 生成流程。
5. 更新动画库 wiki，记录源动画必须绝对姿态烘焙、重定向校验的边界和发布前抽查路径。

## 边界与兼容性

- 不修改模型网格、蒙皮权重和现有 43 段 UAL2 原生动画。
- 只替换同一个动画库 GLB 中的三段导入片段，保持目录 id、分类、片段名和时长契约不变。
- 未匹配的目标非关节包装节点继续保留静止变换，避免把 `Mannequin` 网格包装节点误当成骨骼驱动。
- 发布前必须同时通过客户端静态测试、资源内容测试和实际页面缩略图/预览回归；没有浏览器证据时不能声称 UI 修复完成。

## 验收标准

- 发布 GLB 中三段导入片段的旋转输出均为合法 `VEC4`，且每个采样四元数长度在误差范围内接近 1。
- 所有动画通道目标均属于目标 skin joints；目标骨骼世界旋转能按绑定姿态差公式重建，误差不超过 `1e-3` 的四元数点积阈值。
- 待机、行走、坐姿的内容指标分别通过，不能只用“文件能加载”判定成功。
- 页面首次进入动画库会生成新版本缩略图；清除/更新资源后不会显示旧的绑定姿态截图。
- 现有动画目录契约、TypeScript 类型检查、客户端测试和固定端口浏览器烟测均通过。
