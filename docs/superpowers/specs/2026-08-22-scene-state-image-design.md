# 场景状态图片统一设计

## 背景

设定中心的场景目前同时存在两种图片来源：`NovelScene.imageData` 中的旧版 360° 全景图，以及 `statesJson` 中按外观状态保存的状态图。场景编辑弹窗把两种来源并列展示，用户无法判断哪一张才是当前场景的正式图片；而角色已经通过状态列表选择状态、在右侧查看当前状态图片。

## 决策

场景与角色采用同一套状态图片语义：

- 场景编辑器只把 `statesJson` 的状态图作为正式展示和生成入口。
- 左侧状态列表显示每个状态的缩略图；右侧只显示当前选中状态的一张主图，并沿用现有的大图预览入口。
- 移除场景编辑器中的独立“360° 全景参考图”展示和生成按钮，避免产生第二套主图。
- 大纲侧资产详情同样只展示场景状态图，不再把旧全景图和状态图混排。
- 首帧参考链只使用场景初始状态的已生成图片；初始状态没有图片时不引用场景图片，不再回落到旧全景图。
- 保留 `imageData` 字段、旧文件和兼容接口，不做数据删除或数据库迁移。历史全景图只作为兼容数据保留，不再作为场景状态图片的产品入口。

## 数据流

场景编辑页继续通过 `statesJson` 保存状态描述、图片提示词和生成结果。状态图生成接口返回更新后的状态数组，前端用它刷新左列表和右侧详情。场景的基础 `environmentPrompt` 仍作为状态生成的基础环境描述，但不再单独渲染为一张场景图片。

首帧生成时，场景引用解析器从 `statesJson` 规范化出初始状态：状态图片已生成则作为场景参考图；没有状态图则只带入环境提示词，不再读取 `imageData` 的全景图。

## 交互与状态

- 无状态图时保留现有空状态和“生成图片”入口。
- 生成状态图时按钮保持禁用并显示加载态，成功后刷新状态图并提示成功，失败保留重试入口。
- 状态列表仍支持鼠标和键盘按钮操作；弹窗和大图预览继续使用现有通用组件。
- 不新增颜色、弹窗或图片组件，沿用项目设计 token、`AssetStatesEditor` 和 `LightboxImage`。

## 验证

- 客户端契约测试确认场景设置页和大纲详情不再渲染独立全景图，并继续使用状态图编辑器。
- 服务端契约/单元测试确认首帧场景参考只从初始状态图片取值，不回落 `imageData`。
- 客户端类型检查通过。
- 运行中的 5174 页面验证场景编辑器只显示状态图片，点击状态和生成/预览入口行为正常。
