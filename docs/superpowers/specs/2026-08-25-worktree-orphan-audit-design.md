# 工作树生命周期审计与孤立目录恢复设计

## 背景

当前文件系统守卫能检查一个 checkout 内的 `shared/` 和依赖入口，但 Git worktree 登记本身可能在一次失败的清理后丢失。此时目录仍然存在、分支仍可能存在，却不会出现在 `git worktree list` 中；如果下一次会话把它当成普通目录处理，仍有机会再次触碰共享源码。当前环境已经发现两个这种历史孤立目录，并且还有一个 Git 标记为 `prunable` 的登记项。

## 目标

1. 在创建新工作树、集成和清理前，发现 Git 登记缺失、登记不可用或分支对应目录残留，阻止继续执行可能扩大影响的工作流。
2. 提供只读审计入口，明确列出登记工作树、`prunable` 状态、分支与预期路径不一致，以及可疑孤立目录。
3. 提供显式的 `--apply` 恢复入口；默认只检查，不删除任何文件。
4. 只有在以下证据全部成立时才允许清理孤立目录：
   - 当前运行目录是干净的 `main`，且没有未完成 merge；
   - 目标是精确的本仓库 `codex/<slug>` 分支，分支已合入当前 `main`；
   - 目标路径是创建器按分支 slug 推导出的同级路径，未被 Git 登记，根目录不是链接且没有 `.git` 元数据；
   - 除六个已知 workspace 依赖根外，目录内文件集合和内容逐项匹配该分支 Git 树，没有额外或缺失源码；
   - 六个依赖根及其内部链接全部通过不跟随式路径检查。
5. 递归检查依赖树中的链接，而不只检查根目录和 scoped package 的第一层入口。

## 非目标

- 不自动恢复缺失的源码、不执行 `git restore`，不覆盖或猜测用户文件。
- 不扫描并删除任意同名目录；无法证明所有权和内容一致时只报告并保留现场。
- 不自动清理其他会话的活动工作树、`detached` 工作树或未合入分支。
- 不把孤立目录审计变成服务启动时的隐式删除动作。

## 方案

### 1. 生命周期审计

新增 `scripts/worktree-lifecycle-audit.cjs`，使用 Git 的登记列表和本地 `codex/*` 分支列表建立状态表：

- `registered`：正常登记、`detached`、缺失路径和 `prunable` 状态；
- `branchWithoutRegistration`：分支存在，但创建器推导的同级目录仍存在且没有登记；
- `orphanCandidates`：满足路径命名约定、但未登记的目录，附带分支和路径证据；
- `unresolved`：任何会影响创建/集成/清理安全性的异常。

`pnpm workflow:audit` 默认只读并返回非零状态，输出每个异常的路径、分支、登记状态和下一步受控入口。它不调用递归删除，不修改 Git 元数据。

创建器、集成器和清理器在执行改变工作树拓扑的动作前调用同一审计断言。服务启动仍只检查当前 checkout 的源码和依赖，避免无关历史残留把正在运行的业务工作树静默修改；需要创建、集成或清理时必须先解决审计异常。

### 2. 依赖树检查

将依赖入口扫描改成递归的 `lstat`/`realpath` 遍历：普通目录继续扫描，链接只解析目标且不跟随进入；目标必须在当前 checkout 内。这样 `node_modules/pkg/node_modules/*` 或非 scoped package 下的 Junction 也会被捕获。清理器继续复用同一安全边界，并在所有依赖根验证通过后才删除。

### 3. 受控恢复

新增 `scripts/recover-orphan-worktree.cjs` 和 `pnpm workflow:recover-worktree`：

```powershell
pnpm workflow:recover-worktree codex/<task>
pnpm workflow:recover-worktree codex/<task> --apply
```

不带 `--apply` 时只打印验证结果。`--apply` 需要再次满足全部恢复证据；恢复顺序为：验证 Git 树和依赖根 → 删除六个固定依赖根 → 删除精确孤立目录 → 确认目录消失 → 删除已合入的本地分支。任何一步失败都保留现场，不执行后续动作。

Git 树比较使用 `git ls-tree` 的 blob 内容哈希和受控目录遍历；目录存在额外文件、缺少跟踪文件、包含未允许的 reparse point，或分支未合入时，恢复直接拒绝。

## 验收标准

- 当前环境中的 `prunable` 登记和两个已知孤立目录能被只读审计准确列出。
- 创建器和集成器在存在未解决生命周期异常时非零退出，且不创建、合并或删除目录。
- 依赖树深层外部链接测试能被守卫阻断。
- 未提供 `--apply` 时恢复命令不改变目录、分支或 Git 登记。
- 对内容完全匹配、分支已合入且仅含依赖目录的测试夹具，`--apply` 按固定顺序安全完成；内容缺失/新增/外部链接任一情况都拒绝清理。
- 既有 `pnpm test:workflow` 和文档检查通过，主工作区与其他活动工作树保持不变。
