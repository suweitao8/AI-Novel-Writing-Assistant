# 漫剧分镜摆位草图设计

## 背景

场景状态图已经是可环视的 2:1 等距柱状全景，分镜首帧也会读取当前镜头的角色状态图、场景状态图与道具图作为参考。但现有链路没有保存“这一镜的人站在哪里、占画面多大、谁在前谁在后”的明确构图事实，模型每次重生成都会重新猜测，导致同一场景的角色站位漂移。

旧项目 mydrama 的导演世界将场景、相机和演员摆位保存为快照，导出控制帧，再转换成草图作为下游生成的首要参考。本次保留这条“可编辑摆位事实 → 可视草图 → 已确认参考图”的生产边界，但不引入旧项目的 3D 世界、碰撞与深度资产：当前需求需要稳定分镜构图，而不是完整三维导演台。

## 决策

每个 `DramaShot` 新增一份独立的摆位草图数据与 PNG：

- 草图画布固定为横屏 16:9（1280×720），属于当前镜头，不会改变场景资产本身，也不会串到同一场景的其他镜头。
- 背景来自镜头 `location` 匹配的场景默认状态图。编辑器使用 360° 全景的等距柱状水平环绕裁切，用户可拖动选择当前方向、调整俯仰与视野。
- 角色来自镜头 `characterRefs` 与镜头 `characterStates` 指定的状态图；状态图是四视图板时固定裁取第三格“全身正面”作为透明摆位素材。没有状态图时保留带姓名的轮廓占位，允许先建立构图，但不伪造资产图。
- 用户能拖动角色、调整大小、左右翻转、改变前后层级、删除后重新加入。位置和相机均按归一化数据保存，重新打开会还原同一构图。
- “保存草图”会将当前画布写入专属 PNG 文件，并把相机、角色摆位与版本写入 `DramaShot.blockingSketchData`；“确认草图”只允许已有 PNG 的草图，并将状态切换为 `confirmed`。
- 确认后的草图在正式首帧图生成时始终作为第一张参考图，同时保留角色状态图、场景图和道具图作为身份与材质参考。生成提示明确要求锁定草图的场景视角、角色位置、相对大小、朝向与前后关系，不渲染草图的辅助框、姓名或控制标记。
- 没有草图的历史镜头完全沿用当前生成方式。存在未确认草图时，单镜与批量首帧生成都不得偷偷使用半成品；UI 明确引导用户先确认或继续编辑。

## 数据契约与存储

`DramaShot` 增加可空 `blockingSketchData` JSON 列，PostgreSQL 与 SQLite 迁移同时补齐。结构化数据只存可恢复编辑所需的事实，不存图片二进制：

```ts
type DramaShotBlockingSketchData = {
  status: "draft" | "confirmed";
  version: number;
  url?: string;
  generatedAt?: string;
  scene: {
    assetId: string;
    stateId: string;
    imageUrl: string;
    yawDeg: number;
    pitchDeg: number;
    fovDeg: number;
  };
  actors: Array<{
    characterName: string;
    assetId?: string;
    stateId?: string;
    imageUrl?: string;
    x: number;
    y: number;
    scale: number;
    flipX: boolean;
    zIndex: number;
  }>;
};
```

PNG 写入 `generated-images/drama-shots/<shotId>/blocking-sketch.png`，公开读取地址为 `/api/drama/shot-images/:shotId/blocking-sketch`。同一镜保存新版本覆盖当前 PNG，并在 JSON 中递增版本；后续如需草图版本历史可沿用首帧图的历史存储模式，但本期不额外暴露历史选择界面。

API 分为三类动作：读取草图、保存构图数据、上传渲染后的 PNG、确认草图。图像上传使用 `image/png` 原始二进制，避免把 1280×720 图片塞进 JSON；服务端验证镜头确属请求项目、图像大小与 PNG 类型，并只允许结构化坐标的安全范围。

## 前端交互

入口位于每镜的画面区域，按钮标签为“摆位草图”。打开后使用项目现有的 `Dialog` / `AppDialogContent`，不会新增 UI 库。

编辑器左侧是 16:9 画布：背景可通过鼠标拖动环视、滚轮调视野；角色在画布内可鼠标拖动，选中后显示最小化边框与四项直接操作（缩小、放大、左右翻转、前移/后移）。右侧是本镜角色列表，点击即可加入；没有匹配场景全景或角色状态图时展示可恢复的空/错误状态。底部只保留“保存草图”“确认草图”和“取消”三个操作，保存/上传期间禁用重复提交并显示进行中状态。

画布采用可导出的 `<canvas>` 实现，以保证用户看到的全景裁切、角色摆位和输出 PNG 是同一份数据。WebGL 不可用时沿用现有全景预览的 Canvas2D 降级策略；降级不改变角色坐标、保存格式或参考图接线。新增 UI 只使用语义色 token、现有按钮/对话框/toast，并提供键盘可达按钮、可见焦点和所有异步状态。

## 正式首帧生成接线

`DramaShotKeyframeService` 将读取 `blockingSketchData`：

1. 草图不存在或状态为 `draft`：保持当前参考图列表和当前生成行为；批量任务跳过 draft 草图镜头并回传可恢复原因。
2. 草图为 `confirmed` 且图片可读取：将草图 URL 放在 `refImages` 与 `referenceImages` 的首位，标记为 `layout_sketch`。
3. 原有角色状态图、角色设计稿、场景状态图、道具图仍依次追加，避免草图只锁位置却丢失角色身份和场景材质。
4. 首帧提示词迁入 Prompt Registry 的 `drama.shot.keyframe` PromptAsset；该 Prompt 在检测到确认草图时追加明确的构图约束，确保产品提示词不继续散落在服务类中。

单镜“生成画面”与批量“生成分镜”均走同一服务，因此不会出现单镜使用草图、批量忽略草图的分叉。

## 模块边界

- `server/src/services/drama/visual/`：草图数据校验、文件存储、首帧参考图组装；不把 HTTP 参数解析或 React 状态放入该目录。
- `server/src/modules/drama/http/`：草图读写/确认/图片读取路由，以及请求 schema。
- `client/src/pages/drama/comicDrama/components/`：每镜摆位草图编辑器与画布交互，私有于漫剧工作台。
- `client/src/api/media/drama.ts`：草图 DTO 和 API 调用。
- `server/src/prompting/prompts/drama/`：首帧生成 PromptAsset；服务层只提供结构化上下文。

## 兼容与失败处理

- 已有分镜没有 `blockingSketchData` 时仍可立即生成首帧，不触发数据迁移或强制补图。
- 场景未生成全景、镜头没有角色、或角色状态图缺失时，编辑器不崩溃：禁用无法保存的构图，并用明确的下一步提示说明需要哪项资产。
- 保存草图后编辑器关闭或刷新不会丢失已保存坐标；上传失败保留本地编辑态并允许重试。
- 重新生成正式首帧不会覆盖摆位草图；重新保存/确认草图只更新草图自己的版本。
- 删除镜头时由现有 `DramaShot` 级联删除语义处理，草图文件可按镜头图片目录一并清理；本期不改变项目级资产的删除规则。

## 验收

- 用户可在任意有场景与角色的镜头打开 16:9 摆位草图，选择全景视角、摆放角色、保存后重新打开并得到相同位置。
- 确认草图后，首帧预览接口与实际生成接口均显示草图为第一张参考图；单镜和批量调用一致。
- 未确认草图不会进入正式生图；无草图的存量镜头维持原行为。
- 角色位置、缩放、翻转、层级、全景方向/俯仰/视野的纯计算有单元测试；服务端有项目归属、状态转换、文件存储和参考图排序测试；客户端有入口、交互状态与 API 契约测试。
- 服务端和客户端类型检查、相关聚焦测试、客户端构建通过；变更同步到漫剧工作流 Wiki、release note 和 README 最新更新。
