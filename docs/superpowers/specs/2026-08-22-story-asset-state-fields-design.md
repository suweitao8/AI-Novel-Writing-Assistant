# 故事资产状态字段归一化设计

## 背景

角色、场景、道具已经共用状态列表，但场景的类型、时间、天气和环境提示词仍停留在资产顶层，道具的图片提示词也停留在顶层。编辑时同一份资产被拆成两套信息，生成状态图又只能从旧字段兜底，容易出现图片与状态不对应、场景状态无法复现的问题。

## 目标

- 场景编辑器的资产级信息只保留场景名；场景类型、时间、天气、图片提示词和状态描述都由状态编辑器管理。
- 道具编辑器的资产级信息只保留道具名；道具图片提示词进入状态的图片提示词。
- 角色继续保留姓名与性别这两个身份字段；年龄段、外貌、图片提示词和音色提示词继续归属于角色状态。
- 三类资产都在新建时直接显示统一的左侧状态列表、右侧状态详情编辑器；编辑弹窗扩大并减少无效留白。
- 旧数据库列和 API 字段继续保留，读取旧数据时自动迁移到初始状态，旧调用方仍可读取兼容字段。
- 状态图、分镜首帧和详情展示优先消费状态字段；场景状态提示词继续强制为空环境，不引入人物、怪物或动物。

## 非目标

- 不删除旧数据库列、旧接口或旧图片文件；本次只改变正式编辑入口和消费优先级。
- 不把角色性别这种稳定身份字段挪进状态，避免影响既有角色引用和音色逻辑。
- 不改变状态图片生成供应商、参考状态链或图片预览组件。

## 设计

### 状态模型

`StoryAssetState` 增加可选的 `sceneType`、`timeOfDay`、`weather`。这三个字段只由场景状态使用，但共用状态契约允许它们随状态保存。场景/道具初始状态由旧顶层字段补齐；已有状态中的显式值永远优先。

### 编辑器

`AssetStatesEditor` 根据资产类型显示状态专属字段：角色显示年龄段、音色提示词和图片提示词；场景显示场景类型、时间、天气和图片提示词；道具显示图片提示词。所有状态的图片、生成按钮、参考状态、状态描述和状态名保持同一布局。

三类编辑弹窗使用 `max-w-6xl`，状态列表增加可用高度，状态图使用更大的比例容器但仍由 `LightboxImage` 提供独立大图预览。场景和道具在新建弹窗也显示状态编辑器，保存时一次提交名称和状态数组。

状态编辑器的视觉顺序固定为「状态图片 → 图片设定 → 音色」。左侧状态列表只承担选择，保留缩略图、状态名和必要的编辑/删除操作；不重复展示图片或音色是否已生成、参考状态和状态描述。右侧不再展示“已生成/待生成”徽标，图片存在与否由图片本身表达；角色的音色提示词、音色处理方式、试听和生成操作集中在底部整行区域，场景和道具沿用相同的图片区与图片设定区结构。

### 兼容与消费

服务端 `normalizeSceneStates` 把旧场景列映射到初始状态；状态已经存在时只补缺失的初始字段，不覆盖人工填写。正式状态图片服务、分镜首帧设定接线和详情展示都读取初始/当前状态字段。顶层旧列仍按原接口返回，供旧数据和旧调用方平滑过渡。

## 验证

- 客户端契约测试锁定三类编辑器的字段归属、创建时状态编辑器和弹窗宽度。
- 服务端契约测试锁定状态类型、旧字段归一化、场景纯环境提示词以及首帧接线。
- 运行客户端状态/资产测试、服务端状态/图片测试、客户端 typecheck 和服务端 build。
- 通过本地 API 检查场景列表仍能返回状态字段；UI 浏览器验收由用户继续确认最终视觉效果。
