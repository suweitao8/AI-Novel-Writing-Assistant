# 场景类型驱动的 3D 环境默认参数设计

## Background

场景资产已经在解析结果和状态数据中保存了 `interior`（室内）、`exterior`（室外）和 `nature`（自然）三种类型。3D 场景编辑器目前只读取固定的 `2 / 15` 环境快照，因此室内和自然场景无法获得适合自己的半球尺寸；分镜阻挡预览也可能沿用另一套默认结果。

当前 3D 环境参数是场景级数据，状态图是场景级环境的视觉输入；但设定中心的场景类型已经属于具体状态，场景表的 `sceneType` 只作为旧数据兼容列。用户在场景状态入口进入 3D 编辑器，所以未自定义时必须优先使用场景默认状态（第一个状态）的类型，同时兼容场景级类型；切换到其他状态只会切换图片和状态标记，不会让同一场景的唯一环境参数产生另一套半球直径。

## Decision

### 1. 统一默认规则

所有默认环境都使用：

| 场景类型 | 投射中心高度 | 半球直径 |
| --- | ---: | ---: |
| 室内 `interior` | 2 | 10 |
| 室外 `exterior` | 2 | 15 |
| 自然 `nature` | 2 | 20 |

全景地面分界继续使用 `0.5`，水平旋转固定为 `0`，环境亮度固定为 `1`。类型缺失或不是受支持的枚举值时按室外处理，保证历史数据仍能打开且不增加模型调用延迟。

### 2. 类型来源与优先级

因为 3D 参数存储在场景级、而场景类型存储在状态级，场景级环境的类型解析顺序为：

1. 场景默认状态（第一个归一化状态）的 `sceneType`；
2. 场景级 `sceneType`，用于兼容旧数据或状态类型为空的记录；
3. `exterior` 兜底。

场景列表、3D 编辑器、空间标记分析和分镜阻挡都使用同一个场景默认状态类型；即使空间标记分析针对其他状态，也必须复用场景级环境参数，避免同一场景出现不同半球直径。

不新增 AI 分类请求。解析链已经有结构化类型；只有在数据缺失时使用确定性的安全默认，而不是用关键词或图片猜测掩盖数据问题。

### 3. 保留用户自定义参数

服务端环境解析层增加“按类型取得默认值”和“解析持久化环境”的统一入口。未配置的环境、空值、非法 JSON，以及历史版本写入的固定默认快照 `{ projectionCenterHeight: 2, domeRadius: 15, panoramaHorizonV: 0.5, yawDeg: 0, intensity: 1 }`，视为未自定义，并按场景类型解析。

用户通过 3D 编辑器保存过的参数会带有已配置标记；后续重新进入页面、切换场景状态或更新场景类型时，保留这些数值，不自动重置。历史数据无法区分“用户恰好保存了 15”与旧默认值时，以旧默认迁移兼容为准；用户下一次保存后会获得明确的自定义标记。

### 4. 所有读取链路使用同一规则

- 新建场景和导入场景：没有显式 3D 参数时写入对应类型的未自定义默认值。
- 设定中心场景接口：按首个归一化状态类型、场景级兼容类型的顺序返回环境参数。
- 3D 场景编辑器：使用接口返回值初始化预览，只有保存时提交用户当前参数。
- 分镜阻挡/3D 预览：把场景默认状态类型作为首选传入同一解析器，避免编辑器显示的半球尺寸与实际阻挡预览不一致。
- 3D 标记分析：即使分析的是非默认状态，也把场景默认状态类型传入同一解析器，确保分析和预览看到的是同一环境尺寸。

3D 编辑器的 UI 控件不增加新的必填操作；高度和半球直径仍可由用户调整，规则只负责首次/未配置状态的默认值。

## Alternatives considered

### A. 推荐：服务端领域解析器统一处理

将类型映射、历史默认识别、显式自定义标记和归一化集中在 `StoryScene3dEnvironment` 领域模块，所有服务和客户端接口消费同一结果。优点是行为一致、无额外模型调用、可测试且不会被某个页面绕过。代价是需要兼容旧 JSON 格式。

### B. 仅在 3D 编辑器前端映射

改动小，但分镜阻挡预览、标记分析和其他服务仍可能拿到旧的 `15`，会产生“编辑器看到的参数”和实际生成参数不一致，因此不采用。

### C. 缺失类型时调用 AI 判断

可以依据名称、摘要或图片补类型，但会增加延迟、成本和不可重复结果；而且当前结构化解析已经提供了类型字段，不应在 3D 编辑阶段重复分类。因此只保留结构化字段与室外兜底。

## Runtime contract

对外返回的 `StoryScene3DEnvironment` 仍只包含数值参数，不暴露内部的自定义状态标记。内部 JSON 允许增加向后兼容的配置来源字段；旧 JSON 没有该字段时按上述历史默认识别规则处理。任何入参仍需经过原有范围校验：高度 `1..10`、半球直径 `10..50`、地面分界 `0.4..0.65`。

## Failure modes

- 类型缺失：先检查场景级兼容列，仍缺失时返回室外默认值 `2 / 15`，不阻塞页面。
- 类型非法：按类型缺失处理，不把非法值写回为新的类型。
- 环境 JSON 缺失或损坏：按当前场景类型生成未自定义默认值。
- 自定义环境 JSON：只做范围归一化，不能被类型默认覆盖。
- 类型变更但环境仍未自定义：下次读取使用新类型的默认半径。

## Verification

需要覆盖：三种类型的映射、缺失/非法类型兜底、空值与历史固定默认快照迁移、自定义参数保留、创建/导入序列化标记，以及 3D 编辑器和分镜阻挡服务对统一解析器的调用。完成后运行服务端环境单测、相关契约测试和前端类型检查。
