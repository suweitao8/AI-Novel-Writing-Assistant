# 故事资产卡片预览裁切设计

## Background

角色、场景、道具的故事资产卡片目前只有类型、名称、摘要和状态数量，没有稳定的视觉入口。角色状态图是一张多视图生产板，场景和道具状态图也可能是横向图片；直接把原图压进卡片会让卡片比例不一致，也不能快速识别资产。

## Decision

在客户端增加统一的 `StoryAssetPreview` 展示组件，并让 `StoryAssetPresentation` 为每个资产提供默认状态预览源。预览只属于卡片展示层，不新增数据库字段、接口或派生图片文件。

### Preview source

- 三类资产都优先取标签为「默认」的状态；如果存量数据没有该标签，则兼容使用状态数组第一项。
- 默认状态没有成功图片时，预览源为空，但卡片仍保留方形预览位并渲染统一占位。
- 图片 URL 继续通过 `buildStateImageSrc` 附加 `generatedAt` 缓存破坏参数，重新生成后卡片可以立即显示新图。

### Crop modes

`StoryAssetPreview` 接收展示模式，不在卡片里散落裁切样式：

- `character-top-left-grid`：把角色四视图板按水平 4 份、垂直 2 份理解，显示左上格作为头像预览。
- `center-square`：场景和道具显示默认状态图的水平居中方形区域，保留最核心的环境或物件。

两种模式共用方形容器、圆角、边框和加载失败占位。角色、场景、道具只改变裁切模式，不改变卡片骨架。

### Card layout

`StoryAssetCard` 改为左图右信息的可键盘触达结构：

1. 左侧固定方形预览位，普通资产卡使用较大尺寸，脚本侧紧凑卡使用缩小但仍存在的方形位。
2. 右侧显示类型徽标、名称、摘要、属性徽标和状态数量。
3. 点击预览或信息区域均打开现有详情入口；编辑/删除等外部操作继续阻止事件冒泡。
4. 图片加载失败和缺图都显示可理解的占位，不让卡片出现空白区域。

## Error handling and accessibility

- `img` 的加载错误转为统一占位状态，避免坏 URL 留下破裂图片图标。
- 有图片时使用资产名称和状态生成 `alt`；占位态使用简短的无图片说明。
- 卡片主体继续使用原有按钮语义、键盘 Enter/Space 和 focus ring；预览图不新增独立交互，不制造额外 Tab 停靠点。
- 使用现有语义颜色 token 和 `cn()`，不新增 UI 依赖或硬编码颜色。

## Testing

- 展示适配测试：默认状态优先级、无默认状态时第一项兼容回退、三类资产对应的裁切模式和缓存 URL。
- 组件契约测试：卡片使用共用预览组件、左图右信息结构、紧凑模式仍保留预览位、缺图占位和错误处理存在。
- 运行资产相关客户端契约测试、客户端 typecheck 和 `git diff --check`。

## Non-goals

- 不改变角色四视图、场景全景或道具图的生图提示词和生成规格。
- 不把裁切后的图片写入数据库、磁盘或新的 API。
- 不改变详情弹窗中的原图查看方式；详情仍展示完整状态图。
