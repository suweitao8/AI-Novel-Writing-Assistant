# 模型资产卡片缩略图 256px 性能与洁净画面设计

## 背景

模型库卡片的显示比例是 4:3，页面中单张卡片的最大显示宽度约为 256px，但离屏生成器仍以 288×216 输出 JPEG。所有模型卡片都会在进入列表时请求缩略图，过大的 data URL 会增加浏览器解码、内存缓存和 localStorage 读写负担。与此同时，卡片缩略图不应该复用带编辑器辅助网格的画面。

## 决策

1. 模型卡片缩略图统一输出 256×192 JPEG。
   - 256px 是最长边上限，192px 保持模型卡片现有 4:3 画幅。
   - PlayCanvas 离屏 canvas、固定绘图缓冲、相机拟合宽高比和最终 JPEG 使用同一个尺寸常量，避免渲染比例与保存比例不一致。
   - JPEG 质量暂时保持 0.75，只降低不必要的分辨率，不牺牲模型材质细节。
2. 模型缩略图缓存键从 `model-library:thumbnails:v26` 升级为 `model-library:thumbnails:v27`。
   - 新键使旧的 288×216 图和历史网格图自然失效，不直接删除用户浏览器中的其他缓存数据。
   - 环境、材质、取景或输出尺寸变化时继续递增版本，禁止复用旧格式。
3. 卡片最终图只走模型 + HDRI + 投影阴影的离屏渲染路径，不调用编辑器地面网格绘制函数。详情编辑器的网格辅助线保持不变。
4. 模型卡片 `<img>` 保留原有懒加载，并增加 `decoding="async"`，让浏览器异步解码缩略图，避免图片解码阻塞卡片列表的主线程。

## 不在本次范围

- 不改变动画库缩略图尺寸或动画关键帧缓存。
- 不改变模型详情页的可视画布分辨率、HDRI、相机取景、投影阴影或编辑器网格。
- 不删除 localStorage 中的旧缓存键；版本隔离即可避免旧图继续显示。

## 验证

- 合同测试确认模型缩略图为 256×192、最长边不超过 256、使用 v27、没有网格绘制调用，并保留投影阴影。
- 页面合同测试确认模型卡片使用 `loading="lazy"` 和 `decoding="async"`。
- 运行模型预览相关测试、客户端 typecheck/build 和 `git diff --check`。
- 在固定的本地 5174 服务中打开模型库，确认卡片图片的自然尺寸不超过 256px、画面不出现编辑器网格、控制台无错误。
