# 模型目录顺序整理设计

## 背景

模型库当前由历史保留条目和后续批次新增条目共同组成。策展脚本会保留输入目录中的条目顺序，因此“全部”视图会先显示早期条目，再显示后来追加的条目；同一主题的模型被拆散，用户需要反复依赖分类页签才能找到相关资产。现有分类页签已经由目录数据驱动，模型 ID、GLB 文件名和模型详情路由也已经稳定。

## 目标

1. 让模型库“全部”视图按既定分类顺序连续展示，先家具，再容器、厨房、日用、办公、装饰、灯具、地面、盆栽、石头、灌木、树木、草、花、户外和卫浴。
2. 保留每个分类内当前已经确认的策展顺序，避免因为这次整理产生额外的语义重排。
3. 保留全部 79 个展示模型、角色资源、稳定 ID、GLB 文件名、贴图和详情路由，不删除或重命名资产。
4. 把排序规则固化在模型目录生成流程中，使后续新增模型不会再次按导入批次插入到错误位置。

## 设计

### 目录生成排序

`scripts/models/curate-cine57-library.mjs` 在保留/移除、名称覆盖和材质覆盖处理完成后，对静态 Cine57 条目进行稳定排序：

1. 读取 `modelLibraryPolicy.mjs` 暴露的 `CINE57_CATEGORY_ORDER`，将有效分类映射为顺序序号。
2. 按分类序号升序排列；同一分类内保留生成前的相对顺序。
3. 非 Cine57 条目不参与静态排序，继续放在静态条目之后；当前角色资源因此继续保留在目录末尾并由模型页过滤。
4. 如果条目使用策略中不存在的分类，生成流程直接报错，而不是把它静默放在末尾。

这样生成结果只改变数组顺序，不改变任何资产的可寻址身份。模型页继续直接消费 `MODEL_LIBRARY`，分类页签和搜索逻辑无需新增状态。

### 质量门禁

在模型库质量测试中增加顺序契约：所有静态条目的分类序号必须非递减，角色资源不能出现在静态条目之间。测试同时保留现有数量、白名单、GLB、材质、视觉复核和使用说明门禁，防止“整理顺序”掩盖资产问题。

### 文档

在模型库 wiki 中记录：分类顺序是模型库的展示顺序单一事实源；分类内顺序由已策展目录的相对顺序决定。该规则属于长期维护约束，不记录为一次性变更清单。由于用户可见的“全部”视图排序会改变，发布说明和 README 最新更新同步记录这一行为。

## 错误处理

- 分类不在 `CINE57_CATEGORY_ORDER` 时生成失败，并报告模型 ID 和分类，防止新资产落入不可预测位置。
- 排序不会删除或重写 GLB、贴图和 ID；资产变更仍由现有策展和备份规则负责。
- 角色资源仍保留在底层目录，以兼容动画和分镜引用，但不会参与模型页展示顺序。

## 验证

- 先增加顺序测试并确认当前未整理目录会失败，证明测试能捕获现有批次顺序问题。
- 运行策展生成流程，再运行模型库完整测试和质量门禁，确认条目数量、资产引用和分类顺序均正确。
- 运行客户端类型检查和构建。
- 使用内置浏览器打开模型库，确认“全部”视图按分类连续排列、分类计数保持不变、代表性模型详情链接仍可用且无控制台错误。

## 非目标

- 不增删模型，不改变模型名称、分类语义、稳定 ID、文件名、贴图或几何。
- 不新增层级分类、拖拽排序或数据库存储。
- 不修改角色资源在动画/分镜流程中的使用方式。
