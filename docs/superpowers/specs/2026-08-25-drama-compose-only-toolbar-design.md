# 漫剧分镜单一合成入口设计

## 背景

分镜页顶部同时放置“生成分镜”“统一写实重生成”“生成配音”和“合成”，占用横向空间，也让“统一写实”看起来像一个独立生产模式。实际通用画风已经在画风管理中统一为写实，分镜页不需要再次提供画风切换或重生成入口。

## 目标

分镜页工具栏只保留一个“合成”按钮。用户可以继续在每一镜下方单独生成或重新生成画面、配音；点击顶部“合成”时，系统先准备当前章节缺失的分镜画面和配音，再启动视频合成。

## 交互设计

- 有分镜时，顶部工具栏只渲染“合成”，不再渲染“生成分镜”“统一写实重生成”或“生成配音”。
- 没有分镜时，空状态仍保留“生成分镜”入口；它负责创建当前章节的分镜结构，不属于顶部批量工具栏。
- 单镜头的“生成画面/生成配音/重新生成”入口继续保留，满足逐镜调试和局部重试。
- 点击“合成”后，只补齐缺失或失败的画面与配音，已有完成素材不重复消耗额度；画面任务与配音任务并发提交。
- 如果当前已有对应的批量任务，复用并等待该任务，不重复创建任务。
- 两类准备任务都进入终态且成功后，自动启动视频合成；任一准备任务失败时停止在准备阶段并提示错误，用户可以再次点击“合成”重试。
- 合成按钮在准备和合成期间禁用并显示加载状态，避免重复点击；所有错误使用现有 toast 反馈。
- 视频页的完整合成设置卡继续保留自己的“合成”按钮，便于用户在视频页重新合成。

## 技术方案

在分镜页增加一个无 UI 的章节素材准备协调器：根据当前镜头状态计算缺失画面，根据音频段状态判断是否需要 TTS，使用 `Promise.all` 并发创建两类批量任务；创建后按任务 id 轮询项目状态，直到任务完成或失败。`useDramaEpisodeAssembly` 接收可选的异步准备回调，在准备成功后才调用既有的整集合成 API，因此视频页原有行为保持不变。

任务等待使用条件轮询而不是固定等待时长，保留有限超时和可读错误。已有批量任务只等待，不再次提交；已完成画面和配音不会进入新任务目标。

## 验证范围

- 纯函数测试覆盖：缺失画面和缺失配音同时提交、已有任务复用、完成后才允许进入合成、失败阻止合成。
- 分镜页面契约测试覆盖：顶部不再出现三个批量按钮，只保留“合成”；空状态和单镜操作仍存在。
- 客户端 typecheck/build 通过。
- 使用浏览器打开分镜页，确认工具栏视觉上只有“合成”，并检查按钮加载/禁用状态的可见文案。
