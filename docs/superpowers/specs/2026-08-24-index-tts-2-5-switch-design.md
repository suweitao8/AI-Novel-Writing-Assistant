# IndexTTS 2.5 本地语音服务切换设计

## 背景

项目当前把音频槽位绑定到 VoxCPM2，并在开发启动链中自动拉起 `18761` 的 OpenAI 兼容桥。用户已提供 `D:\Tools\yzy-index-tts-2.5-260824` 整合包，希望停止 VoxCPM2，改用其中的 IndexTTS 2.5 服务，同时保留项目现有的旁白、角色对白、试听、分镜配音和批量配音入口。

整合包的 `启动.bat` 启动的是 9000 端口的网页工作台；网页的“API 服务”页会管理另一个独立的 FastAPI 进程，监听 9005。该 API 使用 `POST /tts`，返回 WAV 二进制，并要求 `speaker`、`audio`（`voices/` 中的参考音频文件名）和 `text`。

## 目标状态

- 音频模型槽位使用 `indextts25`，默认地址为 `http://127.0.0.1:9005`，默认模型为 `index-tts-2.5`。
- 根目录整栈启动和服务端直启只确保 IndexTTS 2.5 API 就绪，不再启动或依赖 VoxCPM2。
- `启动.bat` 继续作为 IndexTTS 2.5 网页工作台入口；项目启动链管理 9005 API，避免把网页进程误当成合成 API。
- 旁白、角色对白、角色状态音色、全局旁白试听、设置页音频连通测试、分镜配音和批量配音全部经过统一的 `synthesizeAudioSpeech` 出口。
- 参考音频支持 data URL、HTTP(S) 音频地址和本地路径。适配层将其以内容指纹缓存到 IndexTTS 的 `voices/` 目录，并在没有参考音频时使用可配置的默认参考音频。
- IndexTTS API 返回的 WAV 直接转换成项目既有的 data URL，保留现有音频缓存和过期判断，不覆盖数据库中的其他资产。
- 情绪提示优先使用 IndexTTS 的情感描述文本能力；当 API 实例未加载 QwenEmotion 时退回参考音色合成，保证语音请求仍能完成，并在原始结果中保留降级信息。
- 启动器只用 `/health` 的 `status=ok` 判断 API 是否可用，因为 IndexTTS 采用首个请求懒加载模型，不能要求启动阶段 `model_loaded=true`。

## 实现边界

### 供应商与配置

将 `indextts25` 加入共享内置供应商类型，音频槽位、供应商注册表、能力表和环境变量示例统一切换到 IndexTTS 2.5。保留旧 VoxCPM2 配置文件和历史数据，不再把它作为当前音频槽位或开发启动依赖，也不执行数据库删除或重置。

### 协议适配

在 `server/src/services/audio/speechProvider.ts` 保留唯一的音频合成入口，根据当前音频槽位 provider 选择 IndexTTS 协议：

1. 解析/校验 9005 `/health` 与 `/voices` 所需的本地服务配置。
2. 将参考音频内容按 SHA-256 缓存到 `INDEXTTS25_ROOT/voices`，使用安全文件名和音频扩展名。
3. 将角色名映射为 IndexTTS `speaker` 配置（默认 `default`）；角色音色主要由参考音频决定，不把角色名拼进正文。
4. 将文本、语言、语速、情绪描述映射到 `POST /tts` JSON；接收 `audio/wav` 二进制并沿用公共响度处理。
5. 对可选的情感文本能力做能力感知：服务支持时发送 `emo_control_method=3`，不支持时按参考音色模式合成，不因情绪能力缺失阻断普通配音。

### 启动与进程管理

新增 IndexTTS API 幂等启动器，默认使用整合包自带 `.venv\Scripts\python.exe` 执行 `app_api.py --host 127.0.0.1 --port 9005`，日志写入项目本地运行日志目录。根目录和 `server/package.json` 的开发启动命令改为调用该启动器；旧 VoxCPM2 启动器及其专用启动测试删除或替换，防止后续开发流程再次拉起 18761。

### 测试与验证

- 单元测试锁定 IndexTTS 请求字段、参考音频缓存、二进制 WAV 返回、错误透传和降级行为。
- 启动器测试锁定默认路径、健康判定和“懒加载模型也算就绪”的语义。
- 运行服务端构建/测试及工作流测试。
- 启动 9005 API，调用 `/health`、`/voices` 和真实短文本 `POST /tts`，用 WAV 头、采样率和字节长度确认生成结果。
- 检查 9000 网页工作台的克隆配音、API 服务、多角色配音和 SRT 配音页可见，确认 UI 服务仍由 `启动.bat` 提供。
- 最终确认 VoxCPM2 进程和 18761 端口均不存在，IndexTTS API 在 9005 正常监听。

## 风险与处理

- IndexTTS API 的参考音频必须在外部 `voices/` 目录中，适配层只新增或复用指纹文件，不删除用户已有音频。
- 模型首请求可能较慢，沿用音频槽位的长超时；健康检查不触发模型加载，真实合成验证必须单独等待。
- 单卡显存由 IndexTTS 网页工作台自行管理；项目 API 进程不与 9000 网页的克隆配音页同时抢用同一模型，实际试听以 API 页启动的独立进程为准。
- 旧 VoxCPM2 配置不会被删除，但不再被默认槽位读取；如需回退，必须显式恢复代码和启动配置，避免隐式切换。
