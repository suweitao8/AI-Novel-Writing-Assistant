# 角色代理关节对比材质设计

## Background

分镜草图、动画预览和动画缩略图共用 `UAL2_UE_Anims.glb` 的蓝色代理角色。该 GLB 已经把角色主体和关节拆成 `M_Main`、`M_Joints` 两个材质槽，但当前公共材质函数把所有 mesh 都替换成同一个材质，导致动作中的关节轮廓不明显。

## Decision

恢复材质槽语义：主体继续使用调用方提供的角色颜色，关节使用同色系的浅色高亮。蓝色代理角色使用固定的浅蓝关节色；分镜中其他角色颜色则按同一规则从角色主色派生浅色，保持多角色区分。材质函数以原始材质名识别 `M_Joints`，找不到关节槽时回退为单材质，不改变动画、骨骼、保存的角色颜色或模型几何。

## Current Rule

- `M_Main` 使用角色主色。
- `M_Joints` 使用独立的浅色材质，颜色由角色主色经过可预测的提亮规则得到。
- 角色换色和读取已保存颜色时，主体与关节必须同步更新。
- 分镜运行时、动画完整预览和动画缩略图必须通过同一个公共入口获得该效果。
- 关节材质不参与选中描边、阴影或动画状态逻辑；它只负责提高动作结构的可读性。

## Alternatives

1. 使用现有 `M_Joints` 槽（采用）：不增加几何和运行时骨骼计算，兼容现有 GLB，三个使用场景天然一致。
2. 按骨骼权重或法线做 shader 渐变：可覆盖更多资产，但会把材质与骨骼数据耦合，调试和性能成本更高。
3. 叠加额外关节几何：轮廓明显，但会增加资源体积、遮挡和动画同步维护成本。

## Data Flow

角色实例化后，公共材质函数读取每个 render mesh 当前材质的名字，主体 mesh 绑定/更新主材质，`M_Joints` mesh 绑定/更新关节材质。再次调用同一函数进行换色时复用对应材质对象，避免遗留旧颜色。动画播放和缩略图抓帧沿用原有流程。

## Acceptance

- 关节材质单元测试确认主色与关节色不同、蓝色关节色更亮，并能从原始 `M_Joints` 槽识别关节。
- 公共材质调用链测试确认分镜、动画预览和动画缩略图仍使用同一入口。
- 内置浏览器分别查看动画预览和分镜草图，确认关节在站立、弯腰或抬臂等动作中可辨识，控制台无错误。
