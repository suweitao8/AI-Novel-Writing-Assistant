# 漫剧分镜参考图与场景光照一致性设计

## 背景

分镜首帧服务已经能从设定中心解析当前镜头的角色状态图、场景状态图和道具图，并把这些素材写入 `referenceImages` 元数据。但这份元数据只是“计划使用清单”：Provider 目前只取第一张参考图，Codex 图片桥的 JSON 生成入口也不会把 URL 转成附件。因此生成结果可能只有文字提示词，角色外观会漂移，场景光照则由每次随机生成和镜头提示词重新决定。

## 决策

### 1. 参考图必须形成可验证的传输闭环

- 分镜参考图顺序固定为：已确认摆位草图（若有）→ 镜头角色当前状态图 → 镜头地点的初始状态图 → 镜头文本命中的道具状态图。
- `refImages` 中的每一项都必须实际转换为本地临时文件，并以 multipart 的多个 `image` 字段发送到支持参考图的 Provider；不能只发送第一项，也不能把相对 API URL 放进 JSON 后期待桥接器自行读取。
- 已有 `refImagePaths` 仍然支持全部文件路径；Provider 不再使用 `[0]` 截断。临时文件只在请求结束后清理，不改变资产原始文件和不可变制品记录。
- Codex 桥接器接收全部 multipart 文件，并接收与附件顺序对应的参考图标签清单，使模型知道哪一张是角色、哪一张是场景光照锚点。
- 启用参考图且任何参考文件不可读取、下载或上传时，生成必须失败并保留可重试错误；禁止静默降级为无参考的提示词生成。Grok Build 继续通过 Provider 路由切换到 Codex，显式选择不支持参考图的 Provider 时直接报错。
- 现有“角色参考图”开关保留为用户明确的创作选择；默认值和批量任务恢复值均为开启。只有用户明确关闭时才允许无参考生成，不能因旧任务进度缺字段而自动关闭。

### 2. 场景状态图是镜头间的光照锚点

- 对命中的场景，首帧提示词追加一个位于镜头内容之后的场景光照契约：以该场景初始状态图中的光源方向、色温、明暗比例、阴影软硬和空气透视为唯一基准；时间、天气和环境文字只用于解释该基准。
- 角色、道具和时代风格可以改变造型与氛围，但不能为角色单独重新设计主光，也不能覆盖场景状态图的光照关系。
- 除非镜头内容明确出现灯具、火焰、闪电、屏幕等新的画面内光源，否则禁止新增暖黄、冷蓝、血红、霓虹、强逆光、强轮廓光或强体积光等独立照明方案。
- 没有场景状态图时仍生成确定性的时间/天气光照契约，但不伪称存在图像锚点；若参考图开关开启且镜头确实有可用资产图，参考图缺失按参考图失败处理。
- 时代风格判定仍可影响题材氛围，但不能绕过这条场景光照契约。

## 模块边界

- `server/src/services/image/referenceImageFiles.ts`：负责将 URL/data URL/本地路径准备为有序的本地参考文件、校验可读性和请求结束清理；不负责资产归属查询。
- `server/src/services/image/provider.ts`：负责把全部有序参考文件写入 multipart 请求，并把参考图标签传给桥接器；不再构造只含第一张图的 `input_image_url`。
- `server/src/services/image/runtime/runner.ts`：把运行时的参考图元数据传给 Provider，保证展示清单与实际附件顺序一致。
- `server/src/services/drama/visual/sceneLightingContract.ts`：提供纯函数，依据场景状态生成正向光照契约和负向禁区，便于单元测试。
- `server/src/services/drama/visual/DramaShotKeyframeService.ts`：组装场景光照契约，并保持摆位草图、角色、场景、道具的参考图顺序。
- `server/src/services/drama/production/DramaBatchOrchestrator.ts`：修复旧任务进度缺失开关时错误回落为 `false` 的问题。
- `server/src/prompting/prompts/drama/shotKeyframe.prompts.ts` 与注册表：将光照契约作为首帧 Prompt v2 的结构化输入。
- `scripts/codex-image-bridge.cjs`：解析参考图标签字段，并在 Codex agent prompt 中按附件顺序说明用途。

## 非目标

- 不重新生成或覆盖现有角色、场景、道具资产。
- 不迁移数据库、不修改资产制品存储结构、不恢复已丢失的历史生成图。
- 不用固定关键词重写镜头剧情；镜头内容仍由现有结构化分镜数据提供，光照契约只约束资产连续性。
- 不把场景全景图裁切或合成为新的资产；首帧仍由图像模型生成。

## 验收标准

1. Provider 单元测试能证明三个 URL 参考图会生成三个 multipart `image` 文件，顺序与标签一致；没有任何 `[0]` 截断。
2. 参考图下载/读取失败时，Provider 在发起图像生成前抛出可识别错误；不会发起无参考的 `/images/generations` 请求。
3. Codex 桥接器日志和 agent prompt 能看到实际附件数量与标签，而不是只看到持久化元数据。
4. 分镜 Prompt 测试能证明场景光照契约位于镜头内容之后，包含场景状态图锚点说明，并包含禁止独立改光的约束。
5. 批量任务旧进度没有 `useCharacterRefImages` 时恢复为 `true`；显式关闭仍保持关闭。
6. 用现有分镜准备接口检查一个同时含叶晨、叶竹和场景的镜头时，参考图清单为三项；用 Provider 请求捕获测试证明三项都进入 multipart。真实 Codex 配额可用时，再用单镜头生成检查桥接日志的 `refs` 数量和最终图片；配额不可用时至少保留请求捕获证据并明确外部验证缺口。

## 风险与回滚

- Provider 现在会严格暴露参考图不可用问题，旧数据中的失效 URL 可能使任务从“错误成功”变成明确失败；这是预期的安全行为，用户可修复资产后重试。
- 临时下载会增加单次请求的磁盘和网络开销；文件在 `finally` 中清理，失败也不会遗留为项目资产。
- 代码回滚只需回滚本设计对应的提交，不触碰数据库和现有生成图片。
