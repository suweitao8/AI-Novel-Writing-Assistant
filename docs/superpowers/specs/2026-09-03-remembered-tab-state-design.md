# 页签记忆与恢复设计

## 背景

模型库、动画库、小说工作区、剧本工作区、知识库和资产编辑器中存在多处页签或页签式筛选器。它们目前大多由组件内部状态控制，页面离开后会回到默认页签，导致用户重新进入编辑区域时需要再次定位。

## 目标

- 记住用户在每个有页签的工作区域中最后一次有效选择。
- 用户返回同一页面或同一业务对象时恢复该选择。
- 模型库、动画库等全局页面记住分类/筛选页签；项目、小说、章节、角色、世界等编辑页面按对象隔离。
- 已通过 URL 表达的页签仍由 URL 决定，不能被浏览器记忆覆盖。
- 页签值失效、存储不可用或数据损坏时，回退到代码定义的默认值，不影响页面工作。
- 不新增数据库字段，不把临时 UI 状态写入服务端。

## 非目标

- 不记住滚动位置、表单草稿、筛选关键词、分页或编辑内容。
- 不改变现有页签名称、路由语义、权限逻辑或业务数据。
- 不让记忆功能替代 URL 深链接；分享或直接打开的有效 URL 必须保持可复现。

## 方案

### 存储边界

使用浏览器 `localStorage`，统一使用带版本的命名空间：

```text
ai-novel.remembered-tab.v1:<encoded-scope>
```

`scope` 由功能名和稳定业务标识组成，例如：

```text
models:library-category
animations:library-category
drama-project:<projectId>:main-stage
novel:<novelId>:story-settings
character:<characterId>:workspace
world:<worldId>:workspace
```

存储层只保存字符串页签值，读写都捕获浏览器存储异常。它不依赖用户身份，也不保存作品正文、提示词或资产数据。

### 统一 Hook 契约

新增通用页签 Hook，调用方提供：

- 稳定 `storageKey`/scope；
- 默认值；
- 当前功能允许的页签值集合。

Hook 负责读取并校验持久化值、在页签切换时同步写入，以及在浏览器存储事件触发时同步其他同源页面。调用方仍然拥有业务状态，Hook 不跨模块推断页签含义。

对于 URL 驱动的页签提供配套 Hook：

1. 有效 query 参数存在时，使用 URL 值并将它记住。
2. 没有 query 参数时，使用该页面/对象上一次有效记忆；必要时以 `replace` 方式补齐 URL，保证刷新和返回结果一致。
3. query 参数无效时使用默认值，并清理或规范化无效参数。
4. 写入 query 时保留其他 query 参数。

### 优先级

恢复顺序固定为：

```text
有效 URL 页签 > 当前业务对象的已记忆页签 > 功能默认页签
```

切换页签会同时更新业务现有状态、URL（如果该页面使用 URL）和记忆值。对象标识变化时必须重新读取对应 scope，不能沿用上一个对象的内存状态。

### 接入范围

第一批覆盖所有稳定的用户工作页签：

- 模型库、动画库的分类页签；
- 剧情项目主工作区与设置页签；
- 知识库、世界工作区、标题工作区、短篇工作区和简单创作工作区；
- 设置页的模块页签/路由页签；
- 小说编辑中的故事设定、章节管理、提纲、章节洞察、角色资产和世界手册页签；
- 书籍分析主视图及其稳定的详情视图；
- Prompt 工作台的编辑/预览页签；
- 创作对话框和资产预览中会被用户反复切换、且有稳定语义的页签式视图。

临时状态机、一次性弹窗中的内部步骤或没有稳定业务边界的按钮组不强行持久化；如果同一组件同时用于全局页和对象页，调用方必须显式传入不同 scope。

### UI 与兼容性

- 复用现有 Tabs、PageTabs 和项目 UI token，不改变视觉体系。
- 保留现有键盘操作、ARIA 属性、激活样式和导航回调。
- 恢复过程不增加用户可见提示；存储失败静默降级到默认行为。
- 所有持久化值都必须经过允许值校验，防止旧版本值或手工修改值让内容区为空。

## 验证策略

### 代码级验证

- 存储读写、异常降级、无效值回退、对象 scope 隔离的单元测试。
- URL 页签优先级、query 保留和对象切换的 Hook 测试。
- 受影响客户端的类型检查和现有聚焦测试。

### 浏览器冒烟

在当前 worktree 的独立开发端口中，使用内置浏览器验证：

1. 模型库选择“花”或其他非默认分类，切换页面再返回，仍恢复该分类。
2. 动画库重复验证分类恢复，并确认模型库与动画库互不串值。
3. 项目/小说对象 A 与对象 B 分别选择不同页签，来回切换后各自恢复。
4. 直接打开带有效页签参数的 URL，确认 URL 选择优先。
5. 刷新页面并检查内容、ARIA 激活状态、导航与控制台错误。

## 迁移与回滚

旧用户没有记忆值时直接使用原默认页签，不需要数据迁移。删除 `v1` 命名空间即可清空本地页签记忆，不影响服务端数据。若某个页面接入出现问题，可移除该页面 scope 的调用而不影响其他页签。

## 自审结论

该设计只引入前端浏览器侧的可恢复 UI 偏好，不改变数据库和业务 API；scope、有效值校验和 URL 优先级覆盖了跨页面串值、旧值失效及深链接被覆盖的主要风险。
