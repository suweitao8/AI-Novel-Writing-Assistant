# 模型导入前景准入与历史台账设计

## 背景

Cine57 模型库目前已经有 GLB、材质、尺寸和详情页预览门禁，但这些门禁主要在产物写入目录后运行。这样会带来两个问题：没有前景使用价值的碎屑、草丛和极小模型仍会先经过转换并进入目录；同一个已经确认不可用的源模型下次导入时也会被重复处理。截图中出现的“积尘碎屑堆”“碎石瓦砾堆”和草类卡片就是当前策展规则没有覆盖产品用途和可见尺寸的结果。

现有 `%TEMP%/fbx2gltf-test/build-library-v3.cjs` 是历史性的外部构建器，直接写入主工作区的 public 目录，并且没有导入历史或发布前详情预览步骤。它不能继续作为唯一的发布入口；仓库需要拥有可复核的准入和发布边界，外部转换器只能提供候选产物。

## 目标

1. 只让有明确前景使用价值、尺寸可见且能通过真实详情页预览的模型进入可用目录。
2. 在转换/导出前根据显式策展规则和历史台账跳过已确认不可用且源指纹未变化的模型。
3. 对每个处理过的模型记录稳定资产键、源指纹、处理结论、失败阶段、原因、证据和重审条件。
4. 预览必须在发布前生成；方形详情预览出现缺图、空场景、破碎、材质异常、请求失败或控制台错误时，候选停留在待处理/隔离区，不能写入发布目录。
5. 当前已确认不适合前景的产物从模型目录中移出，但保持可恢复，不删除 Cine57 原始导出。

## 非目标

- 不用关键词正则替代视觉和用途判断，也不因为模型属于“草”“石头”等类别就全部删除；确定的拒绝项必须是显式资产 ID 或 Mesh 名清单。
- 不修改 PlayCanvas 详情页的相机、光照、缩略图分页或场景摆放逻辑。
- 不改动 Unreal 工程、用户数据库或主工作区运行服务。
- 不把模型导入历史当作不可推翻的黑名单；源指纹变化或人工重开审查时允许重新处理。

## 方案

### 1. 单一前景准入策略

在 `model-library-selection.json` 增加 `foregroundAdmission`：

- `minimumDimensionMeters: 0.1`：按 GLB 节点变换后的世界空间 POSITION 包围盒最大轴判断，低于 10 厘米默认拒绝；以后确需保留的叙事小道具必须通过显式例外清单，而不是降低全局阈值。
- `maximumDimensionMeters: 5`：保留现有 5 米上限。
- `rejectedAssets`：按稳定 ID/Mesh 写入 `ground-scatter`、`foliage-scatter`、`scene-component`、`broken-preview` 等原因码、中文原因和证据日期。
- 策略只记录确定结论；候选的实际几何、贴图和预览仍由准入模块逐项检查。

当前第一批明确移出模型库的对象包括截图中的积尘/碎石/瓦砾碎屑以及已确认出现问题的草类；尺寸门禁同时处理最大轴小于 0.1 米的条目。保留源 GLB 的方式由现有可恢复隔离清单承接，发布目录只保留通过准入的条目。

### 2. 导入历史台账

新增 `scripts/models/model-library-import-history.json`，以记录数组保存每个源模型最近一次结论，并在该记录内保存处理事件：

```text
assetKey = normalizedPackagePath + "#" + meshName
sourceFingerprint = sha256(canonical source row)
status = approved | rejected | skipped
failureStage = semantic | geometry | texture | conversion | preview | publication
reasonCode / summary / evidence / reviewedAt
recheckPolicy = source-change-or-manual-reopen
```

资产键必须由规范化 `/Game/...` 包路径和 Mesh 名组成，不能只用展示名或文件名。源指纹来自稳定的 manifest 字段（包括源 FBX/GLB 指纹时一并纳入），忽略导入时间等易变字段。候选选择器先查台账：

- 已拒绝且指纹相同、记录要求跳过：返回 `previously-rejected`，不进入 FBX→GLB、贴图转换或预览队列。
- 指纹变化：返回可重新审查，保留旧事件并新增本次事件。
- 已批准：只有在准入/发布流程明确要求更新时才重审，不把“批准”误当成永远跳过。

台账不是页面过滤器；它是导入流程的资源节省和可追溯边界。未知模型没有历史记录时必须走完整准入流程。

### 3. 预检、暂存和发布

仓库新增模型导入工作流门面，分成三个明确阶段：

1. `preflight`：解析 manifest，应用来源、技术变体、显式策展和历史跳过规则，输出 accepted/rejected/skipped 计划；不会触碰发布目录。
2. `stage`：只对 accepted 候选完成转换、GLB 清洗、贴图回填和目录草稿，所有文件位于本次 run 的暂存目录。
3. `publish`：先在工作区真实 `/models/<id>` 详情路由生成方形预览，收集当前 GLB/贴图指纹、画布/几何状态、请求和控制台证据；只有所有候选通过结构、材质、尺寸和预览门禁，才把暂存产物和目录提交到发布目录，并把 approved 事件写入台账。失败项写入 rejected 事件并留在可恢复隔离区。

`curate-cine57-library.mjs --check` 继续作为最终只读总门禁；它必须同时检查前景准入规则、导入历史格式、导入审计和浏览器详情预览。历史性的外部 `build-library-v3.cjs` 不再直接决定发布，只能作为转换器被新门面包住。

### 4. 当前库清理

当前工作区执行“从目录撤出、产物可恢复”的清理：

- 从 `modelLibrary.ts` 移出显式拒绝资产；不从截图或文件名推断新的宽泛删除范围。
- 采用仓库外可恢复隔离或已有 `quarantinedAssets` 精确记录保留 GLB；不执行无备份的 `unlink`。
- 重新生成剩余目录的预览审计和语义复核，确保审计覆盖集合与新目录完全一致。
- 对现有模型按尺寸和详情页预览证据补写台账，后续重复导入先命中台账。

## 验收标准

- 选择器测试证明：同一资产同一源指纹的 rejected 记录会在转换前返回 `previously-rejected`；源指纹变化会重新进入候选；显式碎屑/草策略会拒绝，普通名称不会被模糊正则误杀。
- 准入测试证明：尺寸 `<0.1m` 或 `>5m`、缺少预览、非方形截图、预览请求/控制台错误和材质异常均不能发布；边界值 `0.1m`、`5m` 可通过后续门禁。
- 当前目录不再发布第一批明确拒绝的碎屑/草/极小模型，剩余目录数量、分类、GLB、贴图、导入审计和预览审计一致。
- `pnpm test:model-library`、`pnpm check:model-library`、客户端检查通过；工作区 lane 的模型列表和代表性详情页在内置浏览器中可打开，方形预览无新增 console/network 错误。
- 台账、策略和质量门禁均能解释某个模型“为什么导入/为什么跳过/为什么拒绝”，且拒绝产物可按证据恢复。

## 长期规则

今后模型导入必须遵循：候选先预检，已确认坏模型按稳定资产键和未变化源指纹跳过，转换产物只进暂存区，真实方形详情预览和完整质量门禁通过后才发布。任何新增拒绝结论都必须同时写入策展策略和历史台账，避免同一问题在下一批导入时再次消耗转换和预览资源。
