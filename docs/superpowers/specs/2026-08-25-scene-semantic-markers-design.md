# 场景状态 3D 空间语义标记设计

## 背景

场景状态图是 360° 等距柱状全景，当前 3D 场景编辑器只显示 HDRI 环境和比例参照角色。进入分镜 3D 草图后，用户能摆放角色，却看不到床、桌、椅、门窗等固定空间物体，角色位置只能凭感觉，容易与场景结构冲突。

## 目标

- 在场景资产的某一个状态图上，通过注册的多模态结构化 AI 识别主要固定空间物体。
- 将识别结果保存为该场景状态专属的 3D 半透明长方体标记，包含名称、类别、尺寸、位置、朝向、置信度和图像证据区域。
- 在场景 3D 编辑器中显示这些标记，并允许通过标记列表定位到对应物体。
- 分镜 3D 草图复用当前镜头所选场景状态的标记；角色自动构图的 AI 上下文也必须收到这些标记，从而能把角色放在床边、桌旁或椅子前，而不是把坐标当成与场景无关的随机值。
- 场景状态图重新生成后，旧标记不能继续伪装成新图片的空间事实；图片制品提交时清除旧标记，用户需要重新识别。
- 识别失败时保留已有图片和旧标记，不覆盖可用状态；接口返回明确错误，用户可重试。

## 非目标

- 不把标记当成最终场景模型，也不承诺从单张全景图恢复精确 BIM/碰撞网格。
- 不用固定关键词或坐标表猜测床、桌、椅的位置；空间识别由注册的视觉 Prompt 完成，服务端只做结构校验、范围裁剪和确定性渲染。
- 首期不保存家具的真实 3D 网格，不改变场景 HDRI 投影算法，也不把标记写入分镜 `layout3d`；标记属于场景状态，镜头只读取它。

## 数据边界

`StoryAssetState.scene3dMarkers` 随场景状态的 `statesJson` 保存，而不是写入场景顶层 `scene3dEnvironmentJson`。这是因为同一场景的白天、夜晚、损坏等状态可能使用不同全景图，标记必须跟随图片状态。现有状态 JSON 的乐观 CAS 写入链路继续作为唯一写入入口，避免资产表单、图片生成和 AI 识别互相覆盖。

标记集合包含：

- `schemaVersion: 1`、`status`、`analyzedAt`；
- `sourceImageArtifactId` 与 `sourceImageGeneratedAt`，证明标记对应哪一个不可变状态图片制品；
- `markers[]`：`id`、`kind`、`label`、`anchor`、`position`、`size`、`yawDeg`、`confidence`、`imageRegion`、`evidence`。

坐标约定与现有 PlayCanvas 场景一致：地面为 `y=0`，`+Z` 是全景图正前方，`+X` 是右侧，单位按约 1.8 米比例参照角色估算。`position` 是长方体中心，地面锚点由服务端把中心高度归一到 `size.y / 2`；所有值限制在当前半球可视范围内。标记是估算值，置信度必须可见，不能以精确测量的口吻呈现。

## AI 合同

新增 `drama.scene.state.3d_markers@v1` PromptAsset，输入包含场景名、状态名、场景类型、投射中心/半球直径和当前状态图。输出只包含固定空间物体，不包含人物、动物、临时物件或画面内容中的文字；室内场景优先识别床、桌、椅、沙发、柜、门窗等与角色摆位相关的物体，室外/自然场景可以返回空数组。

Prompt 直接要求模型输出大致的世界坐标和尺寸，同时保留归一化全景图证据框。服务端不根据中文名称二次猜测类别，也不使用名称决定坐标；只负责生成稳定标记 id、裁剪数值、让地面物体落地和拒绝非法结构。

## 运行链路

```text
场景状态图片
  └─ 场景 3D 编辑器「识别空间标记」
       └─ 读取当前不可变图片制品
            └─ 多模态结构化 Prompt
                 └─ 校验/裁剪/写回当前 state（CAS）
                      ├─ 场景 3D 编辑器：半透明长方体 + 标记列表
                      └─ 分镜 3D 编辑器：继承同一组标记
                           └─ 自动构图 Prompt 收到标记
                                └─ 角色摆位参考家具空间关系
```

图片重新生成的最终制品提交和场景标记写入使用同一份状态 CAS 合同：成功换图时清除 `scene3dMarkers`；中间生成态、失败态和取消态不删除仍可用的旧标记。资产表单保存只保留当前数据库中的标记，不能因旧页面快照把它清空。

## 交互

- 场景 3D 编辑器提供明确的 AI 操作按钮：无标记时显示“识别空间标记”，已有标记时显示“重新识别”。按钮有加载、失败 Toast 和成功数量反馈。
- 右侧列表显示物体名称、类别和置信度；点击列表项会选中并聚焦对应半透明长方体。视口中用不同语义颜色和轮廓区分标记，角色仍使用原有选择逻辑。
- 分镜 3D 编辑器显示“场景空间标记”列表，点击后聚焦标记；标记不进入角色布局保存 JSON，也不会在退出保存时被镜头私有数据覆盖。
- 没有识别结果时保持现有 3D 视口，不绘制虚构家具；识别为空是合法结果，表示当前图没有可可靠识别的固定物体。

## 兼容与失败处理

- 旧状态没有 `scene3dMarkers` 时正常读取，视为尚未识别。
- 旧场景图片或缺失图片不能发起识别；识别接口返回可操作错误，不写入空结果。
- AI 输出缺少字段、越界、重复结构或无法读取图片时，拒绝整批写入并保留上一次有效标记。
- 场景标记只作为空间参考，不改变已有 3D 草图的旧角色/相机快照；已有分镜继续可打开。

## 验证

- 共享类型/服务端单测：标记 schema、坐标/尺寸范围、地面归一化、旧状态兼容和图片重生成清除边界。
- Prompt 合同测试：已注册、多模态消息、只输出固定空间物体、结构化结果字段。
- API/服务测试：读取当前状态图片、CAS 写入、失败保留、上下文向分镜传递标记、自动构图 Prompt 收到标记。
- 客户端契约测试：场景页识别按钮、两个 3D 页面将标记传入 viewer、viewer 透明盒/选择/聚焦渲染。
- 运行 shared/server/client 定向 typecheck 和测试；最后运行仓库集成检查。真实浏览器中的模型识别效果仍需用户在当前场景状态图上点击识别后验收。
