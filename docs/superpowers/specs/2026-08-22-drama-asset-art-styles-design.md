# 漫剧三类资产画风管理设计

**日期：** 2026-08-22  
**状态：** 已完成需求确认，待文档审阅后实现

## 1. 背景

当前系统把角色、场景、道具共用的渲染提示词称为“通用画风”。它虽然会被多条生图链路复用，但默认内容混入了皮肤、发丝、五官、年龄、性别和人体结构等角色语义，导致场景和道具也受到角色化提示词影响。

同时，角色、场景、道具的参考资产形式本来就不同：角色需要四视图，场景需要完整空间的 360° 全景，道具需要单件物体的 45° 透视图。三类资产不应该继续共用一份可编辑画风提示词。

## 2. 目标

1. 把画风配置拆成角色、场景、道具三项独立配置。
2. 让页面明确展示三类资产的固定生成规格：角色四视图、场景 360° 全景、道具 45° 透视。
3. 用户只编辑每类资产的正向画风提示词；视图格式和负面约束由系统固定，防止自定义内容破坏资产契约。
4. 角色、场景、道具的资产图和状态图严格使用各自画风。
5. 分镜首帧只叠加本镜实际出现的资产类型对应画风，同时保持小说级时代/题材风格作为独立叠加层。
6. 移除“通用画风”作为产品概念，把它改为系统设置侧栏中的独立“画风管理”页面。

## 3. 非目标

- 不改变小说内“时代/题材风格”的选择、脚本切换和优先级。
- 不允许用户编辑角色、场景、道具的固定视图结构或固定负面约束。
- 不把三类画风配置扩展成新的提示词编辑工作台。
- 不删除数据库中已经存在的 `drama.universalArtStyle` 记录；旧值只保留，不再注入新的生成链。

## 4. 方案决策

采用一个系统级 JSON 配置对象承载三类可编辑提示词，而不是三个独立数据库字段或新增数据库表。

```text
AppSetting.key = drama.assetArtStyles
AppSetting.value = {
  "characterPrompt": "",
  "scenePrompt": "",
  "propPrompt": ""
}
```

空字符串表示该类资产使用代码内置默认提示词。每类资产的固定规格、固定负面约束、标签和默认提示词由 `dramaVisualStyles.ts` 的类型化常量提供，数据库只保存用户自定义的正向提示词。

旧的 `drama.universalArtStyle` 记录不复制到三类配置中。这样可以避免旧文本中的角色属性污染场景和道具；保留旧记录也不会造成数据删除。新的页面首次打开时显示三类干净默认内容，首次保存时创建 `drama.assetArtStyles`。

## 5. 页面设计

### 5.1 入口

保留现有系统设置路由 `/settings/art-style` 以避免旧链接失效，但页面标题和系统设置侧栏标签改为“画风管理”。它与“模型设置”“自动导演”“知识库与写法”“外观与主题”同级，不再显示“通用画风”。

小说内的“设定 · 美术风格”仍然负责本书的时代/题材层，只在需要修改系统三类资产规范时链接到“画风管理”。

### 5.2 页面布局

页面采用一页三卡的布局：

```text
画风管理
为角色、场景、道具分别维护生图画风规范。

┌──────────────┬──────────────┬──────────────┐
│ 角色画风      │ 场景画风      │ 道具画风      │
│ 四视图        │ 360° 全景     │ 45° 透视      │
│ 固定规格      │ 固定规格      │ 固定规格      │
│ 正向画风提示词 │ 正向画风提示词 │ 正向画风提示词 │
│ 保存/恢复默认  │ 保存/恢复默认  │ 保存/恢复默认  │
└──────────────┴──────────────┴──────────────┘
```

每张卡包含：

- 资产类型标题和固定输出规格；
- 只读的固定系统约束摘要；
- 一个正向画风提示词文本框；
- 独立的“保存”和“恢复默认”按钮；
- 读取中、保存中、保存成功、保存失败状态。

保存一个卡片时只更新对应的配置项，不覆盖另外两张卡的并发编辑。

### 5.3 固定资产规格

#### 角色画风

- 输出：横版角色设计参考图。
- 单张图包含四个视图：头部正面、头部侧面、正面全身、背面全身。
- 四个视图保持同一角色身份、服装、比例和外观状态一致。
- 角色专属负面约束可以包含人体结构错误、多肢、多手、视图缺失、视图互相不一致等内容。

#### 场景画风

- 输出：横版 360° 全景参考图。
- 完整覆盖空间前方、两侧、后方和地平线，保持连续的空间拼接。
- 以环境和建筑为主体，禁止把人物作为主体；需要时只允许极小的背景人物。
- 场景专属负面约束包含空间断裂、地平线不连续、文字、水印和主体人物等内容，不包含人体结构词。

#### 道具画风

- 输出：横版单件道具 45° 三点透视参考图。
- 单个物体居中展示，清晰呈现轮廓、材质、纹理和颜色，使用中性背景。
- 道具专属负面约束包含多件物体、手、人物、文字和水印等内容，不包含角色或场景专属约束。

### 5.4 内置正向画风

三类内置正向画风都只描述各自资产的渲染质感，不写时代、剧情、角色身份或具体资产内容：

- 角色：写实 3D 电影质感、角色材质细节、电影级光照、自然色彩和统一视图成片质量；
- 场景：写实 3D 环境质感、建筑与空间材质、连续光照、自然色彩和完整全景成片质量；
- 道具：写实 3D 物体质感、表面纹理、边缘细节、材质反射和单件参考图成片质量。

用户自定义提示词可以改变对应类别的渲染审美，但不能改变该类别的固定视图结构、画幅或负面约束。

## 6. 生成链设计

### 6.1 画风上下文

将现有 `ResolvedDramaArtStyle.universal` 改为三类资产风格集合：

```ts
type DramaAssetStyleKind = "character" | "scene" | "prop";

interface ResolvedDramaArtStyle {
  assets: Record<DramaAssetStyleKind, DramaAssetVisualStyle>;
  specific: DramaSpecificStyle | null;
}
```

每个 `DramaAssetVisualStyle` 包含：

- `kind`、`label`、`summary`；
- `formatInstructions`：系统固定的视图和输出格式；
- `styleInstructions`：默认值或用户自定义的正向画风；
- `avoidInstructions`：系统固定的资产类型负面约束；
- `styleTag`：用于强化模型识别的固定短标签。

用户自定义提示词只替换对应资产的 `styleInstructions`，不能覆盖 `formatInstructions`、`avoidInstructions` 或 `styleTag`。

### 6.2 角色、场景、道具资产图

- `DramaCharacterImageService` 使用 `assets.character`，并把角色四视图固定指令放在用户画风之前或之后的系统段落中。
- `StoryAssetImageService.generateSceneImage` 使用 `assets.scene`，保留 360° 全景构图和横版规格。
- `StoryAssetImageService.generatePropImage` 使用 `assets.prop`，保留 45° 三点透视、单物体和横版规格。
- 三类状态图 `StoryAssetStateImageService` 根据 `kind` 选择对应资产风格，状态变化描述和继承参考图规则保持不变。
- 状态图同样遵守所属资产的固定视图规格，不能通过状态提示词改成另一种资产形式。

### 6.3 分镜首帧

分镜首帧使用同一个已解析的三类风格集合，但只注入实际出现的类型：

- 有被分镜引用的角色时，注入角色正向画风和角色负面约束；
- 有地点时，注入场景正向画风和场景负面约束；
- 镜头文本匹配到设定道具时，注入道具正向画风和道具负面约束；
- 未出现的资产类型不注入；
- 首帧自身的竖屏 9:16、构图、运镜和图生视频第一帧规范保持固定，不把四视图、360° 全景或 45° 透视格式带入首帧；
- 小说时代/题材风格仍然作为独立层叠加在资产画风之后。

这样既能让首帧沿用角色、场景和道具的一致性，又不会把“角色四视图”错误地要求在分镜首帧中生成。

## 7. 接口与兼容

新增接口：

```text
GET /api/settings/drama-asset-styles
PUT /api/settings/drama-asset-styles/:kind
```

其中 `kind` 只能是 `character`、`scene`、`prop`，PUT 请求体为：

```json
{ "prompt": "用户填写的正向画风提示词" }
```

GET 返回三类的当前提示词、默认提示词、固定规格摘要和固定约束摘要，供页面展示；PUT 只更新对应类别，最大长度保持 2000 字符，空字符串恢复默认。

客户端 API、React Query key 和小说内 `ArtStylePanel` 都切换到三类画风接口。小说侧只展示“三类资产画风规范”的入口摘要，不展示完整系统提示词。

旧的 `/api/settings/universal-art-style` 路由和客户端方法一并移除；数据库中的 `drama.universalArtStyle` 记录只作为保留的历史数据，不再被任何页面、解析器或生成服务读取。

## 8. 错误和状态处理

- GET 失败：页面显示统一读取失败状态，并提供重试入口，不渲染空白卡片。
- 单卡 PUT 失败：只标记当前卡片失败，其他两卡保持可编辑；错误通过项目 `toast.error` 展示可读描述。
- 保存中：当前卡片的保存/恢复默认按钮禁用并显示“保存中…”，其他卡片不被阻塞。
- 恢复默认：向对应 `kind` 提交空字符串，成功后立即把该卡片切回内置默认内容。
- 不接受未知 `kind`、非字符串或超过 2000 字符的提示词。
- 生成链读取到损坏的 JSON 时，回落到三类内置默认，不影响小说时代/题材风格解析。

## 9. 测试和验收

### 服务端测试

更新 `server/tests/dramaArtStyle.test.js` 并补充设置契约测试，覆盖：

1. 三类默认配置存在且标签、固定规格不同。
2. 角色默认负面约束不会出现在场景和道具配置中。
3. 自定义角色提示词只替换角色正向提示词，固定视图、标签和负面约束仍然存在。
4. 场景和道具资产生成分别使用对应配置，不会串用角色提示词。
5. 状态图按 `kind` 使用对应配置。
6. 分镜含角色、场景、道具时三类都注入；缺少某类时该类不注入。
7. 损坏或缺失的新配置回落默认；旧 `drama.universalArtStyle` 不进入新解析结果。

### 客户端检查

- 运行客户端 TypeScript 检查。
- 检查三张卡的保存、恢复默认、加载中、错误状态代码路径。
- 检查 `/settings/art-style` 仍可打开，但页面文案不再出现“通用画风”。

### 用户验收

- 系统设置侧栏看到“画风管理”同级入口。
- 页面一屏看到角色、场景、道具三张卡。
- 三张卡分别显示四视图、360° 全景、45° 透视规格。
- 修改一张卡后，另外两张卡内容不变。
- 生成角色、场景、道具资产及状态图时分别使用正确画风。
- 分镜首帧只使用实际出现的资产类型画风。
