# 现代日常前景模型库扩容设计

## 背景

当前模型页展示 79 个 Cine57 前景模型，另有 1 个角色资源不参与静态模型选择。Cine57-exported3 已经保存了 466 个静态网格候选，主要来自现代住宅、办公室、厨房、卫浴、电子设备和餐饮场景。现有模型库已经覆盖床、桌椅、少量厨房和装饰，但日常使用频率高的柜体、家电、电脑、电视、卫浴、灯具、收纳和办公用品仍然不足，导致模型选择更像道具样例目录，而不是可支撑现代小说场景的前景资产库。

候选中同时包含完整可摆放对象、同系列 LP/NN 变体、门板/抽屉/柜底等零件、建筑模块和场景组装碎片。若直接把 466 个候选全部导入，目录会出现重复、不可独立摆放或风格不一致的资源，也会把低质量资源带入后续创作流程。因此本次扩容仍采用同源资产的精选策略，但把精选范围明显扩大到现代日常使用场景。

## 目标

1. 将模型页的静态前景模型从当前 79 个扩充到约 180–220 个；新增目标约 100–140 个，最终数量由真实 GLB、材质和浏览器复核决定，不为凑数发布不完整资产。
2. 新增资产按优先级覆盖现代室内高频对象：家具和收纳、厨房电器与餐具、办公和电子设备、卫浴与洗衣、灯具、日常容器，以及少量可用于现代室外场景的完整物件。
3. 保持统一视觉来源：新增资产优先来自 Cine57 的现代住宅/办公室/厨房/电子/卫浴包；同一模型族优先选择一个主版本，只有外观或用途确实不同且通过截图复核时才保留多个版本。
4. 保留现有稳定模型 ID、GLB 文件名、贴图和用户可用路径；本次是可追踪的增量扩容，不删除现有模型，不改用户数据库。
5. 让“现代日常”成为选择和命名的硬边界：不新增古典/复古装饰、纯摆件、背景板、建筑构件、碰撞体、LOD 变体或只能作为零件使用的网格来填数量。

## 推荐的内容配比

目标不是给每个分类强行凑同样数量，而是把用户最常用的前景对象放在前面。候选筛选完成后，预期新增配比如下，实际以质量门禁通过结果为准：

| 优先级 | 资产方向 | 预期新增 | 典型对象 |
| --- | --- | ---: | --- |
| P0 | 家具与收纳 | 25–35 | 沙发/床型、办公桌椅、书架、文件柜、衣柜、餐边柜、置物架、推车 |
| P0 | 厨房与餐饮 | 20–30 | 冰柜/冷藏设备、咖啡机、榨汁机、微波炉、锅具、餐具、厨房容器、餐饮设备 |
| P0 | 办公与电子 | 18–25 | 电脑、显示器、键盘、鼠标、电视、打印机、白板、文件与办公用品 |
| P0 | 卫浴与洗衣 | 12–18 | 浴缸、马桶、淋浴、镜子、水槽、毛巾、洗衣篮、烘干机、洗涤用品 |
| P1 | 灯具与日常小物 | 10–16 | 台灯、吊灯、壁灯、瓶罐、垃圾桶、篮筐、时钟、实用小物 |
| P1 | 现代户外与工具 | 8–14 | 保温箱、露营烤架、背包、望远镜、工具箱等完整可摆放对象 |
| P2 | 装饰与自然补充 | 5–10 | 仅保留能支撑现代室内构图的少量花器、植物或完整装饰对象 |

自然资产和装饰资产不再是扩容主力；它们只有在现代场景有明确使用价值、尺寸合适、材质完整时才进入新增清单。

## 资产策展规则

### 来源与版本

- 只使用本机 Cine57 已导出的 manifest 和贴图，不引入未经许可或无法复现来源的外部模型。
- 现代住宅、办公室、厨房、卫浴和电子包优先；`Antique`、复古酒吧装饰、纯中式装饰等候选不作为新增主线。
- LP 与 NN 是同一资产族的技术/版本变体时只保留通过视觉复核的主版本；只有几何和用途明显不同才允许同时发布。
- 同一完整模型族最多保留 1–3 个有明确用途差异的版本，禁止用编号变体填充目录。

### 完整可摆放对象

候选必须是可以作为一个前景对象独立放置、具有完整外形和可理解用途的静态网格。以下类型直接排除：

- 门、抽屉、柜底、柜门、台面、层板、支腿、把手、连接件、铰链、线缆、零件和单独材质片；
- 建筑墙体、隔断、背景板、地面大块、模块化场景构件和需要多个网格才能组成的半成品；
- `UCX`/`UBX` 碰撞体、`LOD1+` 高阶 LOD、无可见几何的节点，以及超过前景尺寸上限的场景级模型；
- 只适合古典、复古或与现代同源主线明显冲突的新增装饰；
- 与已发布模型用途相同、外观只改变编号或材质颜色的重复变体。

### 分类与命名

- 继续使用模型页现有的平面分类页签，不新增层级分类 UI；分类顺序仍由 `CINE57_CATEGORY_ORDER` 统一驱动。
- 新增对象只能进入现有类别：家具、容器与箱子、厨房与餐具、日用小物、书籍与办公、玩具/装饰品、灯具、地面、盆栽、石头、灌木、树木、草、花、户外、卫浴。
- 展示名以截图中用户能直接理解的中文用途为准，不直接把英文网格名翻译成产品名。无法从标准缩略图和详情页确认语义的候选不得发布。
- 保持食材/纸箱族的现有配额约束；本轮新增容器优先选择篮筐、垃圾桶、瓶罐、保温箱等不同用途对象，不扩张近似纸箱。

## 实现与数据流

资产选择以 `scripts/models/model-library-selection.json` 为单一策略入口，新增条目记录源 mesh、稳定 ID、展示名、分类、包路径和来源批次。历史构建器只负责从 Cine57 manifest 转换被选候选，不能把整个 manifest 自动发布到目录。

```text
Cine57-exported3 manifest (466)
        │
        ├─ 现代日常候选筛选：完整对象、同源风格、族配额
        ├─ FBX → GLB + 材质贴图回填
        ├─ GLB 双层清洗：node/mesh 剔除 UCX、UBX、LOD1+
        ├─ 标准缩略图截图语义复核：名称/分类/可用性
        ├─ 详情页真实预览：透明材质、阴影、贴图和资源哈希
        └─ modelLibrary.ts 再生 → 质量门禁 → 模型页
```

需要保留现有目录生成与质量门禁的职责边界：构建产物 `modelLibrary.ts` 不手工追加条目；`model-library-visual-review.json` 记录每个发布模型的截图语义和审核状态；`modelLibraryQuality.mjs` 负责引用、尺寸、材质、GLB 结构、使用说明和视觉复核的可重复验证。

模型或材质生成规则改变时同步递增模型缩略图缓存版本；动画缩略图继续复用同一套模型环境和材质规则。用户主动保存的动画关键帧是显式覆盖，不因自动缩略图刷新被删除或替换。

## 失败处理与回滚

- 任何会删除或重写 `client/public/models/cine57` 内容的构建前，先把当前模型目录、贴图目录和 `modelLibrary.ts` 复制到带时间戳的本地备份目录，并检查文件数、GLB 数量、贴图数量和总字节数。
- 候选缺少 FBX、材质引用、可解析 GLB、完整包围盒或标准截图复核时，进入仓库外隔离目录或保留在源导出目录，不写入发布目录。
- 质量门禁发现单个新增资产问题时，只淘汰该候选并记录原因，不降低全局门槛、不用运行时隐藏或分类过滤掩盖问题。
- 构建中断或门禁失败时保持 worktree 未提交，并使用备份恢复应用目录；不修改 Unreal 源工程、不操作用户数据库。

## 验证

1. 先增加失败测试，证明当前模型目录不能满足本轮的最低数量、现代日常类别覆盖、候选白名单和零件/重复族约束。
2. 运行选型策略、GLB 清洗、真实材质贴图和目录门禁，确认新增条目全部有文件、材质、使用说明和视觉复核记录，所有 GLB 没有悬空引用、碰撞体或高阶 LOD，尺寸不超过 5 米。
3. 运行 `pnpm test:model-library`、`pnpm check:model-library`、客户端 typecheck 和 build。
4. 用 Codex 内置浏览器检查模型库总数和全部分类页签；至少打开家具、厨房、办公/电子、卫浴、灯具、容器和户外代表模型的详情页，确认缩略图、GLB、贴图、光照和阴影正常且无 console/network error。
5. 最终检查新增模型确实让现代日常场景的可选对象变多，而不是只增加摆件、地毯或不可独立使用的组件；自测通过后才提交、合入、推送和清理工作树。

## 非目标

- 不重做模型库 UI，不新增层级分类、拖拽排序或数据库模型。
- 不修改 Cine57 Unreal 源工程、不把整个 466 条目清单无筛选导入应用。
- 不删除已有稳定模型，即使它们不是本轮新增重点；兼容性清理由独立策展任务处理。
- 不用外部图片或静态截图替代可加载的 GLB 前景模型。
