# 全站创作工作台视觉重设计

## Design Read

这是面向写作初学者的 AI 小说/漫剧创作工作台重设计，用户需要在长流程中持续完成任务；视觉语言参考 `D:\Github\mydrama` 的暗色创作工作台，采用当前项目已有的 React、Tailwind、语义 token 与 shadcn/ui 组件，不引入新的设计系统。

设计拨盘：`DESIGN_VARIANCE=5`、`MOTION_INTENSITY=3`、`VISUAL_DENSITY=6`。目标是稳定、清晰、紧凑且有创作工具感，而不是营销页式的强装饰。

## 背景与审计结论

旧项目的统一感来自四个稳定约束：

1. 暗色工作台基底，面板使用低对比度的半透明层次，边界依靠细边框而不是厚重阴影。
2. 顶栏高度紧凑，项目导航和页面页签使用胶囊容器，活动状态通过填充和文字对比表达。
3. 交互控件采用统一的圆角、焦点环、悬停和按压反馈；输入、按钮、标签与弹层共享同一套材质语言。
4. 信息密度偏高但不拥挤，标题、说明、状态和主要操作有明确层级，长内容区域保持独立滚动。

当前项目已经具备主题 token、移动端壳层、通用 Card/Button/Input/Badge/Dialog/Select/Tabs 组件，但视觉规则仍被大量页面级 Tailwind 类分散表达：默认卡片偏厚、标题尺寸不一致、顶栏/侧栏材质不统一、颜色和透明度在页面中重复定义，导致不同工作区像多个产品拼在一起。

## 目标与非目标

### 目标

- 让首页、小说创作、漫剧工作台、模型/动画库、世界/资产页面和系统设置共享同一套视觉语法。
- 以暗色“工作台”作为主要体验，保留现有三套 palette、明暗模式和 compact density 的兼容能力。
- 统一页面外壳、导航、面板、卡片、表单控件、状态标签、弹窗和滚动条的层级与动效。
- 通过共享组件和语义 token 提高后续页面改造效率，减少页面直接写颜色和材质。
- 保留现有路由、字段、业务逻辑、导航文案、3D/视频渲染专用画布样式与可访问性行为。

### 非目标

- 不迁移旧项目的路由、状态管理、业务组件或 API。
- 不改变产品信息架构、URL、表单字段名和主要导航标签。
- 不把每个页面重写成同一张卡片，也不在 3D/视频画布上叠加全局装饰背景。
- 不引入新的组件库、图标库或字体下载依赖。

## 视觉系统

### 色彩和材质

扩展当前 `index.css` 的语义变量，使页面只通过 token 表达材质：

- `background`：页面基底；暗色使用接近黑色的冷墨色，避免纯黑大面积死黑。
- `card`：主要内容面板；与基底有轻微明度差。
- `muted`/`accent`：次级分组和悬停层；不再用每个页面自定义白色透明度。
- `sidebar`：导航专用表面，与内容面板保持相邻但可辨的明度关系。
- `border`/`input`/`ring`：边界、输入框和焦点状态统一从主题派生。
- 增加面板高亮、控件悬停、控件按压和阴影的语义 token，统一处理透明度与深浅模式。

青绿色作为唯一主强调色，成功/警告/失败保留语义色但只用于状态，不作为装饰色。所有新样式继续使用 `hsl(var(--token))` 或 Tailwind 语义类，不写页面级硬编码颜色。

### 形状、间距和动效

- 面板使用 `xl` 级圆角，控件使用 `lg` 级圆角，状态标签与分段导航使用全圆角；这套规则在共享组件中固定。
- 页面外边距和面板间距采用 8px 基线，桌面内容最大宽度保持可读，工作台页面允许满宽。
- 卡片标题默认降为工作台标题级别，避免每个 CardTitle 都抢占视觉焦点。
- 过渡使用现有的 `--duration-fast/base/slow` 与 `--ease-out-quint`，只用于 hover、focus、展开、切换和状态反馈；遵守 `prefers-reduced-motion`。
- 阴影只表达浮层和层级，不给每一行普通内容加阴影；3D/视频画布继续使用自己的渲染层。

## 组件和页面壳层改造

### 全局壳层

1. `AppLayout` 负责页面背景、内容滚动边界和壳层语义 class。
2. `TopNav` 采用旧项目式的低高度半透明顶栏，品牌、一级入口、页签和右侧实时执行入口各有稳定位置。
3. `Sidebar` 使用独立导航表面、分组标题和更明确的活动条，底部操作与导航滚动区分离。
4. `MobileSiteShell` 保留底部导航和更多入口，将顶栏、弹出面板、页面主区使用同一套 panel/control token。

### 基础组件

- `Card` 默认使用轻边界、工作台面板背景和克制阴影；Header/Content/Footer 的默认 padding 收敛。
- `Button` 统一圆角、按压反馈、焦点环、禁用态和各 variant 的对比度。
- `Input`、`SelectControl`、`Textarea` 统一字段高度、背景、placeholder、focus 和 disabled 状态。
- `Badge` 统一为紧凑状态标签；`Tabs` 的活动态使用面板内高亮而不是多种蓝色填充。
- `Dialog`、`Toast`、`Lightbox` 等浮层使用相同的 surface、border、backdrop 和阴影 token。

### 主要页面

第一轮覆盖共享壳层下最能代表全站的入口：

- 首页：恢复明确的“下一步”主任务层级，减少平铺卡片的视觉噪声。
- 漫剧入口和漫剧工作台：统一项目状态、阶段导航、分镜/资产面板的分组边界。
- 模型库和动画库：沿用刚完成的左侧分类、右侧搜索结构，统一筛选栏和资源卡片材质。
- 小说列表、小说创建和编辑：统一页面标题、操作区、步骤导航和长内容容器。
- 系统设置及其子页：统一设置分组、字段和保存状态，保持现有表单逻辑。

页面私有的 3D、视频、编辑器和数据可视化表面只接入 token，不用全局卡片规则强行覆盖。

## 实施顺序

1. 建立设计 token 与共享 utility，先保证六种主题/密度组合可用。
2. 改造 Card、Button、Input、Badge、Dialog、Tabs 等基础组件，并补充组件级契约测试。
3. 改造桌面 AppLayout、TopNav、Sidebar，再改造移动壳层。
4. 以首页、漫剧、模型/动画库、小说列表/创建、设置页为代表页面做定向去重和层级修正。
5. 使用内置浏览器验证桌面、平板和窄屏，覆盖导航、筛选、表单、弹窗、空/加载/错误状态。

## 验证标准

- 所有改动通过客户端 typecheck、生产 build 和受影响的测试。
- 浏览器冒烟覆盖 `/`、`/drama`、`/models`、`/animations`、`/novels`、`/settings` 及一个代表性编辑工作区。
- 每个目标页面在桌面和 390px 窄屏下无横向溢出，主操作可见，滚动边界正确。
- 浏览器控制台无新增 error；现有 3D 引擎 warning 单独记录，不把它们误报为本次样式问题。
- 键盘焦点、按钮/输入对比度、空状态、加载状态、错误提示和 reduced-motion 行为不回退。
- 视觉验收以“层级统一、间距有节奏、信息优先、装饰克制”为标准，不以复制旧项目的文件结构为标准。

## 维护边界

以后新增页面优先使用共享壳层和基础组件，不在页面内重新定义面板颜色、圆角、阴影和焦点样式。若一个业务区域需要特殊材质，应在其业务模块内定义有名字的 surface 变体，并说明它与普通工作台面板的层级关系。
