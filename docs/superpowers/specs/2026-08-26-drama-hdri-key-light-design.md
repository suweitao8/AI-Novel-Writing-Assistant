# 漫剧 3D HDRI 方向性环境光设计

## 背景

3D 场景编辑器目前把场景状态图交给 PlayCanvas 的 `EnvLighting` 生成
`envAtlas`。这条链路能提供环境反射和低频漫反射，但不会把 HDRI 中的窗户、太阳
或其他高亮区域变成方向性直射光。结果是背景能看到亮部，角色却缺少对应的受光面和
明暗方向，环境图与角色之间看起来像两套系统。

## 目标

- HDRI 的高亮区域能够驱动角色的基础方向光，亮部所在方向在角色身上产生可见的
  明暗关系。
- 保留现有 `envAtlas` 的环境反射与柔和环境光，不把方向光实现成另一套环境贴图。
- 更换、清除或加载失败时正确更新或释放运行时光源。
- 光源估算结果只存在于 viewer 生命周期，不写入 `layout3d`、场景参数或数据库。
- 不增加固定补光，避免所有场景被同一个人为光源污染。

## 方案

### 1. 两层照明

环境纹理加载成功后继续生成并绑定 `Scene.envAtlas`，作为基础环境照明和反射来源。
同时从等距柱状 HDRI 的缩略像素中提取上半部最有贡献的亮区：

- 用亮度阈值和平方权重突出窗户、太阳等高亮区域，降低普通天空/地面颜色对方向
  的稀释。
- 把像素坐标映射到等距柱状方向，按权重求和并归一化。
- 用同一组权重求出主光颜色，并限制到可用范围。
- 根据高亮区域的能量与集中度计算有上下限的方向光强度；无有效亮区时采用柔和的
  默认方向和低强度后备值。

估算出的方向光是 viewer 内部的 PlayCanvas `directional` light，只照亮标准材质
角色和场景物体，不参与 HDRI 半球的自发光显示。这样背景仍按投影材质显示，角色
则同时受到 EnvAtlas 和 HDRI 派生主光影响。

### 2. 生命周期

- 创建 viewer 时创建一个隐藏的方向光实体，避免每次切换环境累积实体。
- 设置环境时先清理旧 atlas/source 和旧主光，再加载新图；加载成功后更新主光的
  方向、颜色、强度并启用。
- 清除环境、请求过期、加载失败或 viewer 销毁时禁用主光，恢复中性环境光，并释放
  atlas/source。
- 像素读取受浏览器 canvas/CORS 限制时不阻断 HDRI 环境显示和 EnvAtlas 生成，直接
  使用默认后备估算；后备光只用于保持角色可读性。

### 3. 模块边界

`blocking3dEnvironmentLighting.ts` 只负责无 PlayCanvas 依赖的像素估算、默认值和
可测试的方向/颜色/强度计算，以及从纹理读取缩略像素的浏览器适配函数。viewer 文件
负责创建方向光、应用结果和生命周期清理，不把估算逻辑内联到页面流程中。

估算函数以 `Uint8ClampedArray`、宽度和高度为输入，输出方向、颜色、强度和是否使用
后备值；它不依赖 DOM，便于用合成 HDRI 像素测试“左侧亮区确实把方向推向左侧”和
“全暗图不会产生异常方向”。

## 验证

- 纯函数测试：高亮区域方向、颜色/强度边界、全暗或无效输入后备值。
- viewer 契约测试：保留 `EnvLighting.generateLightingSource`/`generateAtlas`，同时
  存在 HDRI 派生方向光；清理路径会禁用方向光且不写入布局环境字段。
- 客户端类型检查与现有 blocking 3D 聚焦测试。
- 固定端口页面检查：使用包含明显窗户亮部的场景状态图，确认角色受光方向与亮部
  一致，并确认切换状态图不会叠加旧光源。

## 不在本次范围

- 不修改场景参数 API、数据库结构或 `layout3d` schema。
- 不改变 HDRI 半球几何、投影中心、地面贴图和 UV 投影逻辑。
- 不实现完整离线光照烘焙、阴影贴图或最终影视渲染级全局光照。
