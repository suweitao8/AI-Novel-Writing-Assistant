# 角色状态作为外貌与音色唯一入口

## 背景

设定中心已经具备角色状态图片、状态音色和状态间参考能力，但角色仍把年龄段、外貌、面部提示词和基础音色提示词保存在角色表单外层。这样会产生两套事实来源：状态描述一套，角色基础字段一套；新状态也要求用户重复填写基础描述、图片提示词和音色提示词，操作成本高且容易互相覆盖。

本次需求确认：性别属于角色基础身份信息；年龄段、外貌和音色属于随剧情变化的状态资产。状态资产仍保存在现有 `Character.statesJson`，不新增 Drama 专用状态表。

## 目标

1. 角色基础表单只维护姓名、性别等身份信息，视觉和声音字段不再作为角色级编辑入口。
2. 每个角色始终有一个可识别的初始状态。新建角色时先创建初始状态；旧角色读取或保存时把旧字段无损归并到初始状态。
3. 新状态默认继承上一状态，只需填写状态名、年龄段和一句变化描述；图片/音色提示词由服务端从性别、继承状态和变化描述组装，原有高级提示词数据继续兼容。
4. 生成图片和音色时，当前状态携带自己的完整视觉/声音资产；未变化的内容复用上一状态，发生变化时只重新生成当前状态。
5. 漫剧分镜首帧、视频提示词、台词配音等下游优先读取小说角色状态；旧 Drama 角色字段仅作为没有状态数据时的兼容回退。

## 非目标

- 不删除 `Character` 上的旧字段，不执行数据库重置或破坏性迁移；这些字段作为历史数据回退保留。
- 不自动根据章节内容创建或改写状态；状态创建仍由用户手动确认。
- 不把图片与音频强行合并为一个不可拆分的任务；图片和音色仍可以分别生成、失败和重试。
- 不改变性别的语义；性别继续作为角色基础信息参与状态图片提示词组装。

## 数据契约与迁移规则

### 状态字段

继续使用 `StoryAssetState`。状态已有的 `image`、`voice`、`referenceStateId`、`voicePrompt` 字段保持兼容。新增的状态归一化层提供以下逻辑：

- `label` 是状态身份，首个状态是初始状态。
- `description` 是用户输入的变化说明，也是生成提示词的主要输入。
- `ageGroup` 需要进入状态契约，初始状态默认从旧角色 `ageGroup` 迁入，没有旧值时默认 `youth`；后续状态默认继承上一状态。
- 当前状态的图片提示词和音色提示词可以由 `description`、性别、年龄段和父状态描述自动组装。已有非空 `imagePrompt`/`voicePrompt` 优先保留，避免覆盖用户历史精修内容。
- 状态保留 `referenceStateId` 作为图片参考兼容字段；未提供时按上一状态推导，显式 `null` 表示用户主动不参考。

### 旧数据归并

读取角色设置时，如果 `statesJson` 为空或没有可用初始状态，服务端生成一个内存中的初始状态：

- `label`: `初始状态`
- `ageGroup`: 旧 `Character.ageGroup`，否则 `youth`
- `description`: 旧 `appearance`，再回退旧 `physique`/`attireStyle`
- `imagePrompt`: 旧 `facePrompt` 与外貌描述拼接
- `voicePrompt`: 旧 `voiceTexture`

保存角色时将归并后的状态写回 `statesJson`，但不清空旧列。已有状态列表不会被重建；只有缺少初始状态的旧记录才补齐初始状态，已有图片/音色结果原样保留。

## 交互设计

### 新建角色

新建弹窗显示姓名、性别和一个“初始状态”卡片。初始状态默认名称为“青年·初始状态”，年龄段默认“青年”。用户只需要填写一句“外貌与声音”描述；保存角色后即可生成初始状态图片和试听音色。AI 草稿仍可使用，但生成结果直接填入初始状态，不再填充角色级外貌/音色字段。

### 编辑角色

角色编辑弹窗分为两层：

- 基础信息：姓名、性别。
- 状态资产：状态列表与当前状态详情。

当前状态默认只展示：状态名、年龄段、变化描述、继承来源、图片状态、音色状态和生成按钮。图片提示词、音色提示词放入“高级提示词”折叠区域，已有精修数据可查看和修改，但新建状态不要求填写。

点击“添加状态”时自动继承列表中的上一状态，预填年龄段、外貌/声音基线和参考来源。用户只补充变化描述即可保存；保存后图片和音色按钮才可用，避免服务端按旧 `statesJson` 生成。

### 生成行为

- 图片：默认使用继承状态的已生成图片作为参考；当前状态没有有效父图时仍可生成，但提示词会带完整状态描述。
- 音色：默认沿用上一状态已生成试听；用户选择“生成新音色”时才调用模型。没有变化的状态不重复调用模型。
- 图片和音色按钮各自维护加载、成功、失败和重试状态；一个失败不影响另一个资产。

## 下游消费

`loadNovelCharacterStatesByName` 继续作为小说到漫剧的状态入口。首帧生成读取镜头标注的当前状态图；对白合成读取当前状态音色试听和提示词；状态资产存在时覆盖 Drama 角色基础字段，状态不存在时回退旧 Drama 字段。这样旧项目可以继续运行，新项目只维护状态即可。

## 测试与验收

- 服务端：旧角色字段归并为初始状态；已有状态不被覆盖；新状态继承年龄段、描述和参考来源；状态图片/音色仍只更新目标状态。
- 客户端：基础表单不再展示外貌/图片/音色字段；新建角色带初始状态；新增状态只要求简化字段；生成前阻止未保存状态；生成后保留图片、音色和选择状态。
- 漫剧：状态图优先作为首帧参考；状态音色优先用于配音；无状态数据时兼容旧字段。
- 回归：shared/server build、server focused tests、client typecheck/build、`git diff --check`，以及固定端口 API/浏览器流程。
