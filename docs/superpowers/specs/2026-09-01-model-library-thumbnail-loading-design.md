# 模型库缩略图视口加载设计

## 背景

模型库页面当前会把目录中的 208 张模型卡片一次性挂载。每张卡片挂载后都会立即调用 `ensureThumbnail`，让同一个离屏 PlayCanvas 工作室把模型、贴图、材质和 HDRI 逐张加入串行队列。卡片图片虽然声明了浏览器原生懒加载，但 3D 缩略图已经在图片元素出现前开始生成，因此不能阻止首屏启动全目录的模型解析。

主分支实测模型库首屏在约 1.5 秒仍有 114 个占位卡片，继续等待约 5 秒仍有 88 个；运行日志同时出现多次 PlayCanvas 纹理格式转换的昂贵警告。缩略图画布已经是 256×192，问题在生成调度范围而不在最终图片尺寸。

## 决策

1. **卡片列表继续完整渲染，缩略图生成按视口门控。**
   - `ModelCard` 给卡片根节点绑定 `IntersectionObserver`。
   - 当卡片进入视口或视口外 320px 的预加载范围时，才调用 `ensureThumbnail`。
   - 已存在缓存的卡片直接显示，不等待观察器；这样不会重复触发生成。
   - 不支持 `IntersectionObserver` 的运行环境使用一次性的立即请求作为兼容兜底，保证预览能力不因浏览器能力缺失而消失。

2. **观察器只负责启动请求，现有串行渲染器继续负责生成。**
   - 请求启动后立即解除该卡片的观察，避免重复入队。
   - 只有已请求的卡片才订阅缩略图完成广播；组件卸载时同时解除观察和订阅。
   - 保留现有 256×192 JPEG、HDRI、材质回填、阴影和 localStorage 缓存合同，不改变模型目录与模型详情页。

3. **首屏优化不通过删目录或分页隐藏卡片实现。**
   - 所有卡片仍保留在 DOM 中，搜索、分类筛选、键盘导航和详情链接不改变。
   - 远离视口的卡片显示现有加载占位，用户滚动到附近时自动加入队列。

## 不在本次范围

- 不修改动画库缩略图、模型详情页 3D 预览或漫剧 3D 场景。
- 不降低已经确定的 256px 输出尺寸，不修改 HDRI、材质、相机取景、阴影和缓存版本。
- 不删除已有模型文件、缓存数据或数据库内容。

## 验收标准

- 源码合同测试证明：卡片使用视口观察器和 320px 预加载边界，`ensureThumbnail` 不再在每张卡片挂载时无条件执行。
- 真实浏览器打开 `/models` 后，首屏仍显示完整卡片网格，但只有视口附近卡片开始出现缩略图生成；滚动后新的可见卡片能继续生成。
- 模型缩略图仍保持 256×192、4:3、异步解码和无编辑器网格画面。
- 客户端类型检查、聚焦测试和构建通过，浏览器无新增控制台错误。
