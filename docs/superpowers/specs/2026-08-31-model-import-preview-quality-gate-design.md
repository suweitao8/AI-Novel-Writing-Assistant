# Cine57 模型导入预览与贴图质量门禁设计

## Background

Cine57 的自然模型必须在进入模型库前通过实际三维预览。当前 `grass-01-1` 的详情页出现大面积三角形和拉伸贴图。排查结果显示：UE 导出的草叶 Base Color 是带 alpha 的 RGBA PNG，透明像素约占 37.6%；现有导入脚本的 `probeAlpha` 只匹配 `YMIN:`，而 FFmpeg 输出的是 `lavfi.signalstats.YMIN=...`，因此误判为无 alpha，转成了 JPG。模型目录随后没有 `opacity` 声明，透明区域以不透明颜色渲染。

这类问题不能由卡片占位图或人工挑一张缩略图掩盖，必须让导入链在生成目录前发现并拒绝它。

## Decision

### 1. 透明贴图必须保真

- 贴图转换统一从真实像素格式和 alpha 统计判断是否存在透明度。
- 识别 `YMIN=...`、`YMIN:...` 等 FFmpeg 输出形式；只要 alpha 通道包含非全不透明像素，Base Color 和独立 opacity 都保留为 PNG。
- 任何导入后的带 alpha Base Color 都必须在目录材质映射中同时声明 `baseColor` 和 `opacity`；法线/RMA 仍使用无 alpha 的 JPG。
- 导入前后都运行资源审计，禁止用“贴图文件存在”代替“贴图通道正确”。

### 2. 预览是入库前置步骤

每个新模型按以下顺序处理：

1. UE 导出 FBX 与材质清单。
2. 转换 GLB、清除碰撞壳和高阶 LOD、回填贴图。
3. 使用和产品模型卡片相同的标准视角生成方形预览图，并记录 GLB/贴图哈希。
4. 检查预览中的主体、透明边缘、材质完整性、朝向、落地和尺寸；不合理模型进入拒绝清单，不写入发布目录。
5. 只有预览证据、资源哈希和审查状态均有效时，才允许生成目录并进入 `check:model-library`。

预览证据落在版本库中，至少包含 `previewPath`、`assetSha256`、`renderer`、`renderedAt`、`textureStatus` 和 `reviewStatus`。重新生成 GLB 或引用贴图后哈希变化，旧的批准记录自动失效，不能复用旧截图。

### 3. 不合格模型采用隔离而非覆盖

- 被拒模型从发布目录和模型清单中移除或标记为 rejected，但原始 FBX、UE 资源和拒绝原因保留在外部资产盘/审计记录中。
- 同一模型 ID、文件名和贴图名不能被另一个资产静默复用，避免角色/道具或不同自然模型发生覆盖。
- 本次 `grass-01-1` 不再作为可发布草模型；优先从 `SM_grass_02_A_1`、`SM_grass_03_A_1` 等已导出的候选中重新生成预览，只有真正通过预览的候选才替换它。

## Verification

- 用一个带 RGBA 且 alpha 非全不透明的 fixture 复现旧逻辑，先验证旧逻辑会误判，再验证新逻辑保留 PNG。
- 对现有自然模型执行贴图通道审计；草模型必须包含可用 opacity，拒绝仍输出 opaque JPG 的结果。
- 对候选自然模型生成真实三维预览并进行视觉检查，至少包含草、灌木、花和树等带透明材质的代表资产。
- 运行模型库质量测试、目录检查、客户端类型检查和本地模型详情页浏览器冒烟测试；详情页不得再出现草模型的棕色/绿色大三角背景。

## Non-goals

- 不修改角色图片、场景方形预览或分镜比例逻辑。
- 不把所有 UE 资产一次性导入；模型数量充足时以质量门禁筛选代表资产。
- 不通过降低贴图质量、隐藏透明区域或改变模型比例来掩盖坏资产。
