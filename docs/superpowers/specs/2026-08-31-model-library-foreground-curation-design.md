# 模型库前景资产策展与 GLB 清洗设计

## 背景

当前 Cine57 模型库的 44 个条目中混入了不适合前景交互的场景级模型：纯色背景板会与 HDR 全景环境重复，巨石和扁石接近 10 米，砖炉导出结果是无法使用的建筑碎片，装饰构件则是墙体条带。模型库是静态目录，错误条目一旦进入清单就会一直出现在模型页和后续创作选择中。

审计还发现，现有构建脚本只按 `json.meshes[].name` 删除 `UCX` 与高阶 LOD；实际导出的碰撞体可能只有 `json.nodes[].name = UCX_*` 而没有绑定 mesh，因此会留下孤立节点。清洗规则需要覆盖 node 和 mesh 两层。

## 目标与范围

本次只整理应用当前的 Cine57 前景模型库，不改动 Unreal 工程、原始导出目录或用户数据库。

移出模型库的条目：

- `z-backdrop-01a`：纯色背景板，HDR 环境已经承担背景职责。
- `big-rock-01`、`flat-rock-01`：场景级巨石，最大尺寸约 9.4 米和 9.9 米，超出前景道具范围。
- `brick-stove-1`、`brick-stove-2`、`brick-stove-3`：导出后分别表现为高柱和零散板件，不构成可交互炉灶。
- `decorative-1`、`decorative-2`：约 2.9 米高、数厘米厚的建筑装饰条，不是可摆放前景道具。

保留其余 36 个条目，包括床、桌椅、茶几、书本、箱/食材组合、植物、灯具、地毯和小型碎石。地毯是地面道具，箱/食材组合满足箱子等前景物需求，小碎石仍在可控的前景尺寸内。

## 设计

### 1. 前景资产内容门禁

在仓库内增加模型库质量校验，读取静态目录和真实 GLB，而不是只检查目录文本。门禁固定以下规则：

- 目录只允许策展后的 36 个 Cine57 条目，明确移出的 8 个 ID 不得重新出现。
- 每个目录条目的 GLB 必须存在，且 URL 不得指向已移出文件。
- GLB 的 node 与 mesh 名称都不得包含 UE 碰撞体前缀（如 `UCX_`）或高阶 LOD（`LOD1+`）。
- 通过节点变换后的 POSITION 包围盒计算模型尺寸；前景库最大尺寸上限为 5 米。这样可以阻止新的场景级巨物进入目录，同时允许约 4.5 米的地毯等地面道具。
- 质量校验作为 client 测试的一部分运行，重新生成目录或加入新资源时会在提交前暴露违规内容。

### 2. GLB 清洗器

增加一个无外部运行时依赖的 GLB 清洗模块，供本次产物清理和后续模型导入检查复用：

- 按 node 名删除无 mesh 的 `UCX_*` 节点；按 mesh 名删除碰撞体和 `LOD1+` 网格。
- 重映射保留 mesh、node、children、scene 根节点以及静态 GLB 中可能存在的节点引用。
- 保留 BIN chunk 的原始顶点数据，不重新编码几何；重写 JSON chunk 时正确处理 4 字节 padding 和 BIN chunk 偏移。
- 清洗后重新读取 GLB 做结构门禁，确保没有悬空 mesh/node 引用。

### 3. 目录与产物再生

使用现有 Cine57 构建产物生成方式重建当前 worktree 的目录：先备份当前 `client/public/models/cine57`，再使用策展后的条目集和修正后的 GLB 清洗规则生成 `modelLibrary.ts`，最后清理不再被目录引用的 GLB 与贴图。备份只用于回滚本次资产操作，不进入 Git，也不触碰 Unreal 源目录。

## 数据流

```text
Cine57 manifest2（44 个精选源资产）
        │
        ├─ 策展规则排除 8 个场景级/无效条目
        │
        ├─ FBX2glTF 产物 → node/mesh 双层 GLB 清洗
        │
        ├─ 目录再生 → 36 个条目 + 真实材质映射
        │
        └─ 内容门禁 → 文件引用、碰撞/LOD、包围盒尺寸
```

## 错误处理与回滚

- 任何目录条目缺少 GLB、GLB 无法解析、出现碰撞/高阶 LOD 或超过尺寸上限时，质量门禁失败，不允许把该状态作为完成结果提交。
- 资产清理前验证备份目录存在且包含原始 GLB/贴图；若再生失败，保留 worktree 未提交状态并从备份恢复，不删除源导出文件。
- 这次不通过运行时隐藏或分类过滤来掩盖违规资源；违规资源必须在静态库层被移出。

## 验证

- 先运行内容门禁，确认旧的 44 条目状态按预期失败，证明测试覆盖了本次问题。
- 完成清洗与再生后运行内容门禁，确认 36 条目全部通过、8 个资源不再存在、GLB 无 `UCX`/高阶 LOD 节点且最大尺寸不超过 5 米。
- 运行客户端 typecheck/build 与相关测试。
- 使用内置浏览器检查模型库列表和至少一件床、桌、箱/食材组合、书本、植物、小碎石；确认背景板、巨石、扁石不再可访问，页面无新增 console error。
