# 场景空间标记定位与尺寸校准设计

## 背景

空间标记识别已经要求模型返回 `imageRegion`、`anchor`、米制 `size` 和世界坐标，但服务端仍把模型返回的 X/Z 径向距离当作墙面标记的主要深度依据。模型经常把窗、门或家具返回在投射中心附近；例如当前出租屋状态的窗户图片区域在全景图中上部，保存的水平半径却只有约 `0.5m`，而场景可用外圈约为 `3.6m`，所以 PlayCanvas 立方体会出现在场景中心，而不是窗所在的墙面。

尺寸也只是把模型的三个数值裁剪到通用范围，没有把图片框的可见宽高与床、桌子、椅子等固定物体的合理米制范围结合起来。模型估算偏差会直接变成过大或过小的立方体。

## 目标

- 让带 `imageRegion` 的 AI 标记在 X/Z 方向与全景图的水平经度一致，并把墙面/天花板物体稳定放到场景外侧壳体，而不是投射中心附近。
- 让地面物体继续遵守“中心高度为 `size.y / 2`、底面落地”的合同，并保留当前固定 `v=0.5` 全景的外圈兜底。
- 用图片框的角度跨度校准可见宽度和高度，再用结构化 `kind` 的米制范围限制极端值，使床、桌子、椅子等标记的大小更接近源图。
- 投影和尺寸归一化幂等；重复读取、保存或迁移不会让标记继续漂移或反复变大。
- 保持手工标记和没有图像证据的历史 AI 标记兼容，不静默重排用户已经手工修正的坐标。

## 非目标

- 不把单张全景图伪装成可以测量真实深度的 BIM 或碰撞网格。
- 不根据中文标签、场景名称或固定房间模板做关键词分支；类别范围只使用已经通过结构化 schema 的 `kind` 枚举。
- 不修改源图片、场景环境参数或分镜 `layout3d` 数据结构。
- 不要求用户为已有场景手工重建所有标记；带有效 `imageRegion` 的旧 AI 标记在当前环境读取时可以按新规则重新归一化。

## 设计决策

### 1. 统一的投影入口

`shared/utils/scene3dProjection.ts` 作为纯数学投影入口，服务端归一化器只负责数据清理、状态元数据和调用它。删除服务端与 shared 各自维护一套投影公式的漂移风险。投影结果同时返回 `position`、`size` 和 `yawDeg`，因为尺寸参与地面落点，不能只重算位置。

`imageRegion` 仍是唯一的图片方向证据：

```text
centerU = x + width / 2
angle = (1 - centerU) * 2π - π/2 + panoramaYaw
horizontalDirection = [cos(angle), sin(angle)]  // world X/Z
```

### 2. 墙面和天花板位置

场景半球几何的实际外侧半径约为 `domeRadius / 2`，标记可用半径边界沿用 `maxRadius = domeRadius * 0.45`，确保立方体不会穿出壳体。对带图像区域的 `wall`/`ceiling` 标记：

- 水平半径直接取 `maxRadius`，不再使用模型的 `position.x/z` 径向提示；
- 垂直位置由区域中心的垂直射线与该墙面半径求得，再按 `size.y / 2` 和服务端最大高度裁剪；
- `yawDeg` 朝向图片区域对应的径向方向，使长方体的局部深度轴指向墙面。

这样模型即使返回 `[0, y, 0]` 或一个很小的径向坐标，窗、门、墙柜仍会落在图片对应的一侧和外侧墙体上。单张图不能确认墙体真实前后距离，因此外圈是稳定的摆位参照，而不是测量结果。

### 3. 地面位置

对 `floor` 标记：

- 使用图片框底部射线与 `y=0` 的交点；
- 如果框底位于固定全景合同的地平线 `v=0.5` 以上、射线无法向下落地，使用 `maxRadius` 地面外圈；
- 最终 `position.y` 始终设置为校准后 `size.y / 2`；
- floor 标记保留模型的自身 `yawDeg`，只纠正空间位置。

没有 `imageRegion` 的标记继续只做原有通用范围裁剪和落地，不使用新投影。

### 4. 图片区域驱动的尺寸校准

对带图像区域的 AI 标记，先以投影后的水平半径估算图片框在当前场景中的可见跨度：

```text
imageWidthMeters  = 2 * horizontalRadius * sin(π * region.width)
imageHeightMeters = 2 * rayDistance * sin(π * region.height / 2)
```

其中 `rayDistance` 是区域中心射线到当前墙面/地面参考半径的距离。为避免框边缘、全景拉伸和模型框选误差把物体放大，按 `kind` 使用明确的视觉占比系数和米制范围：

- wall/ceiling：宽度和高度由图片跨度乘占比后裁剪到该类别范围；厚度沿用模型估计，但裁剪到该类别的薄体范围；
- floor：图片跨度决定主要占地宽度，深度按该类别的合理比例和范围生成，高度按图片垂直跨度与类别范围生成；
- `other` 使用保守通用范围，仍不读取 label；
- 图片区域缺失或来源为 `manual` 时完全保留原尺寸。

类别范围是对结构化 AI 输出的确定性后处理，不是意图识别或文本关键词兜底。所有生成尺寸都在现有通用 `0.05–30m` 范围内。

尺寸公式只依赖归一化后的图片区域、环境和类别规则；写回后的结果再次归一化时得到同样的尺寸和位置，从根源上保证幂等。

### 5. Prompt 与数据兼容

空间标记 Prompt 升级版本，明确要求 `imageRegion` 紧贴可见物体主体，`position.x/z` 仅作为旧数据兼容字段，不应承担墙面深度。现有 schema 字段保留，避免数据库迁移；服务端输出的 marker set 仍使用现有 `schemaVersion: 1` 和 `sourceEnvironment` 快照。

手工标记的优先级保持最高。旧 AI 标记只要有完整图片区域，就能在当前环境中重新投影；只有坐标没有图片证据的旧标记仍保持过期/原坐标兼容策略。

## 数据流

```text
场景状态图片 + 环境参数
        │
        ├─ 多模态 Prompt：kind / anchor / imageRegion / 粗略 size
        │
        └─ shared projection：图片区域 → 射线 → 位置 + 尺寸 + yaw
                           │
             normalizeStoryScene3dMarkerSet
                           │
        ├─ 场景 3D 编辑器：PlayCanvas 标记长方体
        ├─ 分镜 3D 草图：相同 marker 几何
        └─ 自动构图上下文：相同归一化 marker 体积
```

## 验证标准

- 回归测试证明近中心的墙面窗/门会被放到 `maxRadius` 外圈，并保持图片区域给出的左右方向和墙面朝向。
- 回归测试证明床、桌、椅的图片框宽高会影响归一化尺寸，输出落在对应类别的合理范围，且不会把模型极端值原样传给 viewer。
- 回归测试证明 floor 标记在框底向下时按地面交点，在固定上半区时按外圈，且中心高度始终为 `size.y / 2`。
- 回归测试证明 manual、无 `imageRegion`、重复归一化和环境变化的兼容行为。
- 共享包构建、服务端定向测试、客户端类型检查/构建通过；浏览器刷新当前出租屋状态的场景 3D 编辑器，确认窗户立方体位于对应墙面方向而不是中心，控制台没有新增错误。

## 风险与取舍

如果模型本身返回的 `imageRegion` 框错了，确定性投影会忠实地放大该错误；因此不能用固定坐标替代视觉识别。使用外圈作为墙面和无法落地家具的参照会牺牲一部分真实深度，但它比把物体留在投射中心更符合当前 UE HDRIBackdrop 式“上半部环境物体、下半部地面”的全景合同，也能保证后续角色摆位的相对方向稳定。
