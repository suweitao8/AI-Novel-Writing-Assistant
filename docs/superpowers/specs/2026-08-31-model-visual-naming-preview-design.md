# 模型视觉命名与预览图规范设计

## 背景

当前 Cine57 模型目录的名称主要来自人工静态映射和英文 mesh 名称词库。这个策略会把 `SM_Desk_Set_01a` 译成“办公桌组”，但实际模型是一个带烟头的黑色烟灰缸。模型卡片缩略图由浏览器运行时离屏渲染，虽然已经按包围盒取景，但相机参数和距离没有形成可验证的视觉构图合同，导致不同尺寸、不同长宽比的模型在卡片中占比不一致。

## 目标

1. 现有 79 个模型全部经过统一缩略图视觉复核，用户看到的名称和分类以模型本身为准；`desk-set-01a` 的展示名称改为“烟灰缸”，分类改为“日用小物”。GLB 文件名和稳定 ID 不变，避免破坏已有引用。
2. 后续模型导入必须先生成标准化截图，再写入视觉复核记录；缺少已批准复核记录的模型不能通过模型库质量门禁。
3. 模型缩略图和模型详情页初始视角统一为透视三分之四视图：水平偏航角为 45°，向下俯视 25°，主体投影占画布约 80%，目标容差为 76%–84%。
4. 取景算法基于归一化模型 AABB 的 8 个角点进行透视投影计算，不用固定距离或 `meshInstance.aabb` 的未经验证结果。
5. 预览生成规则变化后，旧的浏览器缓存必须自动失效；模型卡片仍保留当前的 localStorage 缓存和离屏队列，不把大量二进制预览图强行写入仓库。

## 方案

### 1. 视觉复核清单是导入命名的唯一覆盖层

新增 `scripts/models/model-library-visual-review.json` 作为模型展示语义的来源，按稳定 `id` 记录：

- `meshName` / `fileName`：与真实产物绑定；
- `name` / `category`：用户可见语义名称和分类；
- `visualDescription`：截图中可观察到的主体类型，用于复核和后续维护；
- `reviewStatus`：只能是 `approved`；
- `reviewEvidence`：说明该条目由标准缩略图截图复核。

新增 `scripts/models/modelLibraryVisualReview.mjs` 提供纯数据校验和按 ID 查询。质量门禁同时检查目录中的每个条目都有唯一、已批准的视觉复核记录，且名称、分类、文件绑定完全一致。这样英文文件名仍可作为候选输入，但不能直接成为最终展示名称。

导入构建脚本继续负责 FBX→GLB、清洗、材质回填和目录再生；构建完成后必须运行视觉复核门禁。新资产如果没有截图复核记录会被拒绝，而不是自动生成一个看似合理的中文名后悄悄入库。

### 2. 共享预览取景合同

新增 `client/src/pages/models/modelLibrary3d/modelPreviewFraming.ts`，只放与渲染器无关的纯数学：

- 公开 45° 偏航、25° 俯视、50° FOV 和 0.80 目标占比；
- 根据归一化 AABB 角点和宽高比计算相机到焦点的安全距离；
- 提供投影覆盖率计算，测试可验证常见横向、纵向和扁平模型落在 76%–84% 区间；
- 当几何退化或数值异常时回退到有限安全距离，不允许 NaN/Infinity 进入 PlayCanvas。

`thumbnailStudio.ts` 和 `modelViewerApp.ts` 共用这套取景合同。缩略图缓存键从 `v19` 升级，确保旧的默认角度和旧占比截图不会继续显示。详情页的“聚焦/复位视角”保留用户交互，但首次打开和复位都使用同一套标准视角。

### 3. 视觉证据与失败处理

模型复核使用模型库页面生成的标准缩略图截图；批量审计时按全量目录生成复核图集，逐条确认“实际是什么物体”后更新清单。无法从当前截图可靠判断的模型不进入 `approved` 状态，也不通过质量门禁。渲染失败只允许保留在待复核队列，不能用占位图伪装成已审计模型。

## 测试与验收

- 先为视觉复核清单、`desk-set-01a` 语义覆盖、覆盖率计算和缓存版本写失败测试，再实现；
- `pnpm test:model-library` 覆盖目录、GLB、视觉复核和分类门禁；
- `pnpm check:model-library` 必须通过 79 条目录和全量视觉复核；
- `pnpm --filter @ai-novel/client typecheck` 与客户端构建必须通过；
- 内置浏览器访问 `/models`，检查 79 项、名称“烟灰缸”、标准分类和缩略图构图；打开代表性小模型、大模型、扁平模型详情页，确认 45° 视角、主体约 80% 和无控制台错误。

## 非目标

- 不更改 GLB 文件名、稳定 ID、模型几何和材质；
- 不接入外部视觉服务，不上传本地模型或截图；
- 不改变模型在漫剧场景中的运行时摆放和用户拖拽交互；
- 不把模型缩略图改造成数据库资产或服务端生成任务。
