# 模型使用说明设计

## 背景

模型库目前只记录文件、分类、单位和材质。模型进入后续分镜摆放时，系统只能把所有模型当作同一种“落地道具”处理，无法区分需要贴墙的时钟、需要吊顶的灯具，也无法知道一个模型的朝向是否有意义。仅把说明写成一段 UI 文案会让后续运行时继续依赖猜测，不能解决摆放一致性问题。

当前模型库是客户端静态目录，包含 79 个经过策展的 Cine57 GLB 条目。因此使用说明应和目录条目一起发布，并且在目录质量门禁中保证每个条目都有完整且合法的结构化说明。

## 目标

1. 为模型库中的每一个模型补充一份结构化使用说明。
2. 让地面落地、水平支撑面摆放、墙面挂装和天花板悬挂成为可区分的机器语义。
3. 记录定位基准和朝向要求，使后续分镜/摆放逻辑可以直接读取，而不是解析中文文案或根据模型名称猜测。
4. 在模型卡片和模型详情页展示同一份说明，让用户在选择和检查模型时都能知道正确用法。
5. 对目录新增、删除或重新生成保持强门禁：缺少说明、枚举值非法或出现孤立说明时，测试和模型目录检查必须失败。

## 方案

### 1. 目录数据契约

在 `client/src/config/modelLibraryUsage.ts` 定义 `ModelUsageInstruction`：

- `supportSurface`：`ground`、`wall`、`ceiling`、`horizontal-surface`、`handheld` 或 `free`，表示模型应依附的支撑面或使用方式。
- `placementMode`：`grounded`、`wall-mounted`、`ceiling-hung`、`surface-placed`、`handheld` 或 `free`，表示摆放动作。
- `anchor`：`base`、`back`、`top`、`support-center` 或 `center`，表示对齐支撑面时使用模型的哪一侧/基准。
- `orientation`：`upright`、`horizontal`、`wall-facing`、`downward`、`directional` 或 `free`，表示模型的姿态语义。
- `requiresFacingDirection`：布置时是否必须提供朝向。
- `instruction`：面向用户的短说明，描述接触面、安装位置和朝向要求。

`MODEL_USAGE_INSTRUCTIONS` 以模型 ID 为键，使用说明在 `MODEL_LIBRARY` 装配后成为每个 `ModelLibraryEntry.usage` 的必填字段。目录入口同时提供 `getModelUsageInstruction(id)`，后续摆放运行时可以直接按 ID 读取同一份结构化数据。

### 2. 当前 79 个模型的归类

- 默认落地类：家具、容器、地面、植物、石头、树木、灌木、草、花，以及适合放在场景地面的卫浴/户外模型，使用 `grounded + base`。
- 水平支撑面类：书堆、餐食、咖啡机、杯具、办公用品、打印机、装饰摆件、奖杯和小型灯饰等使用 `surface-placed + support-center`；说明会明确放在桌面/台面等水平面，避免被误当成墙面或天花板资产。
- 方向性水平支撑类：双筒望远镜使用 `surface-placed + directional`，要求把观察方向指向目标。
- 墙面类：时钟使用 `wall-mounted + back + wall-facing`，背面贴墙、表面朝向房间，布置时必须提供墙面法线方向。
- 天花板类：宫灯使用 `ceiling-hung + top + downward`，顶部固定在天花板，灯体向下，布置时保留吊点和朝向。
- 平铺类：地毯和充气床垫使用 `grounded + horizontal`，接触面贴地并保持平整。

如果后续发现模型实际用途不同，应修改该模型的结构化 profile 和测试，而不是在摆放代码中增加按名称匹配的例外。

### 3. 页面呈现

- 模型库卡片显示一个紧凑的支撑面/摆放方式标签，用户不打开详情也能区分落地、墙挂和吊顶模型。
- 模型详情页新增“使用说明”区，展示支撑面、摆放方式、定位基准、朝向和完整短说明；这些字段直接来自 `entry.usage`。
- 只读展示，不在本次引入用户编辑入口；静态策展模型的说明由目录维护，避免用户局部修改后与 GLB 坐标约定不一致。
- 复用现有 `Badge`、`Card` 和 `InspectorComponentSection`，只使用语义化设计 token，不新增硬编码颜色或独立 UI 风格。

### 4. 质量门禁与未来消费

- `scripts/models/modelLibraryQuality.mjs` 校验每个目录条目的 `usage` 是否存在、枚举是否合法、方向标记是否与朝向语义一致，并继续校验 GLB、材质和文件完整性。
- 客户端契约测试覆盖全量 79 个条目、时钟/宫灯/垃圾篮等代表条目、说明读取 helper 和页面数据绑定。
- 摆放逻辑只消费 `supportSurface`、`placementMode`、`anchor`、`orientation` 与 `requiresFacingDirection`；`instruction` 只用于用户显示和 AI 上下文，不作为规则解析输入。
- 本次不改变数据库、不修改 GLB 几何、不自动重摆已有分镜实例；后续分镜接入时可按这份稳定契约增加 surface snap、墙面法线和吊点对齐。

## 非目标

- 不在本次为 79 个模型重新建模、旋转或重导出 GLB。
- 不依赖模型名称、分类名称或中文文案的关键词正则来决定摆放方式。
- 不把“使用说明”做成可自由编辑的数据库字段，也不新增服务端 CRUD。
- 不在模型详情页加入变换写入口；详情页仍然是只读模型检查器。

## 验证

1. 先新增全量目录契约测试，确认当前目录因缺少 `usage` 而失败。
2. 实现结构化说明、目录装配和质量门禁后，运行模型库测试、客户端契约测试、客户端类型检查和构建。
3. 运行目录质量检查，确认 79 个模型的 GLB/文件门禁与使用说明门禁同时通过。
4. 在固定的 `http://127.0.0.1:5174/models` 和代表性详情页检查卡片标签、完整说明、时钟方向字段与宫灯吊顶字段；捕获关键截图并确认浏览器控制台无新增错误。
5. 完成发布说明和模型库 wiki 的长期契约记录，再按仓库流程合并、推送并核对本地与 `origin/main` 的 SHA。
