# 角色资产身高档案自动补齐设计

## 背景

角色身高不是用户手工填写的硬事实，而是根据年龄段、体型、外貌和其他角色资料推断出的分镜比例基准。现有实现把身高档案放在角色行上，但只在角色第一次进入 3D blocking 时按需生成；设定中心的角色资产列表只读取档案，不负责补齐。

漫剧「提取」页还有一条隐蔽的数据边界：提取结果中的 `ageGroup`、`appearance` 和 `imagePrompt` 会被写进角色默认状态，应用接口只提交角色名、性别和状态列表。身高服务当前只读取角色级旧字段，没有读取默认状态，因此新提取角色的身高推断看不到最重要的资料。

## 目标

1. 角色资产列表、提取应用和 3D 分镜使用同一份角色级 `heightProfileJson`。
2. 身高推断读取角色当前默认状态中的年龄段、外观描述和图片提示词，同时兼容仍保存在角色级的旧字段。
3. 角色资产首次创建、更新或进入资产列表时自动补齐缺失/过期档案；有效档案按输入指纹复用，避免重复调用模型。
4. AI 失败时继续保存兼容基准，并在卡片上标记为兼容基准，不阻塞角色资产使用。
5. 提取结果不新增手工身高字段，也不把近似值伪装成用户确认的精确身高。

## 非目标

- 不增加角色表单的精确身高输入框。
- 不改变角色图片、四视图裁切、场景或道具预览逻辑。
- 不让章节提取模型直接输出固定身高数值；提取只负责提供可用于推断的结构化证据。
- 不覆盖已有图片、音色、状态或分镜布局。

## 方案

### 1. 统一身高推断输入

`CharacterHeightProfileService` 查询小说角色时同时读取 `statesJson`。以默认状态（首状态）作为状态资产的当前基准，并按以下优先级构造输入：

- 角色级字段优先：兼容历史角色的 `ageGroup`、`appearance`、`facePrompt` 等字段。
- 角色级字段为空时，回退到默认状态的 `ageGroup`、`description`、`imagePrompt`。
- 其他角色级资料继续保留：姓名、性别、剧情定位、性格、背景、体型、服装等。

这样既不破坏“年龄和外貌属于状态”的现有模型，也让提取应用后的默认状态真正进入身高推断。输入指纹必须覆盖合并后的值，状态被编辑后会重新估算。

### 2. 资产边界自动补齐

设定中心角色列表在投影前调用现有的 `ensureNovelCharacterHeightProfiles`，为缺失或输入指纹变化的角色补齐档案，再把生成结果投影到卡片和编辑数据中。创建与更新角色时也在返回前执行同一服务，保证提取“应用”或普通保存的响应立即带上身高。

身高服务已有进程内并发合并、条件更新和 fallback 机制，沿用这些保护；列表只会对没有有效缓存或输入已变化的角色调用 AI，稳定角色不重复生成。

### 3. 提取写入契约

提取模型继续输出 `gender`、`ageGroup`、`appearance`、`imagePrompt` 和 `voicePrompt`。应用弹窗把这些字段写入角色默认状态，服务端身高服务从默认状态读取它们。测试覆盖“提取结果 → 默认状态 → 身高推断输入 → `heightProfileJson`/卡片”的边界，防止以后只改前端表单字段又让身高输入断链。

## 错误与并发

- 结构化身高输出不合法或模型不可用时使用现有 1.8 米兼容基准，来源标记为 `fallback`。
- 角色资料在 AI 调用期间被编辑时，条件更新不得覆盖新资料；下一次列表或 blocking 请求按新指纹重新估算。
- 默认状态数据损坏时沿用现有状态解析与旧字段回退，不覆盖原始状态 JSON。
- 多个页面同时请求同一角色时复用进行中的任务，不重复发起身高推断。

## 验证标准

1. 失败测试先证明当前实现不会从提取写入的默认状态构造身高输入。
2. 通过测试证明默认状态资料进入输入指纹/Prompt，缺失档案会在角色资产列表和创建/更新响应前补齐。
3. 现有身高边界、fallback、blocking 比例和角色卡片测试继续通过。
4. 运行共享包构建、Prisma 生成、服务端构建、客户端类型检查和相关契约测试。
