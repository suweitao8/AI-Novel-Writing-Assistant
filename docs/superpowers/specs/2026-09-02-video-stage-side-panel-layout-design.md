# 视频阶段三栏预览布局设计

## Background

当前漫剧工作室的视频阶段把已生成的视频和成片信息放在同一行，合成设置、合成概览、进度和错误又继续占据整张卡片宽度。桌面端左右两侧存在可用空间，但主要内容没有形成清晰的视觉层级；播放器还受到固定的 `max-w-[124vh]` 宽度上限影响，纵向预览高度偏低。

## Goals

- 桌面端将视频阶段组织为“左信息栏—中央播放器—右信息栏”，让中央区域只承担视频预览。
- 提高中央播放器的可用高度，同时保持成片的横屏 16:9 比例和原生视频控件。
- 将现有合成设置、运行进度、错误状态和成片信息放到两侧信息栏，不改变它们的业务状态、接口或操作语义。
- 在窄屏自动回落为单列，视频保持优先显示，信息栏按逻辑顺序堆叠并可正常滚动。
- 继续使用现有 Card、Badge、Button 和语义 token，不引入新播放器或新的颜色体系。

## Design

### 1. Desktop composition

`DramaEpisodeAssemblyResultPanel` 的外层使用响应式网格：

- 左栏：合成设置、合成进度、失败信息和缺口提醒；合成按钮继续紧跟“合成设置”标题。
- 中栏：成片播放器；播放器容器占据中央主列，使用 `aspect-video`，去掉旧的 `max-w-[124vh]` 限制，并通过中央列的宽度和视口高度上限提供更高的预览区域。
- 右栏：成片信息、视频下载、SRT 下载和新窗口打开；信息栏保持内容高度，避免被中央视频拉伸出空白。

无成片时中央列保留视频合成标题和横屏规格，左右栏继续提供合成设置与概览；运行中或失败时不隐藏必要反馈。

### 2. Responsive behavior

- `xl` 及以上视口使用三栏网格；中央列使用 `minmax(0, 1fr)`，左右栏使用有边界的固定/弹性宽度，避免长文本撑破布局。
- `xl` 以下使用单列顺序：中央预览（或无结果提示）→ 合成设置/进度/错误 → 合成概览 → 成片信息与下载操作。
- 视频不使用固定像素高度；用比例和 `max-height` 约束确保在应用式固定视口内完整可见，并让小屏页面保留自然滚动。

### 3. Accessibility and state preservation

- 保留原生 `<video controls>`，不改变 `src`、预加载策略或下载链接。
- 复用原有合成按钮禁用、运行中、失败和空状态条件；所有信息栏使用语义 `section`/`aside`，标题可被辅助技术识别。
- 不新增冗余的状态说明文字；状态反馈只保留用户做决策所需的信息。

## Scope Boundary

本次只调整视频阶段的展示结构、响应式样式和信息分栏；不修改合成 API、轮询、视频渲染、音频、字幕、数据库字段、路由或其他阶段。

## Acceptance Criteria

1. 桌面端视频位于独立的中央区域，左右两栏分别承载合成/状态信息和成片信息/下载操作。
2. 中央播放器比当前布局提供更高的有效预览空间，仍保持 16:9、无横向溢出。
3. 无成片、合成中、合成失败和已完成四种状态仍可看到对应的操作与反馈。
4. 窄屏不出现三栏挤压或横向滚动，视频优先且信息仍可访问。
5. 现有组件契约测试、客户端类型检查和内置浏览器桌面/窄屏回归通过。
