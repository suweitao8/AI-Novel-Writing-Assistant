# 全景地面分界固定为 50%：设计文档

## 背景

场景状态图和场景资产图使用 2:1 等距柱状全景图，并在 3D 场景中把全景图投射到连续的上下半球环境。当前 `panoramaHorizonV` 同时存在于环境 JSON、API、前端编辑器、投射 shader、空间标记反算和图片生成提示词中，编辑器还允许把它调整到 40%–65%。这会产生两个问题：

1. 同一张全景图可以被不同的分界参数解释，家具、床、桌椅等物体的垂直投射结果会漂移。
2. 生图模型没有足够严格的中心安全带约束，家具主体或腿部可能跨过 50% 分界，进入下半球后被拉伸或切开。

## 设计决定

1. 全景地面分界是产品级固定合同，统一使用 `v = 0.5`，不再作为用户可编辑的环境参数。
2. 共享类型、服务端环境归一化、空间标记反算、客户端 CPU 投影和 GLSL 投影都使用同一个固定常量；投射中心高度和半球直径仍然可以调整。
3. 历史环境 JSON 和旧分镜布局中的 `panoramaHorizonV` 只做兼容读取，读取时忽略其值；新的环境 JSON、标记快照和分镜布局不再写出该字段。
4. 场景全景图和场景状态全景图的生成提示词必须明确：
   - 纹理坐标的精确中心线为 `v=0.5`，不得把它理解为可调参数，也不得绘制可见分割线；
   - `v=0.48–0.52` 是无家具、无物体碎片的中心安全带；
   - `v=0.0–0.48` 放置完整的墙面、天花、远景和主要环境物体；
   - `v=0.52–1.0` 只保留连续地面、地板或地形以及少量低矮细节；
   - 床、桌、椅、沙发、柜体、门窗、树木、建筑、岩石等物体主体不能跨越中心安全带。
5. 空间标记 Prompt 同步使用固定 50% 的图像证据合同：识别时拒绝中心安全带内被切开的物体，不再向模型传达可调地面分界。

## 兼容性与数据规则

- 不新增数据库迁移；环境参数保存在已有 JSON 字段中。
- 旧 JSON 中的未知 `panoramaHorizonV` 不导致读取失败，但归一化结果固定为 50%。
- 重新保存场景环境时丢弃旧字段，阻止旧可调参数继续传播。
- 旧空间标记如果只有包含 `panoramaHorizonV` 的快照，仍可读取；快照归一化后只保留投射中心高度和半球直径。由于地面分界不再可变，不因旧 horizon 值单独使标记失效。
- API 新写入合同不接受该字段；旧分镜布局读取时忽略它，导出时不再写入。

## 非目标

- 不改变投射中心高度、半球直径、水平旋转和环境亮度的现有语义。
- 不修改场景全景图的 2:1 尺寸、水平无缝环绕或 WebGL 立方体重投影链路。
- 不用后处理裁切或固定关键词补救已经生成的坏图；质量约束放在生成 Prompt 和统一投射合同中。

## 验收标准

- 场景 3D 编辑器不再显示“全景地面分界”控件。
- 任意旧值（例如 `0.4`、`0.58`、`0.65`）读取后都按 `0.5` 投射，且保存结果不包含 `panoramaHorizonV`。
- CPU 投影和 GLSL 不再接受或绑定可调 horizon uniform，水平中心方向仍得到 `v=0.5`。
- 空间标记快照只比较投射中心高度和半球直径。
- 场景生图和空间标记 Prompt 都包含精确 50% 分界、中心安全带和家具不得跨线的约束。
- 相关单元/契约测试、客户端类型检查和服务端类型检查通过。
