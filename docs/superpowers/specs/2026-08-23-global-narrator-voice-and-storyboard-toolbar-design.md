# 系统级旁白音色与分镜工具栏简化设计

## 背景

当前漫剧旁白音色保存在 `DramaProject.narratorVoiceData`，因此每个漫剧项目各自维护一份描述和试听音频。分镜配音服务只读取旁白描述作为情绪提示，没有把试听音频作为参考音频传给 VoxCPM2，试听结果与正式旁白可能不是同一音色。分镜列表还重复提供章节选择、缺失画面、缺失配音、全部重配、音色设置等入口，与工作室右上角的章节选择和角色状态音色入口重叠。

旧项目已经有一份可复用的旁白参考音频：

`D:\Github\storybook\.working_dir\projects\黑暗文明\assets\voices\narration\voice_sample.mp3`

其元数据描述为成年男性、普通话自然清楚、平直直接叙述，不使用播音员或主持人的腔调。当前项目开发数据库没有已保存的漫剧旁白数据，可以作为一次性初始化来源。

## 目标

1. 整个网站只使用一份系统级旁白音色；所有漫剧项目的旁白合成和状态判断都读取它。
2. 系统设置提供独立的旁白音色页面，可试听当前音色、保存描述、生成或重新生成参考音频。
3. 初始化时优先复用旧项目已生成的参考音频；不覆盖任何现有项目数据。
4. 正式旁白合成使用与试听相同的参考音频，并在音色变化后让旧旁白进入需重配状态。
5. 分镜列表工具栏只保留「生成分镜」「生成配音」「合成」三个批量动作，章节选择只由工作室右上角负责。

## 非目标

- 不删除 `DramaProject.narratorVoiceData` 数据列；它只作为旧项目兼容迁移来源，不再作为新配置的权威来源。
- 不把角色状态音色改成系统级音色。角色的图片、音色和状态继承继续由角色资产状态维护。
- 不在本次工作中重做角色音色编辑器或视频合成流程。
- 不把旧项目整个仓库、运行环境或绝对路径写入产品运行时依赖。

## 方案选择

### 采用：`AppSetting` 中保存系统级旁白 JSON

继续复用当前系统设置使用的 `AppSetting` 键值存储，新增稳定键 `drama.globalNarratorVoice`。音频样本仍使用现有语音链路的 data URL，单个样本规模约几十 KB，与当前项目音色试听和逐行配音的存储方式一致。

这样不需要新增表或媒体鉴权接口，服务端只需在合成时读取一个全局配置；将来音频库规模增大时，可以在不改变 API 合同的情况下把 `sampleAudioUrl` 换成受保护的媒体 URL。

不采用“新增文件存储和媒体下载接口”作为本次实现方案：它对大规模音频更合适，但会引入新的文件生命周期、访问鉴权和迁移路径，无法改善当前单个旁白样本的核心问题。

## 数据合同

服务端设置值保存为 JSON，字段如下：

```ts
interface GlobalNarratorVoiceState {
  description: string;
  sampleAudioUrl?: string;
  sampleText?: string;
  source?: "legacy" | "generated" | "manual";
  sampleSha256?: string;
  updatedAt?: string;
}
```

对外 API 使用同一份状态：

- `GET /settings/narrator-voice`：读取当前系统旁白音色。
- `PATCH /settings/narrator-voice`：只保存描述，不生成音频。
- `POST /settings/narrator-voice/design`：按描述生成新的试听样本并立即设为系统当前音色。

服务端对旧 JSON 做容错解析；没有配置时返回空描述和无样本状态，不伪造已配置状态。

## 初始化与兼容迁移

读取系统级音色时按以下顺序解析：

1. `AppSetting` 中已有有效的 `drama.globalNarratorVoice`，直接使用。
2. 没有系统设置时，查找仍保留在 `DramaProject.narratorVoiceData` 中的第一个有效旧配置，将其转换为系统设置；迁移只写入新键，不清空原字段。
3. 开发环境的一次性导入使用旧项目的旁白样本路径和元数据，将音频转成 data URL，并写入 `source: "legacy"`、旧描述、旧试听文本和音频哈希。导入逻辑通过显式迁移入口/脚本接收路径，不把 `D:\Github\storybook` 硬编码到生产运行时。

以后新建或编辑项目都不再写入 `DramaProject.narratorVoiceData`。旧字段保留用于历史项目回退和数据安全；一旦系统设置存在，项目字段不再覆盖系统设置。

## 旁白合成与过期判断

`DramaDialogueAudioService` 和 `DramaAudioSegmentsService` 共用系统级旁白状态：

- 旁白行的 `emotion` 使用全局 `description`。
- 旁白行的 `referenceAudioUrl` 使用全局 `sampleAudioUrl`。
- 对白行继续使用角色基础音色和角色当前状态音色，不读取全局旁白样本。
- `buildDialogueVoiceKey` 将旁白描述与样本音频指纹纳入 key。描述或样本任一变化，已有旁白状态变为 `stale`。
- 没有系统样本时仍允许按描述生成，保持没有旧音频时的可用性；界面显示未配置状态而不是阻塞整个分镜流程。

## 分镜列表交互

`ShotVoiceListPanel` 接收父页面传入的 `chapterOrder`，来源是 `useNovelChapterWorkspace().currentChapter`。组件删除自己的章节选择状态和 `SelectControl`，不再从项目 episodes 自动选第一集。

在当前分镜列表的工具行中只保留：

- `生成分镜`：对当前章节中没有首帧且未在生成的镜头创建批量首帧任务；已有完整分镜时不重复生成结构。
- `生成配音`：生成当前章节缺失或已过期的旁白/对白；当当前章节所有配音都已就绪时，按钮改为 `重新配音` 并执行强制重配，避免并列放置两个重复按钮。
- `合成`：保持现有集成的合成控制器和结果面板。

每个镜头行已有的单镜「生成画面」和「生成配音/重新生成」保留，作为局部修复入口。右上角章节管理按钮继续是唯一的章节切换和新建入口。列表中删除「音色设置」折叠面板；旁白设置迁移到系统设置，角色音色继续在角色资产状态中维护。

## 系统设置页面

新增 `/settings/narrator-voice` 页面，并加入 `SettingsShell` 侧栏和系统设置总览卡片。页面以一张系统设置卡为主：

- 当前状态：已配置/未配置、来源和最近更新时间。
- 音色描述文本框。
- 当前样本原生 audio 播放器。
- 描述保存按钮。
- 根据是否已有样本显示「生成并试听」或「重新生成并试听」。

生成操作期间按钮禁用并显示加载状态，成功后自动刷新配置；错误显示服务端错误信息。页面不承担章节或项目选择。

## 测试与验收

服务端新增合同测试覆盖：

- 全局状态读写、旧项目字段迁移和无配置回退。
- 旁白合成请求传递全局参考音频；对白仍传递角色参考音频。
- 旁白 voice key 随描述或样本变化而变化，角色 voice key 不受全局旁白影响。
- 系统设置路由注册及描述保存/试听生成入口。

客户端新增/更新合同测试覆盖：

- 分镜列表不再包含章节选择和项目级音色设置。
- 工具栏只显示三个批量动作，章节顺序从父页面传入。
- 系统设置总览、侧栏和旁白音色页面的入口与按钮文案存在。
- 生成中、未配置、试听成功和重新生成状态有对应渲染逻辑。

验证顺序：针对性 Node 合同测试、服务端/客户端类型检查、客户端构建；UI 页面由当前浏览器会话做最终验收。数据库迁移只使用非破坏性的 AppSetting upsert，不执行 reset、truncate 或删除操作。
