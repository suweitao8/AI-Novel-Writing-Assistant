# 3D 场景圆半径与角色比例契约设计

## 背景

当前模型预览已经使用真实的 `radiusMeters` 表示“中心到圆形边界”的距离，但场景资产、空间标记和分镜 3D 草图仍把历史字段 `domeRadius` 当作半球直径使用。这样同一个“半径”在不同编辑器中有两套物理含义：场景编辑器显示的是直径，blocking 几何又要再除以二，AI 投影和边界环也各自重复换算，后续很容易把空间范围放大或缩小一倍。

同时，角色/怪物身高已经统一允许 0.50–10.00 米，能够表达儿童、普通角色和血角兽这类 5 米级怪物，但分镜保存接口的 HTTP schema 没有放行 `heightMeters`，请求经过 Zod 后会丢掉这个字段。视觉比例的源数据如果不能完整往返，下一次打开或保存分镜时仍可能退回默认身高。

## 决策

### 1. 场景环境统一使用真实圆半径

- `StoryScene3DEnvironment.radiusMeters` 是唯一产品字段，含义固定为投射中心到半球边界的真实水平半径，界面统一显示“圆半径”。
- 新场景、空间标记、分镜布局和视觉分析的新写入全部使用 `radiusMeters`；业务代码不再把 `domeRadius` 当作当前字段。
- blocking3d 的基础半球网格半径仍为 `0.5`，因此交给 PlayCanvas 实体时统一使用 `radiusMeters * 2` 的缩放值。几何模块的公共参数和环境运行时参数仍只接收真实半径，换算集中在几何/运行时边界。
- `resolveStoryScene3DWorldRadius` 直接返回 `radiusMeters`。旧名称只保留为标记清晰的兼容别名（如果仍有外部调用），不再新增旧命名调用点。

### 2. 保持旧场景的物理尺度

- 历史 `domeRadius` 是直径，旧范围 `5–30` 对应新 `radiusMeters` 范围 `2.5–15`；旧默认直径 `15` 迁移为半径 `7.5`。
- 历史投射中心高度保持不变。旧快照读取时先把 `domeRadius / 2` 转为半径，再用 `projectionCenterHeight / radiusMeters` 得到新比例；历史显式 `projectionCenterHeightRatio` 则按旧直径比例乘二转换。
- 新比例范围为 `10%–40%`，对应旧 `5%–20%` 的物理语义；投射中心高度仍限制在 `0.25–6` 米，并由 `radiusMeters × projectionCenterHeightRatio` 派生。
- 数据库不做迁移或重置。`scene3dEnvironmentJson` 继续作为 JSON 文本列，归一化器在读取时兼容旧字段，在下一次保存时惰性写成 `radiusMeters`。

### 3. 视觉分析和 API 兼容边界

- 视觉分析 Prompt 新输出 `radiusMeters`，明确要求“中心到边界的真实半径”；结构化 schema 使用新半径范围。
- 视觉分析输入仍接受历史 `domeDiameterMeters`，读取时除以二；旧高度按新半径重新计算比例，保持实际中心高度。
- 场景设置、空间标记和分镜保存接口放行新 `radiusMeters`，同时在兼容入口接受旧 `domeRadius`。新响应和新持久化结果不再输出旧字段。
- 分镜旧布局的 `layout3d.environment.domeRadius` 仍可读，旧值按直径转为半径；旧快照的物理范围可先接受到历史上限，再归一到当前 `2.5–15` 半径范围。
- `schemaVersion: 1` 保持不变，因为这是字段语义的兼容归一化，不是布局拓扑版本变化。

### 4. 角色身高必须完整往返

- `STORY_ASSET_CHARACTER_HEIGHT_MIN_METERS = 0.5`、`MAX = 10` 继续作为手动状态、AI 身高估算、角色档案和 3D blocking 的唯一边界。
- 分镜 HTTP schema 必须显式保留并校验 `heightMeters`；5 米输入保存后再次读取仍为 5 米。
- 身高为空时沿用角色级 AI 档案或 1.8 米兼容基准；这次只修复字段往返，不改变已经稳定的优先级。

## 影响范围

- 共享类型与归一化：场景环境、视觉估算、空间标记来源环境、舞台边界和 marker 投影。
- 客户端 3D 草图：环境控件、保存载荷、blocking 几何、HDRI 运行时、边界环和投射中心 gizmo。
- 服务端：场景设置/分镜 API schema、视觉环境 Prompt、分镜布局归一化和标记来源快照。
- 测试与文档：增加旧直径到新半径的物理等价测试、新字段写入测试、5 米怪物身高往返测试，并更新当前 Wiki、README 和 release notes。

## 验证标准

- 新旧环境归一化满足：旧直径 `15` → 新半径 `7.5`，投射中心高度仍为 `2`；新半径 `7.5` 写入后 JSON 只含 `radiusMeters`。
- 半径为 `2.5`、`7.5`、`15` 时，场景边界、marker 投影、几何 seam 和 HDRI 实体的真实世界半径一致，不出现一倍误差。
- 视觉分析能接受新 `radiusMeters`，旧 `domeDiameterMeters` 只在兼容入口转换；低置信度仍使用半径 `7.5`、高度 `2` 的默认值。
- 场景设置、空间标记和分镜保存的新请求均能往返 `radiusMeters`；旧请求仍可读取且不会把旧字段写回新响应。
- 5 米血角兽的 `heightMeters` 经过客户端保存接口、服务端归一化和再次读取后仍为 `5`；`0.49` 与 `10.01` 被拒绝。
- 定向共享/服务端/客户端测试、类型检查、客户端构建和可用条件下的固定端口浏览器 smoke 均通过；不得使用破坏性数据库操作。
