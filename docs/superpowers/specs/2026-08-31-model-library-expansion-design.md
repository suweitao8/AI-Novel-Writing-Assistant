# 模型库前景资产扩容与分类设计

## 背景

当前模型库只有一组精挑的室内前景模型。床、桌、椅等核心家具覆盖不足以支撑完整的小说场景；五个“食材组合”实际是同一纸箱资产族的近似变体，反而挤占目录和分类注意力。Cine57 已有一批尚未入库的静态网格，但其中混有建筑构件、碰撞体、LOD 变体和仅用于场景组装的碎片，不能直接全量发布。

## 目标

1. 保留床、桌、椅等基础家具，并扩充可直接摆放的室内、厨房、办公、装饰和户外道具。
2. 将食材/纸箱族收敛为最多两个外观明显不同的代表模型，不再发布五个近似变体。
3. 将自然资产按可查找的细分类别整理为“石头、灌木、树木、草、花、盆栽”；小摆件、雕像、奖杯等归入“玩具/装饰品”。如果某类源资产无法作为完整静态网格通过质量检查，则不发布空壳条目或场景碎片。
4. 用可追踪的精选清单替代“导出后全量进入目录”，让后续扩容仍然受控。

## 方案

- 目标规模从当前 36 个扩展到约 70–80 个已验证前景模型；本轮最终为 79 个。最终数量由通过几何、材质和浏览器预览的候选决定，不为凑数发布低质量模型。
- 新增候选优先覆盖：扶手椅/吧台凳/餐桌椅、柜体/书架/文件柜、箱子/木桶/篮筐、咖啡机/烹饪工具/餐具/微波炉、书籍/办公用品、摆件/花瓶/雕像/奖杯、露营用品、卫浴用品，以及独立的树木、灌木、草花和盆栽。
- 分类采用现有模型库的平面页签机制，不新增另一套 UI 筛选状态。分类顺序和计数由目录生成；预览页继续显示条目的实际分类。
- 源资产选择只接受完整的静态网格。场景建筑、墙体、地面大块、单独门板/灯泡/架板等组件不进入模型库。

## 数据与质量边界

- 资产白名单记录源网格名、展示名和分类，生成 `modelLibrary.ts` 时只读取白名单；生成文件不手工追加条目。
- 质量门禁不再把 36 作为永久业务规则，而是验证白名单覆盖、分类合法性、箱子族配额、ID/文件唯一性、材质引用、GLB 节点引用、碰撞体/高阶 LOD 清洗、最大尺寸不超过 5 米以及无孤儿 GLB。
- 源 FBX 超过 12 MB、转换后尺寸超过 5 米、无法保留有效材质或含有不可清洗的场景级结构时，候选直接淘汰。
- 纸箱配额按“食材/纸箱同族”限制为最多两个发布条目；已有五个食材组合中只保留一个代表，再保留一个构型不同的通用纸盒，木箱候选因与食材箱重复而不发布。
- 删除或替换现有 GLB 前，先将当前目录和目录文件复制到带时间戳的本地备份目录，并检查备份文件数和总大小。

## 验证

- 先用失败测试锁定新的分类、纸箱配额、白名单和质量门禁，再实现策略和目录生成。
- 批量转换后运行模型库单测、目录门禁、客户端 typecheck/build 和 GLB 独立检查。
- 在固定开发服务上用 Codex 内置浏览器检查全部分类页签、纸箱代表、家具、摆件和自然细分类别；确认缩略图/完整预览可加载且无 console error。
- 只有自测通过后才提交、合并到 `main`、显式推送并清理 worktree。

## 不做的事

- 不修改 Cine57 源工程，不把 HDRI/背景板混入前景模型库。
- 不为了填满类别而导入建筑碎片、碰撞壳、LOD1+ 或重复变体。
- 不新增复杂的层级分类 UI；当前 flat category tabs 已足以承载这批明确的细分类别。
