# 提取资产卡片预览统一设计

## Background

“当前 · 提取”页的角色、场景、道具卡片目前使用独立的 8×8 小缩略图：已有资产显示第一张完成状态图，没有图片时显示类型图标。脚本右侧和资产页已经使用统一的 `StoryAssetPreview`，能够按资产类型保持一致的方形容器、缺图占位、加载失败处理和角色四视图裁切。

提取页因此出现两个问题：同一个资产在不同入口的预览效果不一致；已有资产取第一张完成图，可能和资产卡默认状态图不是同一张。

## Decision

提取页的角色、场景、道具卡片统一使用资产页与脚本页的预览展示规则：

1. 卡片采用左图右信息结构，左侧固定保留方形预览位。
2. 已存在资产的预览源通过 `buildStoryAssetPresentation` 生成，遵循“默认状态优先、没有默认状态时取第一项”的既有规则，并保留 `generatedAt` 缓存破坏参数。
3. 预览图片通过 `StoryAssetPreview` 渲染：
   - 角色使用四视图板最左侧方形裁切；
   - 场景和道具使用居中方形裁切；
   - 没有可用图片或图片加载失败时显示统一的“暂无预览图”占位。
4. 尚未应用的新提取建议没有图片 URL，左侧同样保留方形占位，不再显示角色、场景、道具图标。
5. 右侧继续显示提取页已有的信息：名称、角色定位、已存在徽标和提取说明；点击整张卡片仍打开现有应用/编辑弹窗。
6. 世界观条目不是可生成图片的资产，不显示预览图、缺图占位或类型图标，内容从卡片左侧直接开始；不纳入本次预览统一。

## Approaches considered

### A. 直接复用完整 `StoryAssetCard`

不采用。完整资产卡片的摘要、状态数量和资产类型徽标与提取建议卡的“提取说明、已存在、应用/编辑语义”不同，强行复用会让提取页信息重复或丢失。

### B. 复用预览组件与资产展示规则（采用）

提取卡继续由 `ReferenceExtractTab` 控制内容和交互，只把左侧图片替换为 `StoryAssetPreview`，已有资产通过 `buildStoryAssetPresentation` 获取 `preview`。这样预览裁切、占位和默认状态选择只有一套来源，提取卡仍能保持自己的业务信息。

### C. 在提取页复制图片 URL 与裁切 CSS

不采用。复制逻辑会重新引入默认状态选择、缓存破坏和角色四视图裁切的分叉，后续资产页调整时容易再次产生视觉不一致。

## Component and data boundaries

- `ReferenceExtractTab` 负责把已有角色、场景、道具转换为展示数据，并组合提取卡的左图右信息布局。
- `buildStoryAssetPresentation` 继续作为资产默认预览源的唯一派生入口。
- `StoryAssetPreview` 继续负责方形容器、裁切、缺图占位和图片错误状态。
- 不新增数据库字段、接口、生成任务或图片文件；新建议没有已生成图片时只显示前端占位。
- 世界观条目保持纯文字卡片，不进入图片预览分支，也不渲染无意义的装饰图标。
- 不改变提取卡点击、应用、编辑、查重和“已存在”状态逻辑。

## Interaction and accessibility

- 卡片主体继续使用单个按钮语义，图片不是独立交互目标，键盘 Enter/Space 行为保持不变。
- 有图片时使用资产名称对应的默认状态预览替代空 `alt`；无图时由共享占位组件提供可读的无图标签。
- 预览区域保持 `shrink-0`，避免长名称或说明挤压成不可见的窄条。
- 使用现有设计 token、`cn()` 和共享组件，不新增硬编码颜色或新的 UI 依赖。

## Verification

- 增加或调整展示契约测试，覆盖：已存在资产默认状态图、无图占位、角色/场景/道具裁切模式，以及提取卡仍保留名称和说明。
- 运行相关客户端测试、客户端 typecheck 和 `git diff --check`。
- UI 视觉验收由浏览器检查“提取 / 脚本 / 资产”三处的左侧预览一致性；不改变后端数据。

## Non-goals

- 不改变资产生成图片的提示词、规格或状态数据。
- 不改变详情弹窗中完整原图的展示方式。
- 不为尚未应用的提取建议提前生成图片。
- 不把世界观条目改造成图片资产。
