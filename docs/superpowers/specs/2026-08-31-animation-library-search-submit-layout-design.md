# 动画库搜索提交与来源行布局设计

## Background

动画库入口当前把搜索框单独放在来源筛选上方，并在输入框右侧显示当前结果数量。搜索文字通过短暂延迟自动提交，用户无法明确区分“正在输入的内容”和“已经生效的搜索条件”。在桌面宽度下，搜索区域因此占用额外一行，也与来源筛选的视觉层级不一致。

## Decision

动画库采用提交式搜索，并把搜索表单放到“来源”筛选行的右侧：

- 输入框保留受控草稿，只有点击“搜索”或在输入框内按回车后，才把草稿提交为生效搜索条件。
- 提交时去除首尾空白并回到第 1 页；提交空内容会清除已生效的搜索条件。
- 搜索框旁不再显示 `当前结果 / 当前来源范围` 数量。来源标签上的分类数量和分页区域的结果总数继续保留，因为它们分别服务于筛选选择和翻页定位。
- 来源、分类、套装、动作、姿态和武器筛选继续即时生效，不改变现有交互。
- 现有“清除筛选”保留在搜索表单附近，并同时清除搜索草稿与已生效搜索条件。

## Layout

桌面端的来源行由三部分组成：左侧“来源”标签，中间可横向滚动的来源页签，右侧搜索表单。搜索表单使用现有 `Input` 与 `Button` 组件、语义颜色 token 和 `cn()` 规则；按钮显示搜索图标与“搜索”文字，保证可发现性与可访问性。小屏幕下来源页签保持可滚动，搜索表单换到下一行并占满可用宽度，输入框和按钮仍保持可操作尺寸。

顶部独立搜索分区及其数量文本移除，分类行和下方的套装/动作/姿态/武器筛选不变。

## State and interaction

`searchInput` 表示当前输入框草稿，`search` 表示已经提交并参与 `filterAnimationLibraryEntries` 的条件。删除输入防抖 effect，新增表单 `onSubmit`：阻止页面默认提交、同步 `search`、并把分页设为第 1 页。其他筛选变化继续使用现有状态和分页复位逻辑。

## Accessibility and states

- 搜索表单提供 `aria-label="搜索动画"`，输入框继续有可读的 `aria-label` 和 placeholder。
- 提交按钮使用原生 `type="submit"`，因此鼠标点击和键盘回车走同一条路径。
- 按钮沿用项目 `Button` 的 focus、hover、disabled 语义；搜索是同步本地过滤，不引入虚假的加载态。
- 没有结果时继续显示现有空状态；分页结果统计继续作为结果反馈。

## Verification

- 为页面源码契约补充提交式搜索、按钮、数量移除和来源行同排布局断言。
- 运行动画库页面测试与客户端类型检查。
- 在内置浏览器访问动画库，确认桌面端来源与搜索同排、数量文本不再出现，并分别用点击“搜索”和回车验证结果提交；再检查窄屏换行、空结果和清除筛选。
