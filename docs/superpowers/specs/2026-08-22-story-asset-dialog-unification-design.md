# 故事资产卡片与详情弹窗统一设计

## 背景

角色、场景、道具是同一套小说设定资产，在脚本右侧资产栏和设定中心都会出现。当前脚本侧已经有一个只读详情弹窗，设定中心的三个页签则各自维护卡片和编辑弹窗，导致卡片结构、点击方式、详情层级和操作入口不一致，后续字段变更也需要重复修改。

## 目标

- 脚本右侧和设定中心的角色、场景、道具卡片使用同一套卡片骨架和点击行为。
- 点击任意故事资产卡片后，打开同一套详情弹窗：标题、类型、基础信息、视觉提示、状态列表和底部操作区保持一致。
- 保留角色、场景、道具各自不同的编辑表单和生成/状态操作；详情弹窗负责查看与进入编辑，不把三类表单强行做成一个大表单。
- 删除操作仍由调用方提供，详情组件不直接绑定具体 API；这样脚本侧和设定中心可以复用展示组件，同时保持各自的缓存刷新策略。
- 统一弹窗具备受控开关、Esc/遮罩关闭、焦点回收和可键盘触达的卡片入口，遵循现有 `Dialog`/`AppDialogContent` 约定。

## 非目标

- 不把角色库中的纯图片预览、分镜首帧预览、图片生成确认弹窗合并进故事资产详情弹窗；它们分别属于媒体预览和生成流程。
- 不改故事资产 API、数据库字段、状态图片生成和音色生成流程。
- 不删除或重写三类资产的专属编辑表单。

## 设计

### 1. 领域模型与展示适配

新增 `client/src/components/storyAssets/storyAssetPresentation.ts`，集中定义 `StoryAssetKind`、角色/场景/道具联合源类型、卡片展示模型和详情字段模型。适配函数只负责把 API 数据转换成统一展示数据：

- 类型标签、类型图标、摘要和元信息徽标统一由适配层产生。
- 角色基础信息展示性别、初始状态年龄、性格、背景；外貌、音色和状态内容来自状态列表。
- 场景展示场景类型、时间、天气、环境提示词和状态列表。
- 道具展示参考图、视觉提示词和状态列表。
- 空字段不产生空白区块；状态图片、状态描述、画面提示词和音色提示词按可用字段显示。

### 2. 共用卡片

新增 `client/src/components/storyAssets/StoryAssetCard.tsx`，只负责卡片布局和点击入口。卡片提供紧凑的 `compact` 展示能力供脚本侧使用，设定中心使用默认网格卡片尺寸；两种尺寸只改变布局，不改变信息和行为。

卡片本体是可聚焦按钮区域，支持鼠标、Enter 和 Space 打开详情。编辑、删除等外部操作通过 `actions` 插槽放在卡片头部，并阻止事件冒泡，避免点击操作按钮同时打开详情。

### 3. 共用详情弹窗

新增 `client/src/components/storyAssets/StoryAssetDetailDialog.tsx`，使用 `Dialog + AppDialogContent`。弹窗结构固定为：

1. 头部：资产名称和角色/场景/道具类型。
2. 内容：统一的徽标行、字段行、视觉信息区、状态列表；不同资产只在字段内容上有差异。
3. 底部：调用方可选的编辑、删除操作，以及统一的关闭按钮。

详情组件只接收 `asset`、`open`、`onOpenChange` 和操作回调，不发起删除或编辑请求。删除确认和成功后的查询失效由父级负责，避免把脚本侧和设定中心的业务状态耦合进通用组件。

### 4. 接入范围

- `OutlineSettingsAside`：删除本地 `AssetCard`、`AssetDetailDialog`、详情字段和状态渲染，改用共用适配器、卡片和详情弹窗；保留本章使用过滤、搜索、新增和删除业务。
- `SettingsCharactersTab`、`SettingsScenesTab`、`SettingsPropsTab`：卡片改为共用卡片，卡片点击打开共用详情弹窗；现有编辑按钮仍打开类型专属编辑表单，删除逻辑继续由页签管理。
- 设定中心三类页签的详情弹窗均从同一组件渲染，保证脚本侧点击同一资产时看到相同的信息结构。

## 状态与错误处理

- 没有图片或状态时显示统一的空状态文案，不留空白区域。
- 删除进行中禁用删除操作；失败使用现有 `toast.error`，保留弹窗打开状态以便重试。
- 详情对象被父级刷新移除时，弹窗自动关闭，不访问已不存在的资产。
- 长内容使用 `AppDialogContent` 自带滚动区；移动端保持单列布局。

## 验证

- 先为展示适配函数和三个入口复用契约写失败测试，再实现共用模块。
- 运行新增 Node 契约测试，确认三类入口都导入共用卡片/详情组件，且旧的本地详情实现被移除。
- 运行 `pnpm --filter @ai-novel/client typecheck`。
- 运行客户端构建和 `git diff --check`；浏览器交互验收留给用户按项目规则执行。
