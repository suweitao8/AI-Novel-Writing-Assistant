# 角色四视图与统一状态资产设计

## Background

当前漫剧 Studio 的资产状态图入口把角色、场景、道具都交给同一条单图生成链路。实际审计发现：角色状态发送的提示词只有“全身像”，没有四视图版式，也没有任何可执行的整板契约；本机 Grok Build 图片桥只接受文字提示词并固定产出一张 16:9 图片，因此生成结果容易变成环境中的单人照片。场景提示词还允许“极小背景人物”，同时把血角兽叙事描述直接传给模型，导致场景图出现怪物。

状态编辑器虽然已经复用了左侧状态列表、右侧详情的结构，但右侧无图时使用大比例占位，CSS grid 默认拉伸左栏，角色、场景、道具的弹窗在不同内容高度下出现明显空白。

## Goals

1. 角色每个状态的最终图片都必须是同一张固定画布里的四个视图：正面头像、侧面头像、正面全身、背面全身。
2. 默认无参考图的角色视图仍使用本机 Grok Build；需要参考上游状态图时保留兼容参考图的 provider 路由，不静默丢失参考图。
3. 场景状态图只呈现空间、材质、光线和环境痕迹，不出现人物、动物、怪物、生物或背景人群。
4. 角色、场景、道具状态编辑统一为左侧可选择状态、右侧查看和编辑状态详情的紧凑布局，空状态不制造大块留白。
5. 现有 statesJson、图片 URL 和重试状态契约保持兼容，不做数据重置或破坏性迁移。

## Non-goals

- 不把 Grok Build 伪装成支持参考图编辑的 provider。当前桥接协议不接受模板图片或 reference image；需要真实参考图时继续使用兼容 provider。
- 不修改章节分镜首帧图的画幅或角色参考链路；本设计只覆盖小说设定中心的角色/场景/道具状态图片。
- 不把用户在场景描述里写下的叙事事实静默改写回数据库；只在生图提示词和负面约束中明确“只表现环境证据，不绘制生物”。

## Decision

### Character four-view pipeline

角色状态生图在服务端使用一个完整的 sheet prompt，一次请求生成整张四格板。四个面板的契约固定为：

1. 正面头像：头肩近景，脸部正面清晰。
2. 侧面头像：头肩近景，严格 90 度侧脸清晰。
3. 正面全身：正面站立，从头到脚完整可见。
4. 背面全身：背面站立，从头到脚完整可见。

完整 sheet prompt 共用角色名、性别、年龄段、外貌、服装、状态变化和画风，并强制要求四个等宽栏位、纯白/浅灰游戏资产展示板背景、单一主体、无文字水印。无参考图时整板请求走 Grok Build；有上游状态参考图时整板请求走能力路由选择的参考图 provider，并把同一参考图传给整张 sheet。

Grok Build 当前没有 PSD/PSB 或模板图片输入协议，因此项目不会把代码常量冒充成已上传的 Photoshop 文件。`CHARACTER_STATE_SHEET_TEMPLATE` 只描述原生 1280×720 产物的四个等宽槽位，并保留旧合成器的兼容定义；主链路不再对四张独立结果做裁切或拼接，避免宽幅头像、侧脸和全身图之间发生身份漂移、比例失真和错误裁切。状态 JSON 仍只保存一张最终 sheet。

### Scene and prop pipeline

场景保持单张 360° 横向环境参考图，但正向提示词和负面提示词都加入：纯空场景、无人、无动物、无怪物、无生物、无背景人群；叙事描述中出现的生物只可转译为血迹、足迹、破坏、阴影或环境痕迹。道具继续保持单件 45° 透视视图，并保留已有无手、无人、无文字约束。

### State editor layout

`AssetStatesEditor` 继续作为角色、场景、道具共用组件：

- 外层状态区使用 `items-start`，左栏只按自身内容高度展示，不被右栏拉伸。
- 左栏状态列表设置合理的最大高度并独立滚动，状态缩略图、名称、图/音状态和参考关系保持可见。
- 右栏详情改用紧凑的图片区与字段区布局；已有图片按 3:2 设计参考比例展示，无图时使用固定短占位，不用大块 `aspect-video` 空区域。
- 角色额外显示年龄段、音色状态；场景/道具复用同一图片区和字段排布但不渲染音色区。
- 生成中、错误、重试、未保存禁用和空列表状态沿用现有 `AiButton`、`toast` 和可访问按钮语义。

## Data flow and error handling

1. 服务端读取资产和目标状态，解析上游参考图与最终 provider。
2. 目标状态先写入 `generating`，用一个完整的四格 sheet prompt 发起一次图片请求。
3. provider 失败或生成结果为空时，目标状态写入 `error`，保留可重试入口，不写入不完整 sheet。
4. 请求成功后清理旧扩展名，写入 `done`、最终 URL、provider、完整提示词摘要和历史版本；不保存中间视图。
5. 场景生图失败或生成结果为空时沿用现有 runtime 错误状态；成功重试必须清除旧错误。

## Verification

- 纯函数测试验证四个 view 的顺序、固定版式尺寸、角色无环境约束和场景无生物约束。
- 提示词和模板测试验证四个面板顺序、原生 1280×720 四等分契约与无额外人物约束。
- 服务/客户端定向测试验证状态 API、状态 JSON 兼容、生成按钮 loading/错误/重试状态。
- 真实运行中重新生成叶晨角色初始状态、末世血角兽猎场场景和洁白银行卡道具，检查数据库 provider、最终尺寸、四个面板视觉顺序和图片内容。
- 浏览器验收检查三类编辑弹窗都呈现统一左右布局，左栏不被右栏拉高，场景图不出现人物或怪物。
