# 漫剧分镜卡片显示镜头设计

## Background

脚本阶段已经把每句台词对应到镜头，分镜生成阶段也已经把可拍摄的画面信息写入 `DramaShot`：动作与摆位、景别、机位、场景、出场角色、角色状态和画面提示词。当前工作室的「分镜」页由 `ShotVoiceListPanel` 按镜头聚合配音段；当某镜头存在配音段时，组件只渲染配音文本，因此用户看不到这句台词对应的画面设计，无法判断分镜是否有效。

这次工作只修复展示链路，不重新生成分镜、不修改数据库字段、不改变配音生成逻辑。

## Considered approaches

1. **最小补丁**：在现有配音文本上方直接补一个 `action` 文本。
   - 改动小，但景别、机位、场景和角色状态仍会散落或不可见，后续容易再次出现两个展示分支不一致。
2. **结构化分镜摘要（采用）**：在每镜的右侧内容区固定划分「分镜设计」和「台词/配音」两块。
   - 复用现有 `DramaShot` 字段；动作作为主描述，元信息和角色状态紧凑呈现，画面提示词按需展开；无论是否已有配音，分镜设计都保持可见。
3. **增加 AI 合理性检查**：在卡片上加入“评估分镜”操作，自动判断动作与台词是否匹配。
   - 需要新增 AI 调用、任务状态和结果持久化，超出当前“先能看清分镜设计”的需求，暂不纳入。

## Decision

采用结构化分镜摘要，放在当前工作室分镜列表 `ShotVoiceListPanel` 的每镜右侧信息区。

### Display order

每张镜头卡片右侧按以下顺序显示：

1. 镜头编号与已有景别元信息。
2. **分镜设计**：
   - `action` 作为主文本，完整保留角色位置、姿态、朝向和可见动作；
   - `cameraMove` 与 `location` 作为紧凑元信息，缺失字段不渲染空标签；
   - `characterRefs` 展示出场角色；若 `characterStates` 中有对应状态，在同一角色标签中补充状态，帮助用户确认画面使用的角色状态；
   - `visualPrompt` 使用原生可键盘操作的折叠区展示，避免长提示词撑高列表，但仍可检查生成依据。
3. **台词/旁白与配音**：
   - 有音频段时，显示音频段中的说话人和文本，并显示已有的试听进度条与生成/重新生成按钮；
   - 没有音频段时，显示 `shot.dialogue` 作为台词内容；不显示“未生成”等重复状态文案，也不把 `action` 当作台词兜底。

### Data and state rules

- 所有内容直接读取已返回的 `DramaShot` 字段，不添加 API 或数据库字段。
- `segments.length > 0` 只决定台词/配音区域的呈现，不再决定是否呈现分镜设计。
- 旧数据中的无效 JSON、空数组或缺失字段必须安全降级：隐藏对应标签，主动作缺失时显示简短空状态。
- 设计摘要不显示估算时长，也不复制音频进度条中的实际时长；本次只解决镜头设计可见性。

### Layout and interaction

- 保留现有左侧 16:9 预览与编辑/生图操作；右侧摘要使用紧凑间距，避免引入大块留白。
- 使用项目现有语义 token、`Badge` 和 `cn`，不新增硬编码颜色。
- 画面提示词折叠区使用原生 `details/summary`，具备键盘展开/收起能力；摘要和音频操作保留清晰的 `aria-label`。
- 不增加解释性长文案；只使用「分镜设计」「出场角色」「画面提示词」「台词/旁白」等直接任务标签。

## Verification

- 新增前端源代码契约测试，覆盖：
  - 有配音段的渲染分支之前仍然固定渲染 `action`；
  - 景别/机位/场景、角色状态和画面提示词都有展示入口；
  - 无配音时不以 `action` 替代台词，且设计摘要不依赖音频段存在。
- 运行该契约测试和客户端 TypeScript 检查。
- 复用当前运行中的本地服务做只读数据确认，UI 最终交互由用户在工作室页面验收。

## Out of scope

- 不修改分镜生成 Prompt、分镜数据库结构、脚本解析、配音生成或图像生成。
- 不在本次加入自动“合理/不合理”判定。
