# 动画库统一目录与 UAL2 重定向基准修复设计

## 背景

动画页当前只登记了 3 个 Cine57 片段，但它们所在的合并文件实际已经包含 UAL2 的 43 个内置片段，因此页面没有把网站已有动作统一展示出来。

导入片段的 GLB 结构、旋转 accessor 和 skin-joint 目标均有效，行走片段的双脚轨迹也存在。异常集中在骨骼姿势：UE 源动画的节点默认姿势与 UAL2 目标绑定姿势不同。现有重定向公式把目标绑定 T-Pose 直接作为输出基准，导致源动画本来应该下垂的手臂被重新放到接近水平的位置；脚部因为仍然沿用了源动画的相对运动，所以看起来相对正常。

## 目标

1. 动画页统一展示合并 GLB 中的全部 46 段动作：UAL2 内置 43 段和 Cine57 导入 3 段。
2. 3 段 Cine57 动画在同一个 UAL2 角色上具备正确的站立、行走和坐姿语义，尤其修正待机与行走的手臂姿势。
3. 分镜 3D 草图和动画页继续共用同一个 UAL2 角色、骨架和 GLB，不混用 UAL1 资产。
4. 46 段缩略图生成不会为每张卡片重复下载和解析同一个 GLB。
5. 将“格式合法但重定向基准错误”纳入发布前自动回归，避免只凭 GLB 能打开就发布。

## 决策

### 1. 统一资产范围

动画目录使用 `/anims/cine57/UAL2_UE_Anims.glb` 作为唯一文件，并为文件中的每个动画建立一个稳定目录条目。内置片段的来源标记为 `UAL2`，导入片段标记为 `Cine57`。现有“待机 / 移动 / 坐姿”页签保留，其余 UAL2 动作归入“其他动作”，避免为 46 段动作增加过多筛选页签。

UAL1 是另一套角色骨架，不把它的片段直接追加到 UAL2 角色上；如果未来要支持 UAL1，必须作为独立骨架族和独立资产链路处理。

### 2. 使用固定的 UAL2 站立基准重定向

重定向工具从目标 UAL2 文件的 `Idle_No_Loop` 动画中取固定的 40% 时间点，得到一个不随导入片段变化的目标站立基准姿势。对每个匹配关节，输出世界旋转定义为：

```text
W_target = W_source_animation · inverse(W_source_bind) · W_target_standing_base
```

然后按目标父节点反解局部旋转。目标站立基准的局部平移作为输出基线，根/骨盆仍叠加源动画相对于源绑定姿势的平移增量并按骨骼长度缩放。这样既保留 UE 动画的脚步、重心和手臂摆动，又不会把目标角色重置到 T-Pose。

这项修正放在离线导出层，不在 PlayCanvas 播放时对手臂做特殊补偿；运行时只负责加载、播放和取景。

### 3. 缩略图资源复用

缩略图工作室创建时加载一次合并 GLB，后续每个目录条目只实例化同一个 `ContainerResource`。每个实例仍然独立销毁，工作室闲置时释放 PlayCanvas 应用；缓存版本随资源/姿势基准变化递增，清除旧的绑定姿势截图。

## 验证策略

- 先增加失败测试：目录条目必须覆盖 GLB 中的 46 个动画；当前待机与行走手部高度指标必须达到自然站立基准；旧实现应在这些断言上失败。
- 离线重定向后验证目标世界姿态、四元数 `VEC4`/单位长度、通道只指向 skin joints，以及待机双手、行走脚步与手臂摆动、坐姿骨盆指标。
- 用客户端动画内容测试验证发布二进制，再运行类型检查和客户端测试。
- 在固定端口 `3100` / `5174` 上使用 Codex 内置浏览器冒烟：动画页显示 46 段、筛选计数正确、缩略图为蓝色 UAL2 角色、打开待机/行走/坐姿预览无资源错误。不得使用外部 Chrome。

## 边界

- 不修改 UAL2 网格、skin、权重、inverse bind matrices 或原有 43 段内置动画。
- 不在服务端数据库中写入静态动画目录，不把 UAL1 动画伪装成 UAL2 条目。
- 不把“GLB 文件能加载”当作动作正确的充分证据。
- 本设计只处理当前已导出的 3 个 Cine57 片段；新的 UE 片段仍必须先以绝对骨骼姿态导出，再经过同一离线重定向和内容门禁。
