# 漫剧专注模式下的系统设置可见性设计

## 背景

当前产品处于漫剧项目开发阶段。全局导航已经通过 `DRAMA_FOCUS_MODE` 收起多数小说生产入口，但系统设置总览仍然会展示面向小说创作的“创作可用性检查”，并为这张卡片请求知识库和写法引擎状态。它会让漫剧使用者看到当前阶段不需要处理的配置，也会产生不必要的后台检查。

本次目标是收敛“看得到的入口”和“只为隐藏入口服务的检查”，不删除已有路由、组件、接口或数据，保证未来恢复完整产品线时可以通过同一个专注模式开关恢复。

## 决策

### 1. 使用集中式可见性策略

继续使用 `client/src/config/dramaFocusNav.ts` 作为漫剧开发期可见性策略的唯一来源。除导航路由外，新增带类型约束的功能可见性判断，当前明确隐藏小说向 `novel-readiness` 功能。页面不得自行用另一套 `if` 判断专注模式。

当 `DRAMA_FOCUS_MODE` 为 `false` 时，功能判断全部返回可见；关闭专注模式可以恢复完整设置总览，不需要删除或恢复代码。

### 2. 系统设置总览只呈现漫剧当前需要的内容

专注模式开启时，系统设置总览保留：

- 模型设置：文本、图片、音频模型仍服务漫剧生成链路；
- 旁白音色：漫剧旁白需要的全局音色入口；
- 画风：角色、场景、道具和时代画风；
- 记录：错误日志和任务日志；
- 视频输出：漫剧成片输出规格。

“创作可用性检查”不渲染。它依赖的 RAG 与写法引擎状态查询在功能隐藏时也不启用；模型和旁白查询仍按保留卡片的需要运行。

### 3. 保留路由与恢复能力

隐藏只作用于导航、设置页签和总览卡片。`router/index.tsx` 中的小说、自动导演、知识库、外观等路由继续保留，旧书籍或深链接不会因本次整理失效。进入隐藏路由时不新增拦截页，也不删除数据；需要恢复完整产品线时只调整专注模式配置。

### 4. 桌面与移动端共用规则

桌面顶部导航、移动端“更多”菜单和系统设置页内页签都继续调用同一份路由可见性函数。功能卡片调用同一份功能可见性函数。这样不会出现桌面已隐藏、移动端又重新出现，或入口消失但页面仍持续请求无关状态的分叉。

## 交互与可访问性

- 隐藏内容直接不渲染，不留下空白卡片、不可用按钮或无名称的焦点目标。
- 保留入口继续使用现有 `Button`、`Card`、`NavLink` 和项目语义颜色，不新增 UI 依赖或硬编码颜色。
- 移动端横向设置页签继续可滚动；隐藏页签不参与焦点顺序。
- 直接访问仍保留的旧路由不显示新的警告或误导性提示，避免把开发期策略暴露成用户-facing 迁移文案。

## 数据流与错误处理

```
DRAMA_FOCUS_MODE
        ├── 路由可见性 ──> 桌面导航 / 移动端更多菜单 / 设置页签
        └── 功能可见性 ──> 系统总览 readiness 卡片与其专属查询 enabled
```

隐藏 readiness 后，不会因其专属查询失败而在系统设置总览产生错误状态。保留的模型、旁白和漫剧设置仍沿用各自页面已有 loading、error、retry 或 toast 行为，不改变服务端合同。

## 测试策略

1. 为功能可见性策略添加契约：专注模式隐藏 `novel-readiness`，漫剧设置入口保持可见，关闭模式时所有功能恢复可见。
2. 更新桌面/移动端导航契约，确认隐藏路由不会出现在可见集合，模型、旁白、记录、画风仍出现。
3. 更新系统总览契约，确认隐藏 readiness 卡片及其专属查询受同一策略控制，保留卡片入口不受影响。
4. 运行对应 Node 契约测试、client typecheck 和 production build；UI 改动再执行隔离浏览器 smoke，检查系统总览、移动端设置页签、模型和旁白入口以及控制台错误。

## 不在本次范围

- 删除小说、自动导演、知识库、外观等路由或后端能力；
- 修改模型、旁白、画风、视频输出的数据结构或保存逻辑；
- 改变漫剧工作室内部的阶段页签与 3D 编辑器布局；
- 修改用户已有数据或执行数据库迁移。
